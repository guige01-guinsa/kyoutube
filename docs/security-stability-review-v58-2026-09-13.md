## 먼저 보완할 운영·제품 항목

1. **수정본 운영 반영:** DB 0042·0043·0044, 함수 recipe_api·youtube_recipe_context·ai_recipe_assistant·ai_youtube_recipe_assistant·membership. 공유 파일도 포함해야 한다. 앱 변경은 다음 서명 빌드에 반영한다.
2. **기존 공개 28건:** 소유자의 공개 의도가 불분명하다. 현재 항목은 임의로 변경하지 않았다. 공개 유지가 필요한 항목을 확인하고 나머지를 비공개로 전환한다. DB 기본값 변경만으로 기존 행이 보호되지는 않는다.
3. **비공개 이미지:** private 버킷 + 만료형 서명 URL 또는 인증된 이미지 프록시로 전환한다. 기존 공개 URL을 저장한 앱과 자료의 호환 처리가 먼저 필요하다. 버킷만 즉시 닫으면 기존 이미지가 깨진다.
4. **원가·매출 유료 제한:** 현재는 소유권을 검사하지만 유료 회원 여부를 강제하지 않는다. 무료/만료 계정의 테이블 SELECT·UPDATE·DELETE와 save_chef_workspace·record_chef_sale·chef_sales_totals 우회 호출까지 서버에서 제한해야 한다. 무료 인분 환산/버전 기능과 유료 원가 데이터의 저장 구조도 분리해, 단순 UI 잠금이나 전체 작업실 잠금으로 대체하지 않는다.
5. **관리자와 비밀번호:** 관리자 MFA 및 민감 관리 RPC의 인증 수준 확인, 유출 비밀번호 차단 활성화, 계정 복구 절차 점검. 사용 중인 Supabase 플랜의 지원 범위 확인 후 적용한다.
6. **결제 자격 증명·갱신·환불:** 서버 검증 코드는 있으나 운영 GOOGLE_PLAY_SERVICE_ACCOUNT_JSON이 미등록되어 구매 검증을 정상 운영할 준비가 되지 않았다. 자격 증명과 Play Console 권한 설정 후 실제 테스트 구매를 검증하고, 정기 재검증/RTDN을 추가한다. 계정 바인딩 정보가 없는 구매 토큰의 최초 등록 처리, 구매 확정 실패 재처리와 갱신/환불/정지 시 권한 회수를 강화한다.
7. **푸시와 로그 보관:** 운영 FCM_SERVICE_ACCOUNT_JSON 미등록 및 마지막 발송 실패를 확인했다. 발송 자격 증명 설정·권한 확인 후 실제 관리자 기기 수신·읽음·로그아웃 차단 시험. 일일 관측 원시 로그 정리 예약을 추가하고 보관 기간을 운영 문서와 맞춘다.
8. **복구:** 실제 백업 가용성·PITR 보장 범위를 확인하고 격리 환경에 복원 시험. 복구시간/허용 데이터 손실 목표와 담당자를 정한다. 이번 점검에서는 복구 성공을 검증하지 않았다.

## 적용·복구 절차 및 증거

운영 반영 전에 현재 함수 패키지와 DB 스키마/대상 공개 상태를 보존한다. 마이그레이션을 순서대로 적용하고 공유 모듈을 포함한 함수 5개를 배포한 뒤 익명 요청 거절·로그인 저장 비공개·기존 초안/장보기/회원 검증을 확인한다. 신규 앱은 별도 서명 빌드/기기 테스트 후 배포한다. DB reset은 필요 없다.

비공개 저장과 축소한 익명 권한은 장애 복구를 위해 다시 공개로 되돌리지 않는다. 함수 복구 시에도 이 보호를 유지하는 수정된 패키지를 사용한다. 기존 공개 자료 전환과 이미지 버킷 변경은 이 배포 목록과 별도의 검토 대상이다.
