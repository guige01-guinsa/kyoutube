# 구매요청서 문서형 미리보기와 PDF 공유

2026-09-18 사용자 승인으로 운영 웹 배포와 v73(1.0.1+73) 서명 AAB 생성·검증을 완료했다. DB·서버 함수·요금제·권한 변경은 없다. [릴리스 기록](release-v73.md).

## 표시와 공유

- 기본 미리보기의 긴 텍스트 블록을 흰 문서로 변경했다. 요청번호·작성일(있는 경우), 받는 업체/보내는 업소, 사업자번호, 납품 요청, 품목, 소계, 요청사항으로 구분한다.
- 휴대폰은 읽을 수 있는 품목 행과 수량·단가·금액으로 표시한다. 넓은 화면과 PDF는 품목 표를 사용한다. 200% 글자 확대 때는 세로 배치로 전환한다.
- 모바일의 주 버튼은 **PDF 파일 공유**, 보조 버튼은 **텍스트 공유**다. PDF는 실제 `application/pdf` 파일로 기존 기기 공유창에 첨부한다. 받는 앱에서 파일을 여는 방식이나 썸네일은 그 앱의 동작을 따른다.
- 웹의 주 버튼은 PDF 다운로드다. 기존 **PDF 미리보기 · 인쇄**에서 실제 페이지를 확인하고, 선택한 사업자등록증 사본만 첨부하며, 같은 바이트로 저장/공유/인쇄한다.
- 실제 PDF도 거래 정보 패널·품목 표·숫자 쉼표·소계·요청사항·쪽 번호로 정리했다. 한국어와 영어를 지원하며 폰트와 레이아웃은 기기에서 생성한다.

## 금액과 기존 동작

`RequestDocumentAmounts`를 화면과 PDF에서 공통으로 사용한다. 수량 × 요청 단가로 품목 금액을 계산하며, 단가가 없는 품목은 견적 요청으로 표시하고 소계에서 제외한다. 모든 품목이 미확정이면 소계를 0으로 표시하지 않는다. 무료 제공 등 입력된 0 단가는 유효하다. 배송비·세금·미입력 품목은 별도 확인 안내를 표시한다.

예: 소면 2상자 × 50,000원 = 100,000원. 이 금액은 입력 단가 기준 소계이며 확정 견적·결제 금액으로 표시하지 않는다.

텍스트 공유는 기존 내용을 유지한다. PDF는 기존 플러스·비즈니스 권한과 서버 확인을 그대로 적용한다. 발송 확인·수락·입고 상태는 사용자가 따로 확인하며, 공유만으로 상태·구매 이력·재고를 바꾸지 않는다. 계정 변경 보호, 취소된 요청의 공유 차단, 등록증의 선택 첨부를 유지한다.

## 검증

- 금액 계산: 미입력 단가·수량·0 단가·소수 금액·천 단위 구분.
- 한영 320px·200% 글자 레이아웃, PDF 주 버튼 및 텍스트 공유 분리, 공유 후 상태 변경 없음.
- 실제 한영 PDF 각 1쪽, 100품목 PDF 9쪽, 등록증 첨부 한영 각 3쪽. 전체 17쪽 렌더링, 품목 누락·소계·등록증 내부 링크 확인.
- 최종 전체 분석/테스트 기록: `.artifacts/request-document-polish-verify-final.log`.
- 결과: `.artifacts/verify-request-document-polish.json`. 화면 및 렌더링: `.artifacts/request-document-polish/`.

실제 카카오톡 발송, 휴대폰 설치, 실물 프린터 출력은 수행하지 않았다.

최종 검증: 고정 Flutter 3.44.8/JDK17 기준 분석 0건, 전체 439개 통과·기존 조건부 4개 건너뜀. 새 문서 화면·공유·금액 검사 및 시각 검증을 완료했다.

운영 v73에서 한영 샘플 요청서를 실제 PDF로 내려받아 새 문서 소계와 모든 페이지의 연습 표시를 확인했다. 운영 회원의 요청서는 작성·발송하지 않았다.
