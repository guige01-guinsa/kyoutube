# 사용자 영역·업소 업무 흐름 개편 — 1차

> 2026-09-22: 이 문서의 기능은 v79 통합 운영 배포와 새 서명 AAB에 포함되었다. 아래 소스 단계의 미배포 설명은 당시 기록이다. [최종 배포·검증](release-v79.md) · [메뉴 기반 빠른 구매](business-menu-fast-purchase.md).

2026-09-21. v78 운영 배포 이후의 소스 변경이며 운영 배포·AAB 생성은 포함하지 않는다.

## 구현한 범위

- 일반사용자: 레시피 찾기 / 내 레시피 / 장보기 / 내 정보.
- 업소·전문가 첫 화면: 소속 업소를 먼저 표시하고, 별도의 개인 작업실 진입을 제공한다. 조회 실패를 소속 업소 없음으로 처리하지 않는다.
- 개인 작업실: 내 레시피·개인 구매·개인 연구와 기존 담당 업무별 안내를 유지한다. 담당 업무를 바꿔도 주요 메뉴 위치는 바뀌지 않는다.
- 업소 공동 업무: 업무홈 / 메뉴·레시피 / 구매·입고 / 경영관리 / 더보기. 실제 서버 권한으로 허용된 메뉴만 표시한다.
- 업소 화면 상단: 현재 업소명, 실제 권한에 따른 업무 표시, 공동 자료임을 표시한다. 업체/업소 선택은 데이터 소유권이나 권한을 변경하지 않는다.
- 개인 업무 화면: 해당 계정의 자료이며 업소에 자동 공유되지 않는다는 안내를 표시한다.
- 공급업체: 업체홈에서 업체 정보를 관리하고, 상품·가격과 거래조건을 별도 메뉴로 분리한다. 상품 목록에 가격·유효일을 표시하고, 거래조건에는 배송지역·최소주문·배송비·무료배송 기준을 표시한다.
- 내 정보/더보기: 해당 사용자 영역의 도구를 우선 제공한다. 다른 사용자 영역은 이용 목적 설정으로 진입한다.

## 업소의 기본 동선

1. 작업 공간에서 소속 업소 선택.
2. 업무홈에서 판매 메뉴판, 메뉴·레시피 기준 구매, 권한에 따른 구매 승인 대기 진입.
3. 메뉴·레시피에서 공동 레시피/식단 계획, 시험 조리, 버전별 출시 승인, 메뉴판 연결.
4. 구매·입고에서 구매요청 조회·작성. 새 요청은 기존 메뉴·레시피 기반 구매로 연결한다.
5. 판매 메뉴 준비 / 출시 준비 / 개발·시험 조리 목적을 구분한다. 비품·소모품 직접 작성도 구매 시작 화면에서 선택할 수 있다.
6. 승인·전달·입고는 기존 확인 절차와 변경 이력을 유지한다.
7. 경영관리에서는 공동 원가와 판매 자료만 다룬다. 개인 원가 계산과 자동으로 합치지 않는다.

## 경로와 호환성

- `/workspace`: 업소·전문가의 작업 공간 선택 화면. 일반사용자·공급업체는 해당 영역의 기존 시작 화면.
- `/workspace?area=personal`: 업소·전문가의 개인 작업실.
- `/business-workspaces/:workspace`: 업소 업무홈.
- 같은 경로의 `section=recipes|purchasing|management|settings`: 해당 업무 목록/설정. 구매 승인 대기는 `section=purchasing&status=review`.
- 기존 메뉴판·구매 작성·상세·편집 경로는 유지한다. 기존 편집 종료 확인을 거쳐 이동한다.
- `/supplier-business`: 기존 업체·상품 관리 경로를 보존한다. `section=products|terms`는 상품·가격 또는 거래조건을 표시한다.
- 업소 선택/사용자 목적은 접근 권한이 아니다. `business_context`와 기존 RLS/RPC 권한 검증을 유지한다.
- DB·Edge Function·구독 조건·AI 호출·계정 자료 이동 변경 없음. 기존 생산 DB 마이그레이션이나 스키마 변경이 필요하지 않다.

## 검증

- 검증은 고정 Flutter 3.44.8 및 JDK 17에서 `tools/dev/verify.ps1`로 수행한다.
- 관련 테스트: `workspace_reorganization_test.dart`, 기존 workspace/business 회귀 테스트.
- 새 회귀 범위: 실제 권한과 화면 선호 구분, 안정적인 메뉴 순서, 소속 업소/개인 작업실 구분, 한국어/영어 모바일·데스크톱, 320px 200% 글자 크기, 계정 전환, 작성 중 이동 보호, 권한 갱신과 철회, 공급업체 거래조건의 독립 표시.
- 테스트 화면은 가상 업소 데이터이며 실제 직원 계정이나 운영 자료를 사용하지 않는다.
- 최종 결과는 `.artifacts/workspace-reorg-final-verify.log`, 화면은 `.artifacts/workspace-reorg-previews/`에 기록한다.

## 최종 검증 결과

- 필수 검증 스크립트 종료 코드 0. Flutter 3.44.8 정적 분석 오류·경고 0개.
- 전체 Flutter 테스트 549개 통과, 기존 제외 4개, 실패 0개.
- 실제 앱 글꼴·아이콘을 사용한 한국어/영어 모바일·데스크톱 미리보기 4개 통과.
- 계정 전환, 권한별 메뉴, 작성 중 이동 차단, 권한 갱신 중 초안 유지 및 접근 철회를 검증했다.
- 환경 참고: doctor에는 Android SDK 라이선스 상태 확인과 Windows용 Visual Studio 구성 경고가 남아 있다. 이번 작업은 Android release/AAB 빌드나 Windows 빌드 검증을 수행하지 않았다. 로컬 Docker DB도 실행하지 않았으며 서버 변경은 없다.
- 운영에 로그인한 직원의 실사용 검증과 운영 배포는 이번 검증 범위에 포함하지 않는다.

## 후속 단계

이번 1차는 메뉴·자료 소속·진입 동선 정리이다. 다음은 별도의 데이터 모델과 권한·거래 검증이 필요한 후속 개발이다.

1. 업소 공동 공급업체·상품·규격 연결, 개인 원가 계산 결과를 검토 후 공동 자료로 반영.
2. 품목별 부분 입고·반품 및 재고 수불, 예약·중복 구매 확인.
3. 실제 공급업체 견적 회신·주문 수락·납품 정보 연결.
4. 업소 소유권 이전과 자료 보존 절차.

공급업체 수신함·실시간 재고·자동 발주·자동 결제는 구현된 기능으로 표시하지 않는다.

## 2차 진행 현황 (2026-09-21)

[업소 공동 거래처·상품 규격과 메뉴 구매 연결](business-shared-suppliers.md)을 소스에 구현했다. 선택한 개인 거래처 필드만 공유하고 구매 당시 사본을 보존한다. 이 후속 단계는 DB0068이 필요하며 아직 운영에 적용하지 않았다. 개인 원가 계산 결과의 검토 후 공동 반영, 부분 입고·반품·재고 수불, 견적 회신, 소유권 이전은 이후 단계로 남아 있다.


## 3차 진행 현황 (2026-09-21)

[품목별 입고·반품과 재고·조리 예약](business-inventory.md)을 소스에 구현했다. 구매담당자의 부분 입고·반품·마감, 조리담당자의 예약·실제 사용, 메뉴 구매 준비의 재고 및 진행 중 요청 확인을 제공한다. 기존 과거 입고를 재고로 환산하지 않는다. DB0069와 아직 미배포인 1·2차 소스를 함께 검증했으며 운영 반영은 별도다.

개인 원가의 공동 반영, 공급업체 견적·납품 회신, 로트/유통기한, 자동 발주, 소유권 이전은 후속 범위로 남아 있다. 1차 절의 “DB 변경 없음”은 1차에 한정되며, 2차는 DB0068, 3차는 DB0069가 필요하다.
