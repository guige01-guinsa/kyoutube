# 사장용 담당자 관리

## 적용 상태

2026-09-22: DB0064와 운영 웹 v79 반영, 1.0.1+79 서명 AAB 생성 완료. [통합 배포 기록](release-v79.md). 메뉴 선정 권한은 재무와 분리해 위임할 수 있다. 아래 이전 검증 기록의 미적용 상태는 v79에서 해소되었다.

## 사용 방법

업소 공동 업무 → 업소 선택 → 직원·권한 관리에서 사장이 담당자를 관리한다.

- 직원 초대: 로그인 이메일과 초기 권한을 정하고 초대 코드를 직원에게 직접 전달한다.
- 담당자 정보: 표시 이름(필수, 120자), 직책·담당 표기(선택, 80자), 업무 연락처(선택, 120자)를 수정한다. 전화번호 또는 이메일 등 업무용 정보를 입력할 수 있다.
- 담당 업무·권한: 레시피·식단, 구매·입고, 원가·매출의 조회/수정 및 구매 승인 권한을 보여 준다. 기본 역할을 선택한 뒤 개별 권한을 조합해 겸임 업무를 지정할 수 있다.
- 직원 찾기: 이름·직책·연락처 검색과 전체/이용 중/이용 중지 필터를 제공한다. 목록 인원수에는 사장을 포함한다.
- 이용 중지: 확인 후 해당 업소의 접근을 해제한다. 계정, 공동 자료, 기존 작업 이력은 보존한다.
- 업무·권한 수정: 중지된 직원의 권한을 수정해도 중지 상태를 유지한다.
- 이용 복구: 별도 버튼에서 권한을 확인한 후 저장해야 다시 접근할 수 있다.
- 변경 이력: 기존 직원·권한 변경 이력에 담당자 정보 변경을 추가한다.

직책·담당 표기는 표시 정보다. 직책을 '사장'으로 입력해도 실제 사장 권한이 부여되지 않는다. 본인의 업소 책임자 권한은 해제할 수 없다.

## 저장과 보안

- 새 마이그레이션: `supabase/migrations/0064_business_member_profiles.sql`.
- 기존 업소 구성원 테이블에 직책, 업무 연락처, 프로필 버전을 추가한다. 기존 마이그레이션은 수정하지 않는다.
- 프로필 수정 RPC는 서버에서 업소 책임자 여부를 확인한다. 다른 직원·다른 업소 사장·비로그인 사용자·종료된 연습 공간은 수정할 수 없다.
- 기존 RLS에 따라 연락처는 사장과 해당 활성 직원 본인만 조회할 수 있다. 전체 직원이나 공개 업체 목록에 연락처를 노출하지 않는다.
- 프로필 변경은 권한, 이용 중지 상태, 유료 이용권, 업소 소유자를 변경하지 않는다.
- 프로필 버전으로 오래된 화면의 덮어쓰기를 차단한다. 기존 초대 수락에서 표시 이름이 변경되어도 버전이 갱신된다.
- 같은 내용을 다시 저장하면 버전과 이력을 중복 생성하지 않는다.
- 계정 전환 시 편집창을 닫고 이전 계정의 저장 결과로 목록을 갱신하지 않는다.
- 변경 이력에는 연락처 원문을 저장하지 않는다.

## 검증

- PGlite와 로컬 Docker PostgreSQL에서 각각 업소·샘플·담당자 관리 검사 146개 통과.
- 위젯 검증: 프로필 저장/유효성 검사/동시 수정, 중지 상태 유지, 명시적 복구, 중지 확인, 직원 검색, 비책임자 접근 차단, 계정 전환, 한국어·영어 320px 및 글자 200% 확대.
- 전체 Flutter 분석·테스트 결과는 `.artifacts/business-staff-verify.log` 및 `.artifacts/business-staff-validation.json`에 기록한다.

검증에 실제 직원 계정이나 운영 자료를 사용하지 않는다. 실제 업무 담당자에게 초대나 메시지를 발송하지 않았다.
## 최종 검증 결과

- Flutter 정적 분석: 문제 없음. 전체 테스트 487개 통과, 기존 건너뜀 4개.
- DB 검증: PGlite와 Docker PostgreSQL 각각 146개 통과.
- 고정 Flutter 3.44.8·JDK 17 사용. SDK 경로 인식, Android 라이선스 상태, Windows용 Visual Studio 설치에 관한 기존 doctor 경고는 남아 있다.
- 이전 v76 검증 당시에는 운영 DB 0064를 적용하지 않았다. v79에서는 적용을 완료했다. v76 웹/AAB에는 기존 DB 호환 처리를 포함해 profile_revision이 없는 운영 DB에서는 담당자 프로필 편집 버튼을 숨긴다. 기존 권한 관리는 유지한다.
