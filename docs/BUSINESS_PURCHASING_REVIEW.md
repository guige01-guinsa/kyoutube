# 업소·전문가 구매 흐름 개선 (2026-09-29)

## 사용 흐름

- 업소의 **구매·입고**에서 메뉴 구매 목록, 레시피·시험 조리 구매, 직접 요청서 작성을 선택한다. 거래처·상품과 재고·조리 예약도 같은 화면에서 연다.
- 요청서는 업체·재료·규격·납품일·제목으로 검색한다. 검색과 상태별 건수는 현재 페이지의 최대 50개 기준이며 다음 페이지로 이동할 수 있다.
- 작성 중에는 이어서 작성, 승인 대기에는 승인권자의 검토, 승인 후에는 전달 준비, 전달 후에는 입고 확인으로 연결한다. 상태 변경·전달·입고는 각 기존 화면에서 확인한다.
- 메뉴 구매의 재료 검토는 일반 장보기와 같은 여섯 분류를 사용한다. 진간장·국간장은 양념·오일에 속하지만 서로 다른 재료로 유지한다. 분류, 검색, 확인 필요 필터는 수량이나 저장 대상을 바꾸지 않는다.
- 전문가의 개인 구매에서는 **장보기 목록 정리**로 개인 재료의 분류·합산·보유량 확인을 시작한다. 업소 공동 자료와 개인 자료는 별도로 유지한다.

## 단위와 환산

| 경우 | 처리 |
| --- | --- |
| g ↔ kg, ml ↔ L | 동일 차원에서 표준 환산 |
| ea / each / pcs / 개 | 개수 단위의 표기 정규화 |
| g ↔ ml, 개 ↔ g | 자동 환산 안 함. 밀도·개당 무게 확인 필요 |
| 봉·팩·박스·컵 등 | 동일한 단위의 수량만 유지. 포장 내용량이나 조리 계량 기준을 추정하지 않음 |

레시피 편집의 **표준 단위로 정리**는 변경 전·후를 보여주고 확인받아 g·ml·개로 정리한다. 규격·손질 상태는 유지한다. 기존 저장 자료를 자동 변경하지 않는다. 레시피 저장 후 기존 출시 메뉴에 새 버전을 반영하고, 단위가 바뀐 재료의 구매 기준과 재고 연결을 다시 확인해야 한다.

공동 구매의 서버 합산 기준은 여전히 **재료명·규격·단위 일치**다. 과거 레시피가 g/kg로 나뉘어 있으면 위 기능으로 원본 단위를 정리하기 전까지 별도 행으로 유지된다. 화면에서만 임의 합산하면 재고 예약·상품 연결의 키와 어긋나므로 이를 하지 않는다.

수동 메뉴 구매에서 재고·입고 예정·포장 내용량은 호환 단위로 입력할 수 있고, 서버에 보낼 때 원래 레시피 단위로 환산한다. 빠른 구매의 상품 연결에서도 표준 환산계수를 제시한다. 서로 다른 차원이나 포장 환산은 확인한 상품별 계수를 입력한다.

예: 필요 2,300g − 재고 0.3kg − 입고 예정 0.5kg = 부족 1,500g. 1kg/봉 상품은 **2봉**, 여유량 **500g**이다. 부족량을 계산한 뒤 포장 수를 올림하며, 중간 과정에서 포장별로 중복 올림하지 않는다.

빠른 구매는 기존 서버 동작대로 연결 재고만 사용·예약하며 입고 예정량을 자동 차감하지 않는다. 수동 메뉴 구매는 사용자가 확인한 재고와 입고 예정량으로 초안을 계산하며 자동 재고 예약은 하지 않는다.

## 변경 범위

Flutter 공통 화면과 입력 보조 개선이며 서버 API·스키마·승인 권한·기존 주문 내역은 변경하지 않는다. 웹과 Android에 같은 소스가 적용되며 실제 운영 반영에는 별도 빌드·배포가 필요하다.

## 검증 결과

- 고정 Flutter 3.44.8 / JDK 17 환경에서 정적 분석 통과(문제 0건).
- 업소 전체 테스트, 번역 사전, 전문가 개인 구매, 작업 공간 탐색을 함께 재검증: **138건 통과**.
- 표준 단위·별칭, 무게/부피/포장 간 잘못된 환산 차단, 0·음수·과대 수량, 소수 포장 올림, g 입력을 kg 기준으로 저장하는 흐름, 원본 규격 보존, 필터로 숨겨진 미확인 재료의 저장 차단을 확인했다.
- 320px / 글자 200% 레이아웃과 한국어·영어 화면을 검사했다. 웹·휴대폰 요청서 목록 및 재료 검토 화면의 렌더링 이미지도 확인했다.
- 전체 `tools/dev/verify.ps1` 실행에서는 687건 통과, 4건 건너뜀, 13건 실패했다. 이 중 새 화면/번역에 관련된 7건은 수정하여 위 138건 재검증에 포함했다. 나머지 **기존 6건**은 `shopping_assistant_widget_test.dart`에서 이미 숨긴 일반 쿠팡 검색 버튼(`open-store-coupang`)을 찾는 검사다. 이번 변경에서는 해당 일반 검색 화면과 테스트를 수정하지 않았다.
- 환경 검사에는 기존 PATH의 전역 Flutter, Android 라이선스 확인 및 Windows Visual Studio 설치 경고가 남아 있다. 실제 검증에는 저장소의 고정 SDK를 사용했다. 서버 변경·운영 배포·Android 릴리스 빌드는 실행하지 않았다.
