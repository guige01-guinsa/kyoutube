# 구매요청서 AI 검토와 원본 비교

2026-09-20 사용자 승인 후 운영 DB·서버 함수·웹에 반영했습니다. Android 1.0.1+77 서명 AAB도 생성했습니다. 배포 증빙과 제한은 [v77 배포 기록](release-v77.md)을 참고하세요.

## 사용 흐름

1. 기존 방식으로 공급업체와 요청 품목을 작성합니다.
2. **AI 검토·대안 만들기**를 열어 전송 항목과 사용 제한을 확인합니다.
3. **AI 검토 시작**을 눌러야 AI를 호출합니다. 화면을 열기만 하면 호출하지 않습니다.
4. 입력 단가로 계산한 소계, 견적이 필요한 품목 수, AI 확인사항과 품목별 원본/제안을 비교합니다.
5. 원하는 품목의 제안만 선택하거나 전체 제안을 선택한 뒤 **선택한 수정 반영**을 누릅니다. **원본 유지**를 누르면 변경하지 않습니다.
6. 적용은 현재 편집 중인 품목에만 반영됩니다. 기존 **저장하고 미리보기**를 눌러야 저장되며, 발송은 기존 별도 공유 절차를 따릅니다.
7. 다른 품목 편집을 하기 전에는 **AI 반영 전 품목으로 되돌리기**로 직전 적용을 취소할 수 있습니다. 이후 수동 품목 변경을 덮어쓰지 않도록 원본 복원 버튼은 적용 직후 상태가 유지될 때만 표시합니다.

동일한 품목·통화·언어의 결과는 편집 화면이 열려 있는 동안 메모리에서 재사용합니다. 화면을 닫고 다시 열면 캐시는 유지되지 않습니다. 검토 창을 닫거나 계정을 바꾸면 늦게 도착한 결과를 적용하지 않습니다. 이미 시작한 서버 호출은 창을 닫아도 과금될 수 있습니다.

## 이번 단계의 범위

- 기존 입력을 바탕으로 품목명·규격의 문구 수정안과 확인사항을 만듭니다. 단위 모호성, 누락된 포장 규격, 중복 가능성, 미입력 단가 등을 검토하도록 지시합니다.
- AI는 수량, 구매 단위, 단가, 공급업체, 상품 링크, 장보기 원본 연결을 수정할 수 없습니다. 반환 스키마에 이 필드가 있으면 전체 응답을 거부합니다.
- 수량과 금액 계산은 기존 `RequestDocumentAmounts`에서 수행합니다. 일부 단가가 없으면 입력된 단가의 소계와 견적 필요 수를 함께 표시하며 배송비·추가 세금은 포함하지 않습니다.
- 수량 변경·단위 환산이 필요하다는 제안은 확인사항으로 표시되고 사용자가 기존 편집기에서 수정합니다. 실시간 가격 수집, 다른 공급업체 최저가 비교, 재고·납기 확정, 자동 주문은 포함하지 않습니다.
- 서버는 제안 전후의 숫자·계량 단위·포장 단위를 비교합니다. 망을 봉지로 바꾸거나 용량을 바꾸는 제안은 제외하고 확인사항으로 알립니다. 변경 없는 제안은 숨깁니다.
- 모델의 문구 제안도 사실 확인이 필요합니다. 구조 검증이 의미상의 정확성을 보장하지는 않으므로 기본 선택은 모두 해제되어 있고 적용 전에 비교하도록 했습니다.

## 비용과 사용 제한

- 별도 구독 상품이나 결제를 만들지 않고 서버가 선택한 기존 회원 모델(`gpt-4o-mini` 또는 `gpt-5.4-mini`)과 일·주·월 AI 한도를 공유합니다.
- 구매요청 검토에 추가로 **회원당 하루 5회, 월 30회**의 시도 제한을 적용합니다. 예약된 호출은 실패·만료를 포함해 시도 횟수에 들어갑니다. 회원 공통 한도가 더 작으면 해당 한도가 먼저 적용됩니다.
- 한 번에 최대 20품목, 요청 본문 32 KiB, 출력 최대 3,000토큰, 모델 응답 제한 60초입니다. 외부 검색 도구와 자동 재시도는 없습니다.
- 기존 사용자별 동시 요청 1건, 10분 내 시작 3건 제한을 유지합니다. 일·월 경계는 서울 시간입니다.
- 토큰 사용량은 성공 여부와 별도로 기존 예약 기록에 남깁니다. AI 응답이 불완전하거나 검증에 실패해도 응답에 포함된 사용량을 기록합니다. 네트워크가 끊겨 사용량을 받지 못한 호출의 정확한 과금은 제공사 대시보드 확인이 필요합니다.
- 실제 추가 비용은 활성 사용자 수와 입력·출력 토큰에 따라 달라집니다. 이 제한은 **서비스 전체의 달러 지출 상한은 아닙니다**. 기존 운영 예산 모니터링을 함께 사용해야 합니다.
- 서버 `PURCHASE_REVIEW_ENABLED=false`로 새 검토를 중지할 수 있습니다. `OPENAI_API_KEY`는 기존 서버 비밀값을 사용하며 클라이언트에 포함하지 않습니다.

## 보안 및 DB 변경

- `ai_purchase_request_review`는 JWT 게이트웨이와 서버 `auth.getUser()`를 거치며 익명 사용자를 거부합니다. 사용자 ID나 모델은 요청 본문으로 받지 않습니다.
- 전송하는 전용 필드는 언어·통화와 품목 ID/이름/규격/수량/단위/단가뿐입니다. 구매자명, 전화번호, 납품주소, 사업자등록증, 업체 연락처, 요청 메모, 상품 URL은 전용 필드에서 제외합니다. 사용자가 품목명·규격에 직접 넣은 내용은 전송될 수 있습니다.
- OpenAI Responses API의 strict JSON schema와 런타임 검증을 함께 사용합니다. 알 수 없는 품목 ID, 중복 ID, 초과 길이, 추가 필드, 거절·불완전 응답은 적용할 수 없습니다.
- 입력 문구는 명령이 아닌 검토 데이터로 취급하며 웹 조회·도구 호출 없이 `store:false`로 요청합니다. 오류 응답에는 공급자 원문이나 비밀값을 노출하지 않습니다.
- 새 마이그레이션 `0066_purchase_request_ai_review.sql`만 추가했습니다. 설치된 기존 예약 함수 정의를 좁게 확장하여 0055의 유효기간·시작일·활성 요금제 조건과 기존 권한을 보존합니다. 예상 정의와 다르면 마이그레이션을 중단합니다.
- 별도 검토 내용 저장 테이블은 만들지 않습니다. 사용자가 적용·저장한 요청서 내용만 기존 저장 구조에 들어갑니다.

## 검증과 운영 반영

- Deno 핸들러 테스트 12개: 명시적 호출, 인증/본문 제한, 한도 초과, 불완전 응답 사용량 기록, 외부 ID·가격 주입 거부, 장애·회계 실패, 요청 방식/CORS, 포장·수치 보존, 변경 없는 제안 제외.
- 격리 PGlite 계약 검사 14개: 무료/유료 모델 결정, 공통 한도 공유, 실패 시도 제한, 기존 요금제 조건 보존, 클라이언트 직접 예약 차단. 운영 DB를 사용하지 않습니다.
- Flutter 기능 테스트 10개: 원본 보존, 일부/전체 제안 적용, 단가·URL 보존, 입력 최소화, 원본 복원과 캐시, 실패 후 수동 저장, 계정 전환과 늦은 응답 폐기.
- 390px 한글 화면을 렌더링하여 비교 카드와 조작 버튼을 확인했습니다. `.artifacts/purchase-review-390.png`는 가상 품목/모의 응답으로 만든 검토 자료입니다.
- 사용자 승인 후 운영 DB 0066 → JWT 보호 함수 → 웹 순서로 반영했습니다. 운영 임시 계정과 가상 품목으로 실제 OpenAI 호출 3회(입력 1,287 / 출력 409토큰)를 수행하고 모든 임시 계정·사용량 행을 삭제했습니다. 메일은 보내지 않았으며 제공사 호출 비용은 발생합니다. 최종 호출은 HTTP 200, 5.88초였고 누락 단가 확인과 규격의 띄어쓰기 수정만 반환했습니다.
- 즉시 중지: 서버 플래그를 끄면 기존 수동 구매요청 작성은 유지됩니다. 기존 AI 예약 기록을 삭제하거나 과거 마이그레이션을 되돌릴 필요는 없습니다.

API 참조: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini).
