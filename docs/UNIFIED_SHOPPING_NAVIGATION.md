# 공통 메뉴와 장보기 흐름 통합

2026-09-29. 웹·Android 공통 Flutter 화면 변경. 운영 배포와 배포용 앱 파일 생성은 포함하지 않는다.

## 사용자 흐름

- 개인·전문가의 기본 메뉴: 레시피 찾기 / 레시피 보관함 / 장보기 / 더보기.
- 업소에서도 같은 이름과 순서로 표시한다. 허가되지 않은 업무는 표시하지 않는다.
- 상단 공간 선택에서 개인 공간, 실제 참여한 업소, 활성화한 공급업체 공간으로 이동한다. 업소 선택은 실제 소속 조회 결과를 사용한다.
- 신규 사용자에게 이용 목적 선택을 강제하지 않는다. 전문·공급업체 기능 설정은 더보기에서 계속 이용할 수 있다.
- 인분·배합·원가 도구는 레시피 보관함 및 개인 레시피 상세의 전문 도구에서 연다. 업소 경영·직원 권한 관리는 더보기로 모은다.

## 장보기

1. 구매 준비: 원본 목록 선택, 동일 재료·호환 단위 취합, 확인한 보유량 차감, 구매량 검토.
2. 진행 중: 확정한 구매량으로 구매처를 확인하고 실제 구매량을 기록한다. 목록 확인·완료에서 기존 완료 처리를 실행한다.
3. 구매 기록: 상품별 구매 기록, 완료한 목록, 거래처 요청 기록을 구분해서 조회한다. 저장 상품도 이곳에서 확인한다.

거래처 요청은 같은 화면의 해당 단계에서 준비·진행할 수 있다. 업소 장보기는 초안을 구매 준비에, 승인 대기·승인 완료·전달 건을 진행 중에, 입고·취소 건을 구매 기록에 표시한다. 검색과 건수는 기존처럼 현재 불러온 최대 50개 요청 기준이며 이전/다음 페이지로 이동할 수 있다.

## 자료·안전 조건

- 개인 자료와 업소 자료를 합치지 않는다. 서버 권한, 상품 공개 조건, 재고 반영, 승인·입고 확인 절차를 유지한다.
- 화면이나 제휴 링크를 여는 것만으로 주문·구매 완료·재고 반영을 수행하지 않는다.
- 구매 예정량은 구매처 화면과 실제 구매 기록 창에도 전달한다. 원본 필요량은 보존한다.
- AI로 이름이 다른 재료를 합친 경우, 실제 구매 기록은 같은 화면의 선택창에서 원래 재료별로 확인한다. 임의로 보유량을 배분하지 않는다.
- 특정 목록 링크는 다른 목록의 저장된 선택을 이어받지 않는다. 확인 상태는 목록·재고·날짜가 바뀌면 다시 검토한다.
- 저장 중에는 단계 전환을 막고 기존 편집 이탈 보호와 계정별 위젯 분리를 유지한다.
- 거래처 요청 기록과 실제 결제/구매 기록은 같은 장보기 메뉴에서 접근하되 별도로 표시한다.

## 이전 주소 호환

| 이전 주소 | 통합 화면 |
|---|---|
| `/shopping-preparation`, `/shopping-assistant` | `/shopping?stage=prepare` |
| `/kitchen?tab=shopping` | `/shopping?stage=active&view=lists` |
| `/kitchen?tab=history` | `/shopping?stage=records&view=lists` |
| `/purchases`, `/supplier-requests` | 단계에 맞는 `/shopping?...&view=requests` |
| `/supplier-request-ledger` | `/shopping?stage=records&view=requests` |

기존 목록 식별자와 요청 식별자는 보존한다. 레거시 전문 작업실 주소도 호환용으로 유지하지만 기본 메뉴에 중복 노출하지 않는다.

## 검증

핵심 검사는 `shopping_hub_test.dart`, `shopping_preparation_widget_test.dart`, `business_purchase_review_test.dart`, workspace 관련 테스트에 있다. 경로 호환, 수량 보존, 특정 목록 선택, 저장 중 단계 전환 보호, 역할별 메뉴, 모바일/데스크톱 및 영문 확대 글씨를 확인한다. 실제 서버 주문·입고 처리를 검증하기 위해 운영 자료를 변경하지 않는다.
