# 업소 구매요청의 쿠팡 연결 설계

## 검토 결과와 범위

개인 장보기는 제휴 상품을 여는 동작과 구매 기록을 분리한다. 업소 구매는 요청서 승인 → 전달 → 품목별 입고/반품으로 재고를 관리하며, 거래처 상품의 규격과 환산 근거가 연결돼 있다. 따라서 개인 구매 기록 저장 기능을 업소에 재사용하면 별도 재고·중복 기록 또는 승인 우회 위험이 있다.

기존 제휴 상품 조회와 링크 검증만 재사용하고, 업소 요청서에는 외부 상품 확인 화면을 연결한다. 요청서·상태·가격·수량·단위·거래처·재고·입고를 변경하는 코드는 이 기능에 포함하지 않는다. 서버 스키마와 기존 상태 전이는 변경하지 않는다.

## 진입과 사용 흐름

업소 장보기 → 진행 중 → 승인 완료 요청서 → 쿠팡 상품 확인 → 재료 선택 → 요청서와 상품 비교 → 쿠팡에서 구매.

- 구매 조회·작성 권한이 있고 유료 기능을 사용할 수 있는 구매 담당자만 승인 완료 요청서에서 사용한다. 승인 생략 업소도 기존 '구매 승인' 단계로 수량을 확정한 뒤 사용한다.
- 작성 중·승인 대기에서는 승인 안내를 제공한다. 전달·입고·취소된 요청과 연습 공간에서 실제 구매 링크를 제공하지 않는다.
- 기존 공개 상품 RPC를 그대로 사용해 웹/모바일 허용 위치, 공개 상태, 확인 기한, 재료 매칭을 적용한다. 쿠팡의 유효한 발급 링크만 표시한다.
- 요청서 수량·단위·규격·단가와 쿠팡 상품 규격을 구분해 표시한다. 포장 개수, 무게/부피, 단가 환산을 추정하지 않는다. 다른 거래처·상품·금액으로 구매할 경우 기존 수정·재승인을 사용하도록 안내한다.
- 사용자가 승인 내용과 상품을 확인하고 중복 주문 여부를 확인한 후 외부 링크를 연다. 열기 직전에 서버에서 권한·요청서·상품 공개 여부를 다시 읽는다. 계정 변경, 요청서 변경, 공개 중단, 연결 오류에는 링크를 열지 않는다.
- 웹은 같은 탭으로 열어 비동기 확인 후 팝업 차단을 피하고 뒤로 가기로 복귀한다. Android는 기존 외부 브라우저/앱 열기 방식을 사용한다.
- 쿠팡 주문 후 기존 '전달 완료로 기록'으로 발주 사실을 기록하고, 수령 후 '품목별 입고·반품'에서 실제 수량을 확인한다. 상품을 열었다는 이유로 주문·결제·상태·재고를 처리하지 않는다.

## 보장 범위

쿠팡 주문 API나 주문 동기화를 추가하는 기능이 아니다. 사용자가 외부 페이지를 연 뒤 수행하는 주문과 직원 간 외부 중복 주문을 앱에서 차단하거나 감지할 수는 없다. 열린 페이지는 나중에 권한이 바뀌어도 회수할 수 없다. 담당자가 실제 주문 내역과 승인 내용을 확인해야 하며, 앱의 구매·입고 원본과 개인 장보기 자료는 그대로 보존한다.

## 검증 계획

승인/권한/연습 모드별 제한, 최신 요청서·상품 변경 시 차단, 계정 변경과 중복 클릭, 공개 상품이 없는 경우와 조회/열기 오류, 단위·규격 보존, 취소/뒤로 가기 무변경, 한국어·영어 좁은 화면과 큰 글씨를 검사한다. 기존 개인 장보기·업소 승인/입고 테스트와 전체 분석·테스트를 실행한다.

## 구현과 확인 범위 (2026-09-29~30)

- 승인된 구매 요청 카드와 요청서 상세에 진입 버튼을 추가했다. 공통 라우터에서 구매 화면으로 분류하며, 로그인 계정이 바뀌면 화면과 확인 창의 자료를 비운다.
- 도메인 검증과 읽기 전용 연결 서비스를 화면에서 분리했다. 요청서 전체 내용과 리비전, 최신 권한, 공개 상품의 제목·규격·발급 링크를 확인한다. 서버 응답을 기다리는 동안 계정이 바뀌어도 이후에 링크를 열지 않는다.
- 신규 동작 검사 31개를 통과했다. 일반 장보기 자료나 업소 구매·입고 자료를 저장하는 메서드가 호출되지 않는지도 검사했다. 정기 권한 갱신 중 변경 없는 구매 확인 창이 유지되는지 확인했다. 390px 모바일 및 1440px 웹 크기의 한국어 화면과 확인 창을 이미지로 확인하고, 320px 영어 화면에 글씨 크기 2배를 적용한 조작도 검사했다.
- 기존 v90 파일 및 버전 번호를 유지한다. 이 변경은 아직 운영 웹에 배포하거나 Android 파일에 포함하지 않았다. 실제 기기에서의 쿠팡 앱 전환과 외부 주문·결제는 이번 자동 검증 범위에 포함하지 않는다.

기본 개발 환경 검사에는 전역 Flutter/Dart 경로와 프로젝트 SDK 경로 차이, Android SDK 라이선스 확인 불가, Windows용 Visual Studio 구성 부족 경고가 있었다. 실제 분석과 테스트는 지정된 Flutter 3.44.8로 실행했다. 릴리스 빌드나 SDK 설정 변경은 하지 않았다.
