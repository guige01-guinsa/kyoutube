# 장보기 목록의 쿠팡 판매 규격·구매량 계획

2026-09-30 구현. 운영 적용 전 검증 기록.

## 사용자 흐름

- 개인 장보기: 목록을 생성하면 재료 카드에 현재 기기에서 공개된 쿠팡 상품을 표시한다. `이 상품으로 구매량 적용`을 누르면 판매 단위 수량과 총내용량, 부족량 또는 여유량을 보여준다. 수량 조절·상품 변경 후에는 목록을 다시 확정한다.
- 필요한 양과 실제 구매 예정량은 별도로 보관한다. 소면 필요량 1.2kg, 판매 옵션 900g 한 봉이라면 권장 수량은 2봉, 구매 총량은 1.8kg, 여유량은 600g이다. 구매 기록 창에는 1.8kg을 제안하며, 실제 수령 결과는 사용자가 확인한다.
- 업소 메뉴·확정 식단 구매 준비: 재료별로 기존 공급업체 또는 쿠팡 상품을 선택한다. 쿠팡 품목과 공급업체 품목은 별도 요청서로 생성한다. 공급업체의 기존 상품 연결·요청 단위·재고 예약 절차를 유지한다.
- 업소 직접 요청서 편집: 구매 담당자가 작성 단계에서 쿠팡 상품을 선택하고 포장 수를 조절할 수 있다. 기존 요청서의 일반 구매 수량이 내용량 단위(g/kg/mL/L/개)여야 자동 환산할 수 있다. 한 요청서에 공급업체 품목과 쿠팡 품목을 섞어 저장할 수 없다. 혼합 목록은 메뉴 구매 준비에서 구매처별로 생성한다.
- 업소 구매 링크는 승인된 요청서에서 연다. 선택한 상품·규격이 달라지면 작성 상태로 돌아가 다시 선택하고 승인한다. 최신 권한·요청서·상품 정보를 재확인한 뒤 발급된 제휴 주소 그대로 연다.
- 링크 열기와 계획 저장은 주문 완료나 입고로 처리하지 않는다. 입고 시 쿠팡 판매 포장의 내용량을 환산 값으로 제안하며, 실제 수령량·재고 품목·환산 값은 기존 확인 절차로 확정한다.

## 관리자가 등록할 판매 규격

제휴 상품 관리에 선택 항목을 추가했다.

1. 개별 포장 내용량과 단위
2. 한 번 주문에 포함된 포장 수
3. 판매 단위 이름(봉·병·묶음 등)
4. 직접 확인한 판매 옵션명

예: `500g × 2봉` 한 묶음은 내용량 500, 단위 g, 포장 수 2, 판매 단위 묶음이다. 한 번 주문하면 1,000g을 받는다. 포장 수를 다시 중복 곱하지 않는다.

기존 링크는 그대로 사용할 수 있다. 판매 규격이 미등록·미확인인 상품은 수량을 자동 계산하지 않는다. 제품명에서 무게나 밀도를 추정하지 않으며 g↔mL, 개↔g 같은 환산은 하지 않는다. g↔kg, mL↔L, 명시적인 개수만 호환 환산한다.

## 데이터와 호환성

- `0080_coupang_sale_packs.sql`: 선택적인 `purchase_pack` 구조와 검증, 새 공개 조회 RPC. 기존 조회 RPC는 유지한다. 이전 편집기에서 상품 정보나 주소를 변경하면 오래된 판매 규격을 지운다.
- `0081_coupang_purchase_planning.sql`: 요청서 품목의 판매 옵션 스냅샷, 쿠팡·공급업체 분리 생성, 변경된 옵션의 저장·승인 차단. 확정 식단 연결, 재고 예약, 기존 요청서 승인·입고 기능을 사용한다.
- 상품 공개 위치·만료·삭제·검토 상태를 유지한다. 새 조회 RPC가 없는 서버에서는 기존 상품 링크 조회로 돌아가며 판매 규격 계산은 제공하지 않는다.
- 변경된 구매량·판매 옵션으로 같은 요청 ID를 재사용할 수 없다. 응답 유실 후 동일 요청 재시도는 같은 결과를 반환한다.
- 개인 계획은 기존 계정별·원본 목록 및 재고 지문별 로컬 저장을 사용한다. 변경된 재료·재고·날짜에 이전 확정을 재사용하지 않는다.
- 일반 쿠팡 검색, Google 쇼핑, 네이버 검색 버튼을 다시 노출하지 않았다. 쿠팡 결제 화면에 장바구니나 주문 수량을 자동 입력하는 기능은 포함하지 않는다.

## 검증

- 격리 PostgreSQL에서 기존 관리 기능과 함께 463개 검증 통과. 운영 데이터 쓰기 0건.
- 새 계산·개인 목록·업소 구매 준비 화면 테스트 10개 통과.
- 기존 관련 화면 테스트 52개 통과.
- 최종 `flutter analyze` 통과(문제 없음). `.artifacts/coupang-planning-analyze-final.log`에 기록했다.
- 전체 앱 테스트는 790개 통과, 기존 제외 4개, 번역 누락 검사 2개 실패였다. 누락 문구를 보완한 후 해당 파일의 검사 3개 모두 통과했다. 수정 후 재검사를 포함하면 실행 대상 792개가 통과했다. 전체 실행은 `.artifacts/coupang-planning-verify.log`, 재검사는 `.artifacts/coupang-planning-localization-test.log`에 기록했다.
- 개발 환경 진단의 기존 경고(전역 Flutter 경로, Android 라이선스, Windows 데스크톱용 Visual Studio)는 남아 있다. 이번 작업은 출시 빌드를 실행하지 않았다.
- 모바일 화면 구성은 위젯 렌더링으로 확인했다. 실제 쿠팡 주문·결제는 실행하지 않았다.

## 운영 반영

2026-09-30 후속 배포 승인으로 DB 변경 0076~0081과 운영 웹 v91을 적용하고 서명된 v91 AAB를 생성했다. 기존 v90 파일은 보존했으며 Google Play 업로드는 실행하지 않았다. [배포·검증 기록](release-v91.md)을 참고한다.

배포 당시 공개 쿠팡 상품 101개 중 구조화된 판매 규격이 입력된 상품은 없었다. 현재 상품의 판매 규격은 운영자가 실제 판매 옵션을 확인해 입력해야 한다. API 키나 자동 검색에 의존하지 않는다.
