> 2026-09-13 보안 반영 이후 상태는 [최신 운영 반영 기록](security-rollout-2026-09-13.md)을 확인하세요. 아래의 이전 날짜 상태와 구분합니다.

2026-09-13 운영 확인: REST 경로의 safeupdate 호환성 수정 0041을 추가 적용했다. 03:20 KST 정시 예약에서 점검 시간과 비용 자료 누락 경고 저장을 확인했다. Firebase 발송 자격 증명 미설정으로 발송 상태는 실패이며 HTTP 503을 반환한다. 앱 알림함 평가는 동작하지만 휴대폰 푸시는 아직 완료되지 않았다.

## 사용자 흐름

회원 관리자 → 서비스 운영 현황 → 상단 알림 아이콘 → 운영 알림함.
관리자는 이 휴대폰에서 푸시 받기를 선택하고 OS 알림 권한을 허용한다.
푸시를 누르면 알림함을 열며, 앱 사용 중에는 간단한 알림 배너와 확인 버튼을 표시한다.
한/영 UI, 날짜, 경고/위험/복구, 판단 수치, 조치 안내, 읽음 표시, 50건 페이지 조회를 제공한다.
푸시에 상세 원가·매출·토큰·회원 정보는 싣지 않는다.

마지막 점검이 없거나 15분 이상 지났으면 자동 점검의 설정/실행을 확인하도록 표시한다.
푸시 실행 실패와 전송 대기·실패 건수를 알림함에 표시한다.
관리자가 설정하는 DB 용량은 알림 계산 기준이며 실제 디스크 할당량이나 유료 서버 등급을 변경하지 않는다.

## 서버 구조

- 0036 관측 테이블/RPC가 전제, 신규 0040이 알림 상태·이벤트·기기·읽음·전송 큐를 추가한다.
- operations_monitor를 5분 주기로 실행한다. 월30일 기준 약8,640회이며 일반 사용자의 앱 실행 수와 무관하다.
- evaluate_ops_alerts는 advisory lock으로 동시 상태 전이를 직렬화한다.
- 전송은 한 번에 10건을 10분 임대로 확보하고 실패 시 다음 예약에서 재시도한다. 최대5회, 24시간 초과는 만료 처리한다.
- FCM 성공 직후 DB 확인 기록이 실패하면 재전송될 수 있는 at-least-once 방식이다. Android tag/iOS collapse ID로 동일 이벤트 중복 표시를 줄인다. 정확히 한 번 전달이나 OS 배달을 보장하지 않는다.
- 잘못된 등록 토큰(UNREGISTERED)은 제거한다. 일반 공급자 오류는 토큰을 삭제하지 않는다.
- 푸시 전송 서비스가 실패해도 이미 저장한 알림함 기록은 유지된다.
- 이벤트90일, 만료 기기30일 정리. 로그인 앱이 등록을 갱신한다.
- 기기는 관리자 user와 auth.sessions에 묶인다. 관리자 역할 재검사, 세션 만료 검사, 세션 삭제 시 기기/대기 전송 cascade 삭제. 일반 사용자에게 토큰 테이블 권한이 없다.
- 일반 사용자/비로그인은 알림함 및 관리자 RPC를 사용할 수 없다. 서버 실행 RPC는 service_role만 실행한다.

## 운영 구성과 남은 기기 검증

1. 2026-09-13 사용자 명시적 승인으로 0036·0040, 관측 래퍼 함수들, operations_monitor, 5분 예약과 v57 AAB를 적용했다. 기존 함수 소스를 각각 백업하고 관측 래퍼만 추가했으며 기존 JWT 설정을 유지했다.
2. Supabase 시크릿 FCM_SERVICE_ACCOUNT_JSON(해당 Firebase 프로젝트의 FCM 발송 권한), OPS_MONITOR_SECRET(무작위 최소32자)를 안전한 서버 설정에 등록한다. OPS_MONITOR_SECRET과 Vault 설정은 완료했다. FCM_SERVICE_ACCOUNT_JSON은 추가 설정이 필요하다. 앱용 google-services.json만으로는 서버 발송 권한을 얻을 수 없다.
3. Vault에 ops_monitor_url, ops_monitor_secret를 동일 값으로 설정한다. 값은 코드/문서/로그에 남기지 않는다. FCM HTTP v1 API가 활성화되어 있어야 한다.
4. 로컬/스테이징 검증 후 승인된 운영 DB에 0036·0040만 적용한다. 이미 적용된 0037~0039는 재실행하지 않는다.
5. 승인된 관측 함수 패키지를 검증한 후 배포한다. operations_monitor는 JWT 게이트 대신 별도 스케줄러 비밀값 헤더를 검증하는 전용 엔드포인트이며, 다른 함수의 JWT 검증은 바꾸지 않는다.
6. tools/ops/schedule-operations-monitor.sql을 검토 후 실행한다. Vault에 URL/비밀값이 없으면 예약 전 오류로 중단한다. 새 예약이 즉시 고객 전체에게 발송하는 구조가 아니며 등록된 관리자 기기만 대상으로 한다.
7. 후속 앱의 관리자 기기로 등록→테스트 상태 전이→FCM 실제 수신→앱 열기→읽음→정상 복구→로그아웃 후 차단을 확인한다. 현재 로컬 검증은 실제 FCM 수신을 대신하지 않는다.
8. pg_cron/pg_net 실행 실패와 함수 503을 확인한다. Supabase 자체 또는 DB 전체가 중단되면 같은 DB 기반 점검도 멈춘다. 완전 장애 즉시 통지는 독립된 외부 상태 점검이 추가로 필요하다. 현재 앱의 오래된 점검 경고는 앱을 열 때 확인할 수 있다.

알림은 환경 변경을 권고할 뿐 자동 증설·요금제 변경·AI 한도 축소·비용 자동 차단을 수행하지 않는다.
