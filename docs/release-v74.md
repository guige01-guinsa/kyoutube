# Recipe Scout v74 — 2026-09-19

사용자 승인에 따라 **DB 0062 운영 적용, 운영 웹 배포, 1.0.1+74 서명 AAB 생성**을 완료했다. 기존 Firebase/Supabase 프로젝트와 v73 업로드 서명을 유지했다. 새 Edge Function 배포는 필요하지 않다.

## 사용 흐름

- **업소·전문가 → 담당 업무 설정**에서 구매·조리·경영을 선택하고 자주 쓰는 업무를 첫 화면에 배치한다. 업무 선택은 화면 설정이며 자료 권한을 부여하지 않는다.
- **업소 공동 업무 → 업소 만들기 → 직원·권한 관리**에서 사장이 업소를 만들고 직원 이메일과 권한을 지정한다. 업소 책임자의 활성 Business 이용권이 필요하다.
- 직원은 자기 계정으로 로그인하고 **초대 코드로 참여**한다. 초대받은 인증 이메일과 일치해야 하며 코드는 24시간 이내 한 번 사용할 수 있다. 초대 코드는 사용자가 직접 전달한다.
- 조리 담당자의 레시피·식단 연구, 구매 담당자의 요청·승인·전달/입고 확인, 경영 담당자의 원가·판매 기록을 공동 자료로 연결한다.
- 기존 개인 자료는 자동 공유하지 않는다. 조리 수량과 구매 수량을 구분하며 조리로 인한 재고 자동 차감은 하지 않는다.

권한표, 업무별 흐름과 현재 지원 범위: [업소 공동 업무 안내](business-workspaces.md).

## 운영 적용 및 검증

- 암호화 백업 복호화·내용 해시·변조 차단 검사 통과. 별도 Docker DB에 **88개 테이블·4,779개 행**을 실제 복원해 확인했고 임시 컨테이너를 제거했다. 평문 SQL 파일은 저장하지 않았다.
- 검증된 `0062_business_workspaces.sql`만 트랜잭션으로 적용했다. 기존 마이그레이션 이력을 보존했고 기존 회원 24명·개인 레시피 30건이 유지됐다.
- 운영의 새 **6개 테이블 RLS·22개 함수 권한**, 직접 쓰기 금지, 초대 해시 조회 차단, 비로그인 HTTP 접근 차단 확인.
- 별도 Supabase PostgreSQL 17 테스트 DB에서 권한·초대·승인·동시 수정·문서 재검사·판매 기록 보존 **57개 검사** 통과. 이 결과는 격리된 인증 fixture 기반이며 실제 운영 계정 로그인 테스트가 아니다.
- Flutter **3.44.8 / JDK 17**, 분석 오류 0개, 자동 테스트 **467개 통과·기존 제외 4개**. 빌드 전후 입력 파일 **341개** 해시 일치.
- AAB 버전·서명·ZIP 무결성·운영 설정·공동 업무 코드·한글 PDF 글꼴·비밀키 미포함 확인. v73 서명과 일치.
- 웹 두 도메인에서 각각 **13개 자산** 일치, CSP/HSTS/프레임 차단 등 보안 헤더 확인. 앱 소스맵 미게시.
- 실제 Edge 브라우저에서 한영 업무 전환 6개 흐름, 한영 공동 업무 안내 2개, 보호 경로 12개를 포함한 **22개 검사** 통과. 서버 테스트 쓰기·브라우저 오류 0건.
- 배포된 한국어 구매 모바일 화면과 영어 경영 데스크톱 화면을 시각적으로 확인했다.

실제 직원 계정의 운영 로그인·초대 수락·공동 자료 저장 전 과정은 이번 출시 검사에서 수행하지 않았다. 서버 권한 동작은 격리된 PostgreSQL 검사와 운영 권한 검사로 확인했다. Google Play 업로드·휴대폰 설치·실제 초대/구매요청 발송·프린터 출력은 수행하지 않았다.

## 복구와 후속 확인

운영 장애가 있으면 Firebase Hosting의 이전 릴리스로 웹을 복구하고 0062의 공동 자료는 보존한다. Android는 이전 기능을 복구한 코드로 더 높은 versionCode의 새 서명 AAB를 만들어야 하며 Google Play에 v73을 단순 재업로드해 다운그레이드할 수는 없다.

다음 실사용 확인은 사장·구매·조리·경영의 실제 테스트 계정으로 초대 수락 → 레시피 전달 → 구매 승인 → PDF → 권한 해제 순서로 수행한다. 공동 원가의 재료별 단가·수율 자동 동기화, 공동 구매의 공개 업체 자동 비교, 업소 소유권 이전은 후속 확장 범위다.
