# 셰프 작업실 / Chef studio

이 문서는 v55의 1차 기능 기준이다. 2026-09-13 후속 원가 항목·판매가·매출 기능과 적용 대기 상태는 [원가·판매가·매출 관리](chef-costs-and-sales.md)를 참조한다.

사용자가 선택한 1차 범위는 **재료비·수율·추가 비용**이다. 인분 환산, 원가, 조리 수율, 배합/조리법 버전 저장·비교·복원을 구현한다. 기존 영어 초안 개선 및 편집 실행 취소·다시 실행 변경도 유지한다. 2026-09-12 사용자 명시적 승인 후 운영 DB 0037과 영어 초안 함수를 적용했다. 승인된 v55 빌드의 최종 결과는 CURRENT_STATUS.md와 release-notes-v55-ko.md에 기록한다.

## 사용 흐름

1. 내 레시피의 편집 가능한 레시피 상세에서 **셰프 작업실**을 연다.
2. 원본의 기준 인분과 만들 목표 인분을 입력한다. 원본 인분을 모르면 임의로 추측하지 않는다.
3. 재료별 손질 후 사용량, 손질 수율, 구매 포장량·단위·가격을 확인한다.
4. 인건비·포장비 등을 합산한 추가 비용을 기준 배치 금액으로 입력한다. 이 비용은 목표 인분에 비례해 환산된다.
5. 조리 전 총중량과 완성 중량을 g으로 입력하면 조리 수율 및 완성품 100g 원가를 확인할 수 있다.
6. **작업 저장**은 현재 배합을 보관하고, **새 버전 저장**은 이름과 변경 이유를 붙인 과거 기록을 만든다.
7. 버전 관리에서 두 버전의 배합·단가·수율·인분·조리법·메모 차이를 확인한다. 과거 버전을 불러온 뒤 저장해도 기존 버전은 변경되지 않는다.

The same workflow is available in English through **My recipes → editable recipe → Chef studio**. Base quantities are edible quantities after trimming. Pack price is the total price of the entered purchase pack. Extra cost applies to the base batch and scales with servings.

## 계산 기준

- 환산 배수 = 목표 인분 ÷ 기준 인분.
- 목표 사용량 = 기준 사용량 × 환산 배수.
- 필요 구매량 = 목표 사용량 ÷ (손질 수율 ÷ 100).
- 재료 원가 = 구매 단위로 변환한 필요 구매량 ÷ 포장량 × 포장 구매가.
- 배치 원가 = 기준 재료비와 추가 비용의 합 × 환산 배수.
- 1인분 원가 = 목표 배치 원가 ÷ 목표 인분.
- 조리 수율 = 기준 배치 완성 중량 ÷ 조리 전 중량 × 100.
- 완성품 100g 원가 = 기준 배치 원가 ÷ 기준 완성 중량 × 100.

예: 기준 4인분, 목표 10인분, 당근 사용량 800g, 손질 수율 80%, 1kg 포장 구매가 8,000원, 기준 추가 비용 1,000원이면 사용량 2,000g, 필요 구매량 2,500g, 목표 재료비 20,000원, 전체 원가 22,500원, 1인분 원가 2,250원이다. 기준 조리 전 1,000g에서 완성 중량 750g이면 조리 수율 75%, 완성품 100g 원가는 1,200원이다.

kg↔g, L↔ml, 개수끼리만 환산한다. g↔ml에는 식재료 밀도가 필요하므로 자동 환산하지 않는다. 범위 수량·적당량·컵/스푼·추정 표시 등은 확인 전 자동 계산하지 않는다. 조리 시간과 온도는 인분에 비례해 변경하지 않는다. 손질 수율은 0 초과 100% 이하이며, 조리 수율은 물 흡수 등으로 100%를 넘을 수 있다.

단가가 비어 있으면 0원으로 보지 않는다. 확인된 재료비만 따로 보여 주고 전체/1인분 원가는 미완성으로 표시한다. 실제로 0원을 입력한 경우에만 무료 재료로 계산한다. 구매량은 원가 계산용 비례량이며 포장 단위 발주 올림 계산은 하지 않는다.

KRW/USD를 지원한다. 통화 변경은 환율 변환이 아니므로 가격을 다시 확인하는 안내를 표시한다. 판매가·목표 원가율·세무/회계 처리는 이번 범위에 포함하지 않는다.

## 데이터와 접근 제어

새 마이그레이션은 supabase/migrations/0037_chef_workspaces.sql이다. chef_workspaces에 현재 문서와 수정 번호, chef_recipe_versions에 당시 배합·단가·조리법 전체 문서를 저장한다. 기존 recipes_creator 행이나 레시피 본문은 수정하지 않는다.

저장은 save_chef_workspace RPC만 허용한다. 호출자와 원본 레시피 소유자를 확인하고, 행 잠금 및 예상 수정 번호를 통해 다른 기기의 변경을 덮어쓰지 않는다. RLS는 본인 자료만 읽도록 제한한다. 클라이언트는 과거 버전 수정·삭제 권한이 없다. 원본 레시피 또는 계정 삭제 시 관련 작업실과 버전도 함께 삭제된다.

재료 최대 200개, 문서 최대 256KiB, 버전 이름 80자, 변경 이유 1,000자 등 서버 한도를 적용한다. 버전 이력은 20개씩 조회한다. 불러오기는 새 작업 문서로 복원하며 사용자가 저장할 때 반영한다. 저장 실패 시 입력을 화면에 남기고, 충돌 시 다시 불러오기 전에 변경 폐기를 확인한다.

## 검증과 반영 상태

- 2026-09-12 최종 Flutter 분석: 문제 0개. 전체 Flutter 테스트: **191개 통과**. 로그는 .artifacts/chef-analyze.log, .artifacts/chef-full-tests.log.
- 계산식·단위 호환성·미입력 단가·수율·버전 가격 보존에 대한 단위 테스트.
- 한글/영어, 폭 320px·글자 2배, 편집·저장·버전 복원·저장 충돌에 대한 위젯 테스트.
- 로컬 SQL 트랜잭션 검증: 과거 버전 보존, stale revision 거부, 타 계정 읽기/쓰기 차단, 익명 RPC 차단, 원본 삭제 연계. 모든 변경은 테스트 종료 시 롤백한다.
- SQL 계약 검증 결과: **CHEF_CONTRACT_PASSED** (.artifacts/chef-sql-contract.log). 실제 복수 세션의 동시 부하 시험이나 운영 휴대폰 테스트를 의미하지 않는다.
- 화면 렌더: .artifacts/chef-studio-ko.png, .artifacts/chef-studio-en.png. 실제 휴대폰 설치 화면이 아닌 Flutter 위젯 렌더다.
- 최종 한글/영어 캡처 테스트 2개 통과 (.artifacts/chef-capture.log). 두 이미지를 열어 제목, 원가 카드, 입력란, 하단 저장 버튼의 배치와 잘림 여부를 확인했다.

기존 v54 AAB에는 이 기능이 없다. 운영 DB 0037과 적용 이력을 한 트랜잭션으로 기록했다. 배포 후 RLS 활성화, 본인 읽기 정책 2개, 인증 사용자 RPC 실행 허용, 익명 RPC 및 직접 수정·과거 버전 삭제 차단을 확인했다 (.artifacts/v55-chef-verify.json). 0036 운영 관측 마이그레이션은 이번 승인 범위에 포함하지 않아 계속 보류한다. 실기기 사용에는 v55 테스트 트랙 설치와 로그인 후 저장·복원 확인이 필요하다.
