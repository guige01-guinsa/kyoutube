# 업무 흐름 연속성 개선 결과

운영 반영 완료: [v93 배포 기록](release-v93.md). 아래 개발 단계 기록 이후 DB·웹·AAB 적용과 출시 검증을 완료했다.

작업일: 2026-09-30

## 구현 범위

기존 `workflow-continuity-audit.md`의 우선순위 1~3단계를 구현했다. 과거 데이터 보존을 위해 불편한 절차를 유지할 필요는 없다는 사용자 지침을 반영하되, 수량 오류·중복 처리·다른 계정 접근을 막는 검증은 유지했다. 운영 데이터 삭제나 초기화는 수행하지 않았다.

### 1. 구매 준비와 입고

- 거래처·상품 선택 창에서 검색어를 유지한 재조회, 빈 목록과 검색 불일치 구분, 바로 신규 등록 후 선택을 지원한다.
- 신규 거래처·상품은 저장된 ID로 다시 조회한다. 목록 개수 제한 때문에 방금 등록한 항목을 찾지 못하는 문제를 피한다.
- 재고가 없을 때도 입고 작업을 시작할 수 있다. 품명·규격을 이어받아 재고 품목을 등록하고 원래 입고 화면으로 돌아온다.
- 입고의 수량·환산 확인, 중복 실행 방지, 첫 입고 후 연결 잠금은 유지한다.
- 공급업체 검색에 결과가 없으면 개인 거래처 등록 후 원래 재료로 요청서를 작성할 수 있다.
- 구매 준비 내역과 재고 후보의 오류 재시도에서 비동기 결과를 화면 상태 변경 함수가 반환하던 오류도 수정했다.

### 2. 로그인·승인·편집 충돌

- 로그인과 관리자 2단계 인증 후 내부 업무 경로로 복귀한다. 앱 내에서 화면을 겹쳐 연 경우 원래 화면과 입력을 유지한다.
- 외부 인증으로 앱이 다시 열리는 경우에는 제한 시간 30분의 일회용 내부 경로를 복원한다. 외부 주소·인증 반복 경로는 거부한다. 브라우저가 재시작되면 모든 편집 입력까지 복원한다는 의미는 아니다.
- 미확인 이메일은 로그인 화면에서 명시적으로 인증 메일을 재발송할 수 있다. 재발송 대기시간은 60초다.
- 쿠팡 상품 변경·승인 문제는 정확한 구매요청서를 열어 수정·재승인한 뒤 최신 자료를 조회한다. 구매·저장을 자동 실행하지 않는다.
- 판매 메뉴가 없거나 승인된 레시피 버전이 없으면 해당 설정·레시피 화면을 열고 선택 창을 다시 갱신한다.
- 제휴 링크 중복은 정확한 기존 상품 또는 휴지통 상품을 조회한다. 동시 편집 충돌은 최신 내용과 내 입력을 비교하고 사용자가 선택한다. 초안을 자동으로 최신 자료에 덮어쓰지 않는다.
- 일반 장보기의 레시피 조회 오류와 인증 문제에도 현재 화면에서 재조회·로그인 경로를 제공한다.

### 3. 재고 환산과 정리

- 재료 g와 재고 kg, 재료 mL와 재고 L 등 표준 환산 가능한 단위를 연결한다. 무게↔부피나 규격이 없는 포장은 자동 환산하지 않는다.
- 재료 기준 필요량과 실제 재고 기준 예약량을 분리한다. 같은 재고를 여러 재료가 사용하는 경우 재고 단위로 누적하여 중복 배정을 막는다.
- 재고 배정은 지원 정밀도 안에서 내림 처리하며 남은 필요량은 구매 수량에 남긴다. 미리보기 이후 잔량이 바뀌면 재조회하도록 서버가 차단한다.
- 삭제·단위 변경이 관련 자료 때문에 막히면 해당 재고·예약·요청서로 이동하고, 돌아온 후 영향을 다시 확인한다.
- 조리 완료 후 관련 구매 준비 내역과 재고 예약으로 이어진다. 조리 완료만으로 예약 전체를 사용 처리하지 않는다.

## 화면 경로 검증 보완

현재 GoRouter에서는 ShellRoute의 직접 자식에 다른 상위 Navigator를 지정할 수 없다. 해결 화면(로그인·MFA·판매 메뉴·요청서 상세·재고 상세)을 최상위 경로로 옮기고 공통 WorkspaceFrame을 명시적으로 적용했다. 기존 입력 창 위에서 열리고 돌아올 수 있으며 공통 화면 구성을 유지한다. 실제 앱 라우터 생성과 앱 시작 테스트로 확인했다.

## 서버 적용

새 마이그레이션: `supabase/migrations/0083_workflow_continuity.sql`.

단위 환산·예약 처리 변경과 제휴 상품/재고 의존 자료 조회를 포함한다. 앞선 개발의 `0082`도 운영 적용 여부를 확인해야 한다. 배포 시에는 서버 마이그레이션을 먼저 적용하고 웹·Android를 배포한다. 이번 개발 작업에서는 운영 DB, 웹 배포, AAB 생성, Play Console 등록을 하지 않았다.

## 검증

- 분리된 PostgreSQL 테스트: 339개 통과, 운영 DB 쓰기 0건.
- 전체 Flutter 검사: 800개 통과, 4개 선택적 화면 캡처 검사 제외, 8개 실패를 발견했다. 실패는 좁은 화면의 쿠팡 수정 버튼 넘침 1건과 같은 화면 경로 구성 오류에 의한 7건이었다.
- 두 원인을 수정한 뒤 해당 4개 테스트 파일(앱 시작, 실제 라우터 구성, 거래처 선택 창 위 등록 화면과 복귀, 쿠팡 구매)을 다시 실행하여 69개 모두 통과했다. 수정 뒤 전체 808개를 한 번 더 실행한 결과로 표현하지 않는다.
- 새 선택 창 재조회·등록 취소 시 검색 유지, 빈 재고 등록 후 입고 복귀, 안전한 인증 복귀 주소와 만료, 번역 누락 검사는 전체 검사에서 통과했다.
- 최종 정적 분석 결과: `.artifacts/workflow-final-analyze.log`.
- 검증 로그: `.artifacts/workflow-verify.log`, `.artifacts/workflow-routing-final.log`, `.artifacts/workflow-db.log`.
- `tools/dev/verify.ps1` 실행 시 개발 환경 진단에 기존 Android 라이선스 확인 불가·Windows용 Visual Studio 구성 미완료 경고가 있다. 앱 분석과 Flutter 테스트는 실행됐다. Android 출시 빌드 성공 여부를 확인한 것은 아니다.
- 실제 운영 계정의 Google/Kakao 인증 왕복, Android 실기기의 뒤로 가기와 외부 구매 후 복귀는 아직 현장 검증하지 않았다.
- 시스템 무결함을 보증하는 결과는 아니며, 출시 전 위 실제 기기 흐름을 확인해야 한다.
