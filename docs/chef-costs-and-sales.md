# 원가 항목·판매가·매출 관리

2026-09-13. 사용자 승인 후 운영 DB 0038·0039 적용과 v56 서명 AAB 생성을 완료했다. Play 업로드·실기기 설치는 별도이며, 유료 전용 제한은 아직 구현되지 않았다. [v56 출시 기록](release-notes-v56-ko.md)을 참조한다.

## 원가 항목 관리

- 셰프 작업실 → 추가 비용 관리에서 인건비·포장비·공과금·배송비 이름을 선택하거나 직접 입력한다.
- 기준 인분에 드는 금액을 항목별로 입력한다. 수정·삭제 즉시 총원가와 1인분 원가를 다시 계산하며, 작업 저장을 눌러 보관한다.
- 재료마다 단가 바로 수정 버튼으로 구매 포장량·단위·가격을 변경할 수 있다. 수량/수율을 바꾸는 재료 수정도 유지한다.
- 1,500 또는 1,500.50 같은 천 단위 구분 입력을 지원한다. 1,5 또는 12,00은 추측해서 변환하지 않는다.
- 기존 v55 추가 비용은 별도 기존 비용 항목으로 표시하고 편집·삭제할 수 있다. 새 항목과 이중 계산하지 않는다.
- 이름은 최대 80자, 항목은 최대 100개, 추가 비용 총액은 최대 1조이다. 모든 비용은 기준 인분에 대한 금액이며 목표 인분에 비례한다.

## 판매가 계산

사용자가 **원가에 이익을 가산하는 방식**을 선택했다. 원가 10,000원에 50%를 선택하면 판매가 15,000원이 된다. 원가율(판매가에서 원가가 차지하는 비율)이나 판매가 기준 이익률이 아니다.

- 판매가 = 1인분 원가 × (1 + 선택 가산율 ÷ 100).
- 슬라이더 0~100%. 0%는 원가, 100%는 원가의 두 배이다.
- KRW는 원 단위, USD는 센트 단위로 판매가를 반올림한다. 원가 계산 중간값은 반올림하지 않는다.
- 원가가 불완전하면 판매가 계산과 판매 기록 추가를 막고 입력 확인을 안내한다.
- 저장하고 매출 관리 버튼은 현재 원가와 비율을 먼저 저장한 뒤 매출 화면을 연다.

예: 원가 10,000원에 50% 가산 → 판매가 15,000원. 10인분 판매 → 매출액 150,000원, 판매분 원가 100,000원, 예상이익 50,000원.

## 일·주·월 조회

판매일과 판매 수량(인분)을 직접 기록한다. POS·결제 시스템 자동 연동은 포함하지 않는다.

- 요리별 화면과 내 레시피 상단 매출 현황의 전체 요리 집계를 제공한다.
- 일별은 선택 날짜, 주별은 월요일~일요일, 월별은 해당 달 전체이다. 날짜 및 이전/다음 기간 선택을 지원한다.
- 매출액 = 기록 당시 판매가 × 판매 수량.
- 판매분 원가 = 기록 당시 1인분 원가 × 판매 수량.
- 예상이익 = 매출액 − 판매분 원가. 미입력 비용과 세금은 포함하지 않는다.
- KRW와 USD는 별도 집계한다. 환율 변환이나 통화 혼합 합산은 하지 않는다.
- 합계는 서버에서 기간 전체를 계산하고, 개별 기록은 50개씩 조회한다.
- 판매 기록 수정은 날짜·수량만 변경한다. 삭제는 확인 후 수행한다. 기록 시점의 판매가·원가는 고정한다.

## 데이터 보존과 권한

0038은 이름 있는 비용 항목과 가산율을 저장하는 문서 schema 2를 검증한다. extraCost에는 추가 비용 합계를, legacyExtraCost에는 기존 비용을 별도로 저장한다. 따라서 v55는 새 문서를 읽어도 합계가 맞다. v55가 schema 1로 다시 저장해 항목 내역을 지우려 하면 서버가 CHEF_UPGRADE_REQUIRED로 차단한다. 과거 schema 1 버전은 새 앱에서 불러와 schema 2로 저장할 수 있다.

0039는 chef_sales와 판매 기록/기간 합계 RPC를 추가한다. 기록 RPC가 저장된 문서로 원가와 판매가를 계산하여 클라이언트의 임의 가격 입력을 받지 않는다. 예상 수정 번호 검사와 요청 키로 오래된 가격 및 같은 요청의 중복 기록을 방지한다. 날짜는 달력 날짜로 저장하며 시간대 변환으로 하루가 이동하지 않는다.

본인 기록만 읽기·수정·삭제할 수 있다. 클라이언트 직접 INSERT 및 과거 가격/원가 수정은 금지한다. 원본 레시피 삭제 후에도 매출 기록과 요리 이름은 보존하여 전체 집계에서 볼 수 있다. 계정 삭제 시 매출 기록도 함께 삭제된다.

0036 운영 관측 마이그레이션은 별도 보류 상태다. 이번 신규 마이그레이션 적용 시 전체 db push로 무관한 0036을 포함하지 않는다.
