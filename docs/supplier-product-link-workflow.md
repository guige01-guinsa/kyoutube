# 상품 링크로 공급업체 연결

2026-09-20 로컬 구현. 운영 웹서비스에는 아직 배포하지 않았습니다.

## 사용 흐름

1. 구매요청서 작성 화면에서 **상품 링크로 업체 연결·품목 추가**를 선택합니다.
2. HTTPS 상품 페이지 주소를 붙여 넣고 **공급업체 찾기**를 누릅니다.
3. 공개 업체의 등록 홈페이지와 일치하면 업체명과 배송 안내를 확인합니다.
4. **이 업체로 품목 작성**에서 상품명, 규격, 구매 수량·단위를 입력합니다.
5. 품목 확인 후 해당 업체를 내 거래처에 연결합니다. 같은 공개 업체는 기존 거래처를 재사용합니다.
6. 요청서를 저장하면 상품 링크도 저장되며, 화면·공유 텍스트·PDF에 포함됩니다. 요청서 반복 작성 시 링크를 유지하고 기존 단가는 비웁니다.

공급업체가 이미 선택되어 있고 유효한 홈페이지 주소가 있으면 **홈페이지에서 상품 찾기**로 외부 사이트를 열 수 있습니다. 외부 사이트의 상품 선택을 자동 감지하거나 장바구니를 가져오지는 않습니다. 상품명·규격·가격은 자동 추정하지 않고 사용자가 확인합니다.

## 공급업체와 구매 사이트 구분

- 일반 쇼핑몰/공급업체: 홈페이지가 일치하는 공개 업체를 추천합니다. 등록된 거래처가 있으면 재사용합니다.
- 중개몰: 사이트를 실제 공급업체로 자동 등록하지 않습니다. 실제 판매자를 기존 거래처에서 선택하거나 별도 등록해야 품목 작성으로 진행할 수 있습니다. 상품 링크에는 원래 구매 사이트 주소가 남습니다.
- 등록되지 않은 사이트: 사용자가 실제 공급업체를 선택하거나 등록합니다. 사이트 주소만으로 회사명이나 연락처를 만들어 내지 않습니다.
- 여러 업체의 품목: 기존 품목이 있는 요청서에 다른 업체의 링크를 연결하려 하면 별도 요청서를 작성하도록 안내합니다.
- 자주 쓰는 업체: 기존 즐겨찾기와 내 거래처 기능을 유지합니다. 상품 재사용은 기존 요청서 반복 작성 기능을 사용합니다.

## 구현 및 보안

- 일반 회원의 기존 `search_public_supplier_listings`와 `import_public_supplier_listing` RPC를 사용합니다. 관리자 API나 외부 공공데이터 인증키는 필요하지 않습니다.
- 검색 요청에는 상품 URL 전체가 아닌 정규화한 호스트만 전달합니다. 페이지 본문을 서버가 가져오지 않습니다.
- HTTPS, 사용자정보 없는 URL, 기본 포트만 허용합니다. 기존 `shoppingProductUri` 검증을 사용합니다.
- 호스트 전체를 비교하며 `www.`와 `m.` 별칭만 정규화합니다. 임의 하위 도메인, URL 경로, 리디렉션 매개변수, 문자열 접미사로 업체를 판단하지 않습니다.
- 조회 중 URL을 수정하면 이전 결과를 무효화합니다. 계정이 바뀌면 조회·등록 결과를 새 계정의 편집기에 적용하지 않습니다.
- 상품명 입력을 취소하면 공개 업체를 새로 가져오지 않습니다. 사용자가 별도로 누른 실제 공급업체 등록은 기존 거래처 저장 동작입니다.
- `SupplierRequestLine.productUrl`은 선택 필드 `product_url`로 기존 요청서 JSON에 보존합니다. 기존 요청서는 빈 링크로 읽힙니다. 읽을 때 유효하지 않은 링크는 제외합니다.
- DB 스키마·정책·Edge Function 변경이 없습니다. 기존 요청서 전체 크기 제한(128 KiB)은 유지됩니다. 구버전 클라이언트는 새 필드를 모르므로 구버전에서 편집·저장하면 링크가 빠질 수 있습니다.
