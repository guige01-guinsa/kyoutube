갱신: 2026-09-13. 사용자 승인으로 운영 DB 0036·0040, 관측 함수 7개와 관리자 점검 함수, 5분 예약을 적용했고 v57 서명 AAB를 생성했다. Firebase 서버 발송 자격 증명과 실제 관리자 휴대폰 수신은 후속 설정/검증이 필요하다. 최신 실행 결과는 [v57 출시 기록](release-notes-v57-ko.md), 구성은 [관리자 운영 알림](operations-alerts.md)을 참조한다.

구현의 로컬 결과와 환경 경고: [2026-09-12 검증 기록](operations-verification-2026-09-12.md).

## 제공 범위

회원 관리자 → 서비스 운영 현황(`/membership/admin/operations`)에서 다음 항목을 본다. 한국어·영어를 지원한다. 서버가 `profiles.role = admin`을 검사하므로 화면 주소를 알아도 일반 사용자는 집계·비용에 접근할 수 없다.

| 항목 | 계산·해석 |
| --- | --- |
| 서버 요청/실패/거절 | 최근 1·7·30일의 수집된 HTTP 요청. OPTIONS 제외 |
| AI 성공률 | 두 AI 함수의 성공 / (성공+실패). 인증·한도·잘못된 입력 거절 제외 |
| AI P95 | 위 AI 요청의 서버 처리 시간 95백분위. 기기 네트워크 시간 제외 |
| 앱 오류 | 로그인 이후 제한적으로 수집한 오류 분류. 전체 설치 대비 충돌률이 아님 |
| 월 토큰 | 기존 AI 사용 예약 원장의 입력·출력 합계. UTC 월 경계, 성공·실패 모두 포함 |
| 사용량 확인 불가 | 입력·출력이 모두 0인 예약. 무료 요청이라는 뜻이 아님 |
| 미완료 예약 | 15분 초과 reserved 상태. 자동으로 요금이나 회원 한도를 보정하지 않음 |
| 실제 비용 | 공급자 청구 화면의 당월 누적 OpenAI USD·기타 운영 USD를 관리자가 입력 |

비용은 증가분이 아니라 **당월 현재 누적액 전체**를 저장한다. 모르는 금액은 빈칸으로 둔다. 일부 미입력은 총액·잔액을 확인 불가로 표시하며 실제 0과 구분한다. 변경은 `ops_cost_audit`에 관리자·시각과 함께 남는다. 대시보드에는 관리자 ID나 개별 사용자 ID를 표시하지 않는다.

기본 예산 입력값은 기존 정책의 월 USD 700이다. 토큰 단가·환율을 임의 적용하지 않는다. 공급자 청구 API 자동 연동이나 자동 지출 중단은 없다. 앱의 회원별 AI 한도와 운영비 예산은 별도다.

## 주의 표시와 대응

| 조건 | 관리자 대응 |
| --- | --- |
| 치명적 앱 오류 보고 | 영향 버전·재현 조건과 로컬 진단 확인 |
| AI 10건 이상, 성공률 90% 미만 | 실패 분류 및 두 AI 함수의 플랫폼 로그 확인 |
| AI P95 60초 이상 | 공급자 지연·시간 초과·재시도 확인 |
| 15분 초과 미완료 예약 | 함수 종료/사용량 마감 실패 확인, 근거 없이 성공 처리하지 않음 |
| 비용 70%/95% 이상 | 실제 청구 갱신·공급자 예산 설정·회원 정책 검토 |
| 비용 미입력/7일 초과 미갱신 | 공급자 누적액 재확인 |

이 표시는 관리자가 화면을 열었을 때 계산된다. 이메일·푸시·외부 자동 경보는 발송하지 않는다. 운영자는 매일 및 배포 직후 확인하고, 높은 지출 시 청구 기록을 더 자주 갱신한다.

## 수집 방식·한계

`_shared/operations.ts`가 `recipe_api`, `youtube_search`, `youtube_recipe_context`, `ai_recipe_assistant`, `ai_youtube_recipe_assistant`, `membership`, `delete-account`를 감싼다. 고정 분류·HTTP 상태·처리 시간만 저장한다. 백그라운드 저장은 2초 제한이며 실패해도 제품 응답을 유지한다. 안전한 구조화 로그 `ops_request`와 `ops_delivery_failed`가 저장 실패 확인 경로다.

`public_recipe_sync`, Supabase Auth 자체, DB 연결 전 장애, Edge gateway 거절/강제 종료는 이 수집 범위 밖이다. 앱 오류는 초기화·로그인 전, 오프라인, 수집 전 강제 종료 시 누락될 수 있다. 0건은 무장애 증명이 아니다. 플랫폼 로그·상태 및 실기기 검사를 병행한다.

클라이언트는 오류 원문·스택·이메일·URL·레시피·인증 토큰을 보내지 않는다. 고정 source/code, fatal, 빌드 번호만 전달하고 서버가 로그인 사용자 ID를 붙인다. 동일 분류는 1분 중복 억제, 기기에서 1분 최대 10분류, 서버에서 계정당 시간당 20건으로 제한한다. 계정 삭제 시 연결된 클라이언트 이벤트는 삭제된다. 기존 기기 내 진단 원문은 별도 기능이며 중앙 수집에 복사하지 않는다.

## 보관 관리

`purge_ops_events()`는 90일이 지난 이벤트를 한 번에 최대 10,000건 삭제하며 service_role만 실행할 수 있다. **이 마이그레이션만으로 매일 실행 작업이 등록되지는 않는다.** 운영 적용 시 승인된 보안 실행 환경에 아래 스크립트를 매일 등록하고 성공/실패를 확인해야 한다. 비용 스냅샷·감사 이력은 이벤트 정리 대상이 아니다.

```powershell
powershell -ExecutionPolicy Bypass -File tools/ops/purge-telemetry.ps1
```

환경의 `SUPABASE_URL`·`SUPABASE_SERVICE_ROLE_KEY`를 보안 저장소로 공급한다. 명령 인수·로그에 키를 넣지 않는다. 실행 결과가 실패하면 원인을 확인하고 재실행한다. 플랫폼 자체 로그의 보관 기간은 별도 설정을 확인한다.

## 재구성 시 적용 순서 (0036·0040은 운영 적용 완료)

1. 대상 프로젝트와 적용된 마이그레이션을 확인한다. `0031`의 AI 예약 원장이 전제다. 기존 `0032`~`0035`의 적용 여부를 확인하고 임의로 일괄 push하지 않는다.
2. staging에서 새 `0036` 적용, 일반/비로그인 접근 차단·집계·삭제 검증.
3. 승인된 운영 DB에 `0036` 적용 후 위 7개 함수를 배포한다. 함수별 통제된 요청과 이벤트 증가·실패 로그를 확인한다. 유료 AI 호출은 테스트 범위/비용을 확인하고 실행한다.
4. 90일 정리 작업을 등록·첫 실행·실패 감시한다. 수집 안내를 개인정보 공개 페이지 및 실제 배포 범위의 Data safety에 반영한다.
5. 새 미사용 versionCode(v57 이후)로 앱을 빌드·테스트 트랙 검사한다. 기존 v53에는 관리자 화면·중앙 앱 오류 보고가 없다.
6. 일반 계정 차단, 관리자 비용 저장·감사 이력, 한/영 UI·오류 복구를 [UAT](staging-uat-checklist.md)로 확인한다.

조회 실패 화면은 데이터 0으로 대체하지 않는다. 배포 실패 시 원래 제품 응답이 유지되는지 확인하고 필요하면 이전 함수 소스로 복구한다. 신규 DB 테이블을 급히 삭제하거나 운영 데이터를 reset하지 않는다. 이전 앱 버전은 새 테이블 없이도 기존 동작을 유지한다.
