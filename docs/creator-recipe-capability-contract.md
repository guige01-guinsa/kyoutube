# 크리에이터 레시피 상세 기능 계약 (Capability Contract)

## 목적
- 크리에이터 레시피가 상세 화면에서 일관된 사용자 가치를 제공하도록 최소 기능 세트를 고정한다.
- 예외 허용 기준을 명시해, 완결성과 현실적 운영 사이의 균형을 맞춘다.

## 기본 원칙
- 크리에이터 레시피는 원칙적으로 아래 5개 액션을 모두 제공해야 한다.
  1. 바로 요리 시작
  2. AI 요약 생성
  3. 장보기 리스트 만들기
  4. 조리 완료 피드백
  5. 조리 완료 기록

## 예외 허용 정책
- 예외는 가능하지만, 아래 2가지를 반드시 충족해야 한다.
  - 기능 미제공 사유를 사용자에게 명확히 안내
  - 대체 행동(재시도, 편집 보완, 로그인 등)을 즉시 제공

예시
- 요약 없음: AI 요약 생성만 우선 노출, 생성 후 기록 가능
- 재료 비어 있음: 장보기 생성 비활성 + 재료 보완 안내
- 비로그인: 기록/저장 계열 액션 제한 + 로그인 유도

## 상태 모델 제안
- capability_ready: 5개 액션 모두 가능
- capability_partial: 일부 기능만 가능, 사유 표시
- capability_blocked: 핵심 전제(로그인/데이터) 부족

## UX 제안
- 상세 상단 또는 액션 영역에 `기능 상태` 표시
  - 준비됨
  - 일부 제한 (사유 1줄)
- 비활성 버튼은 숨기지 말고 이유를 함께 노출

## 구현 가이드
- 공통 검사기 추가(예: RecipeCapabilityEvaluator)
  - 입력: 레시피 데이터 + 로그인 상태 + 네트워크 상태
  - 출력: 액션별 enabled/disabled + reason
- 상세 화면은 검사기 결과를 그대로 렌더링
- 승격/생성 직후 검사기를 실행해 누락 필드가 있으면 안내

## 테스트 가이드
- 필수 5개 액션 모두 활성 시나리오
- 요약 없음/재료 없음/비로그인/네트워크 오류 시나리오
- 비활성 사유 문구 및 대체 행동 버튼 노출 확인
