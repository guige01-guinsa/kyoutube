# 셰프 단위 선택·사용자 환산 기준·작업 버튼 개선

상태: 2026-09-13 사용자 승인으로 DB 0049 운영 적용과 적용 후 검증 완료. 새 앱 v60(1.0.1+60) 서명 AAB 생성·검증 완료. 기존 v59 AAB는 보존했다. Play 업로드와 휴대폰 업데이트는 아직 실행하지 않았다. [v60 배포 기록](release-v60.md)

## 화면과 사용 방법

- 레시피 상세의 셰프 작업실·장보기 준비를 동등한 색상/크기로 유지하면서 아이콘과 글자를 가로로 배치했다. 최소 높이는 120 → 48 논리 픽셀, 세로 여백은 16 → 10이다. 좁은 화면이나 큰 글씨에서는 두 버튼을 세로로 놓고 텍스트 높이에 맞춰 확장한다.
- 셰프 재료 수정의 사용 단위와 구매 단위, 단가 바로 수정의 구매 단위에 무게·부피·개수·포장 선택을 제공한다. 장보기와 같은 단위 목록을 사용한다.
- 목록에 없으면 ‘필요한 단위 직접 입력’을 누르고 1~20자로 입력한다. 예: 국자, 대접, 인분. 취소하면 기존 자료는 유지한다.
- 자동 환산할 수 없으면 두 단위 사이의 기준 입력 칸이 나타난다. **구매 1단위에 해당하는 사용 단위 수량**을 입력한다. 예: 사용 단위 g, 구매 단위 팩 → 1팩=400g이면 400.
- 기준을 비워 둔 중간 작업도 저장할 수 있다. 이때 원가·판매가는 미완성이며 매출 확정은 차단된다. 숫자를 입력하는 경우 0·음수·무한대·범위 초과를 거절한다.
- 사용 단위나 구매 단위를 바꾸면 기존 환산 기준을 지운다. 같은 숫자를 새로운 단위에 잘못 재사용하지 않는다.
- 재료 카드에 환산 기준 또는 기준 입력 안내를 표시한다. 필요 구매량은 구매 단위로 보여준다. 단위·기준·원가가 작업 저장과 요리 버전에 함께 보존되고 버전 비교에 표시된다.

## 계산 기준

- g ↔ kg, mL ↔ L은 자동 환산한다. 동일한 표준 단위 또는 동일한 직접 입력 단위도 1:1이다.
- 그 외는 재료별 사용자 입력 기준을 사용한다. 컵·국자·팩·봉지의 크기나 무게/부피 사이의 밀도를 임의로 추정하지 않는다.
- 기준값은 양수이며 최대 1,000,000,000이다. 저장 필드는 `purchaseUnitInUsageUnits`이고 단위 조합과 같은 재료 문서에 보관한다.
- 손질 후 300g 사용, 수율 75%, 1팩=400g, 2팩 구매가 6,000원이면 필요 구매량 400g=1팩, 재료비 3,000원이다. 기본 2인분이면 1인분 원가 1,500원, 원가 가산율 50%면 판매가 2,250원이다. 다른 재료와 추가 비용이 없다는 예시다.

## 호환성과 운영 반영

- 저장/계산 검증은 `supabase/migrations/0049_chef_flexible_units.sql`에 추가했다. 기존 마이그레이션·RLS·유료 권한을 변경하지 않는다.
- 기존 g/kg/ml/l/each 코드와 schema 1/2 문서는 계속 읽는다. 새로운 문서에는 `unitFormat: 1`을 넣고 직접 입력 단위는 `custom:` 접두어로 구분한다. 이 접두어는 화면에 표시하지 않는다.
- 구버전 앱은 모르는 단위를 g로 읽을 수 있으므로 새 단위 문서를 저장한 뒤 구버전 앱이 덮어쓰는 요청은 서버가 거절한다. 새 단위 기능을 사용하는 기기는 함께 업데이트해야 한다.
- 운영의 0047·0048은 관리자 MFA 등록 조건 때문에 보류 중이다. 0049 자체는 0046 이후 단위 확장이고 MFA에 의존하지 않는다. 일반 `db push`로 대기 중 마이그레이션을 한꺼번에 적용하지 않는다. 실제 배포 시 적용 대상/이력을 명시하고 관리자 잠금 여부를 확인한다.
- 2026-09-13 사용자가 “DB 0049 운영 적용과 새 서명 AAB 생성을 승인합니다.”라고 명시적으로 승인했다. 해당 범위로 0049만 적용하고 이력을 같은 트랜잭션에 기록했다. 0047·0048은 계속 보류 중이다. Play Console 업로드/배포는 아직 실행하지 않았다.
- 운영 적용 후 소스와 DB 이력 내용 일치, 기존 작업 2건 모두 유효, 예시 원가 1,500원/판매가 2,250원, 기준 누락 시 미완성, RLS 활성화, 익명 저장/내부 RPC 우회 차단을 확인했다. 운영 회원·레시피·매출 테스트 데이터는 생성하지 않았다.

## 검증

- 기존 셰프·작업 버튼 회귀 테스트와 새 단위 왕복 직렬화, 수율 포함 수동 환산, 미입력/0 거절, 버전 비교 테스트.
- 실제 위젯에서 환산값 저장 → 다시 열기 → 직접 입력 단위로 변경 → 기존 기준 초기화 → 새 기준 저장 확인.
- 로컬 DB 트랜잭션에서 0049와 기존 보안 계약을 함께 검증: 사용자 단위 검증, 서버 원가 1,500원/판매가 2,250원 일치, 버전 보존, 구버전 덮어쓰기 거절, 내부 RPC 우회 차단. 실행 후 롤백.
- 한글·영어 390px 위젯 화면을 렌더링하고 직접 확인했다. 카테고리, 직접 입력, 환산 기준, 확인/취소가 잘리거나 겹치지 않는다. 영어 카테고리는 너비에 맞춰 두 줄로 배치된다. 이는 위젯 렌더링이며 휴대폰 설치 검증은 아니다.
- 번역 검사와 환산 편집 화면 검사 4개 통과. 전체 회귀 검사 중 발견한 새 문구의 공용 번역 목록 누락을 수정했다.
- 최종 `flutter analyze --no-pub`: 문제 없음. `flutter test --no-pub`: **224개 통과, 선택적 화면 캡처 4개 건너뜀, 실패 0개**. 한글·영어 단위 화면 캡처는 별도 `UNIT_CAPTURE=true` 실행으로 통과했다.
