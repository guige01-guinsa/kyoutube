# 유료 2,000명·무료 10,000명 운영 비용 검토

2026-09-13. 비교 분석이며 환경/모델/한도 변경은 실행하지 않았다.
실제 공급자 청구액, 현재 Supabase 컴퓨트 등급·초과 사용량은 확인하지 못했다.
아래 ‘현재’는 현재 서비스 구조와 문서의 토큰 가정을 대상 규모에 적용한 시나리오이며 현재 청구서가 아니다.

## 확인 근거

운영 DB 읽기 전용 조회: 무료 gpt-4o-mini 1/일·5/주·10/월,
월간 9,000원 gpt-5.4-mini 10/일·50/주·100/월,
연간 30,000원 gpt-5.4-mini 3/일·15/주·30/월.
홈 한식 10종은 앱 내 카탈로그. 원가·판매가·매출은 AI 없이 Dart/SQL로 계산한다.
확인한 YouTube 검색/메타데이터 서버 경로에는 영속 공유 캐시가 없다.
광고 문구 제거 및 한 차례 초안 보정은 이미 구현되어 있다.
0036 운영 관측 DB는 아직 미적용이며 전역 비용 자동 차단도 없다.

최근 30일 AI 예약 원장에는 52건(성공 25·실패 27)이 있다. 모델/언어/배포 버전 및 테스트 여부를 분리하지 않은 작은 표본으로, 실제 사용자 성공률 또는 영어 개선 후 성공률로 사용할 수 없다.
성공 기록 평균 입력/출력은 무료 989/440, 유료 1,324/1,155토큰으로 문서의 10,000/3,000보다 작다. 따라서 아래 표는 긴 입력에 대비한 예산 계획이며 가장 가능성 높은 실측 전망이라고 볼 수 없다. 실패·보정 비용을 포함한 대표 운영 표본을 수집해 교체해야 한다.

## 공식 단가와 가정

- 무료 모델 입력/출력 100만 토큰당 $0.15/$0.60: [GPT-4o mini](https://developers.openai.com/api/docs/models/gpt-4o-mini).
- 유료 모델 입력/출력 100만 토큰당 $0.75/$4.50: [GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini).
- 현재 문서 가정: 생성당 입력 10,000·출력 3,000 → 무료 $0.0033, 유료 $0.021.
- 개선 목표 예시: 입력 5,000·출력 3,000 유지 → 무료 $0.00255, 유료 $0.01725. 아직 측정된 절감 효과가 아니다. 짧은 입력에 이 가정을 강제로 적용하지 않는다.
- 평균 입력 축소는 조리 근거/수량/온도/시간을 보존하고 한/영 회귀 검증을 통과해야 한다. 출력 제한을 낮추거나 유료 모델을 낮추는 변경은 제안하지 않는다.
- 실패·보정 여유 비용 15%를 양쪽에 동일 적용한다. 이는 성공률 보장이나 최대치가 아니며 실패가 많으면 더 커진다.
- 공통 비AI 운영 예산 $50~120/월: Pro Small~Medium $30~75 + 별도 테스트 Micro $10 + 이메일/도메인/별도 백업·소규모 초과 사용 예비 $10~35. 실제 견적이 아닌 계획값이다. 개발은 로컬을 사용한다.
- 환산 1달러=1,500원은 예산용 가정이며 현재 환율이 아니다. VAT, 환전·결제 수수료, 인건비, 마케팅, 환불, PITR는 아래 기본 합계 제외.

중간 사용은 약 242~252만원 → 199~210만원/월, 약 43만원 절감 목표다.
전원 월간 한도 사용은 약 789~799만원 → 647~657만원/월이다.
일반적인 3,000 출력 가정이므로 절대 상한은 아니다. 기존 입력 10,000/출력 4,000을 적용한 월간 한도 전체 사용은 AI만 $5,490, 실패·보정은 추가다.
유료 구성 혼합 시 최대 유료 생성 수는 월간회원수×100 + 연간회원수×30이다.
평균 사용률이 낮으면 비용은 훨씬 작아진다. 기존 $700 예산으로 2,000명의 월간 최대 사용을 약속할 수 없다.

## 권장 구성과 확장 기준

| 영역 | 권장 | 판단 이유 |
|---|---|---|
| 앱/DB/Auth/Edge | Flutter + Supabase 유지 | 재개발·이전·자체 운영 부담 방지 |
| 컴퓨트 | Pro Small 부하 검증, 지연/연결/CPU 지속 부하 시 Medium | 12,000 계정만으로 인스턴스 크기를 단정하지 않음 |
| 지역 | 현재 지역 유지 후 사용자 지역별 지연 측정 | 지역 변경은 데이터 이전과 점검 비용이 발생 |
| 캐시 | 우선 Postgres의 짧은 TTL 테이블과 앱 캐시 | 새 Redis/별도 서버 없이 시작 |
| 검색 | 검색어+언어+국가+필터+페이지 단위 캐시, 요청 합치기 | YouTube 할당량과 동일 검색 반복 절감 |
| AI | 사용자별 동일 요청 재사용, 고정 지시문 앞부분 정리 | 개인 레시피를 다른 사용자에게 공유하지 않음 |
| 이미지/영상 | 업로드 전 이미지 축소, 기존 CDN; 영상은 YouTube 재생 | 서버가 영상 파일을 저장/중계하지 않음 |
| 매출 | 인덱스/기간 범위/페이지 조회 유지, 규모가 커지면 일 집계 | 매 화면 전체 기록 조회 방지 |
| 알림 | 관리자 알림함+FCM, 상태 변화 시만 발송 | FCM은 무료, 중복 알림과 로그 폭증 방지 |

Supabase Pro 포함량은 MAU 100,000, DB 8GB, 파일 100GB, 일반/캐시 전송 각250GB, Edge 200만 호출이다. 12,000 MAU는 Auth 포함량 안이지만 DB 성능·전송량은 별도다.
Pro $25 + Small $15 - 컴퓨트 크레딧 $10 = 약 $30; Medium이면 약 $75.
일일 DB 백업 7일 보관이 포함된다. 매출 재입력이 어려워 일일 백업의 손실 범위가 허용되지 않으면 PITR 7일 보관 $100/월 추가를 권한다. Storage 파일 자체는 DB 백업에 포함되지 않아 별도 보관·복원 검증이 필요하다.
[Supabase 요금](https://supabase.com/pricing), [DB 백업](https://supabase.com/docs/guides/platform/backups), [Firebase 요금](https://firebase.google.com/pricing).

YouTube 공식 기본 할당량은 search.list 하루100회다. 월12,000명×10검색만 해도 하루평균4,000회라 검색 호출이 평균1회라는 조건에서 캐시97.5%가 없으면 기본 한도를 넘는다. 캐시만으로 해결을 약속하지 않고 사전에 공식 심사·할당량 증설을 준비한다. 추가 페이지와 재시도도 고려해야 한다.
[할당량/심사](https://developers.google.com/youtube/v3/guides/quota_and_compliance_audits).

기존 서비스 구조를 유지한 채 먼저 실제 성공 1건당 비용, 재시도율, 검색 캐시 적중률, DB 저장량 증가, 지연을 2~4주 측정한다. 위 절감값에 캐시 효과를 중복 가산하지 않는다. 관리형 DB를 저가 VM으로 옮기는 방안은 기본료 수십 달러보다 백업·보안 업데이트·장애 복구 부담이 커질 수 있어 현재 권장하지 않는다.
