# 웹 배포 안전장치

버전 번호만으로 판단하지 않고 승인한 Git 커밋 전체 40자와 화면 변경 내용을 확인합니다. 같은 v99 표시가 소스 일치를 보장하지 않습니다.

1. 변경을 커밋하고 검토합니다. 미커밋 변경이나 추적하지 않은 파일이 있으면 배포를 차단합니다.
2. 사용자에게 운영 빌드와 배포 승인을 받은 뒤 `tools/release/build-production-web.ps1 -ExpectedCommit <승인한 커밋>`을 실행합니다. 고정 Flutter와 전체 분석·테스트가 통과해야 빌드합니다.
3. 웹 전체 파일의 SHA-256과 소스 커밋을 기록합니다. `tools/release/deploy-production-web.ps1 -ExpectedCommit <같은 커밋>`으로 배포합니다. 소스 변경이나 빌드 파일 수정·추가·삭제를 차단합니다.
4. 실제 웹의 main.dart.js, index.html, release-info.json과 소스 명세를 내려받아 대조하고 주요 화면도 확인합니다.

기존 빌드에는 새 명세가 없어 새 경로로 배포할 수 없습니다. 정상 운영 웹은 변경하지 않았습니다. 기존 테스트 실패 두 건을 해결하기 전에는 새 운영 빌드가 차단됩니다.

직접 Firebase 명령을 실행하면 저장소 검사를 우회할 수 있습니다. 운영 권한 분리와 GitHub 승인 환경은 별도 계정 설정이 필요하며 이번 변경에는 포함되지 않습니다. 자동 배포를 추가하지 않았습니다.

오래된 최상위 로그만 정리합니다. v99 AAB, 복구 증거, 환경 파일, 프로젝트 설정, 스토어 자료와 공개 페이지는 보존합니다. 삭제 목록과 해시는 집 PC `.artifacts/cleanup-obsolete-logs.json`에 보관합니다.
