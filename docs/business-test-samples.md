# 업소 업무 테스트: 20개 샘플

## 적용 상태

2026-09-19 DB 0047·0063과 운영 웹 v75 반영을 완료했다. Android v75 서명 AAB도 생성했으며 Google Play 업로드·기기 설치는 별도 진행한다. 테스트를 시작하려면 관리자가 기간·참여 범위를 정해 테스트를 열어야 한다.
이번 변경은 실제 회원 이용권을 수정하거나 실제 업소 데이터를 생성·삭제하지 않는다.

## 시작 경로

- 테스터: 업소 공동 업무 → **샘플 20개로 업무 테스트** (`/business-samples`).
- 관리자: 회원 관리자 → 과학 실험 아이콘 **업소 테스트 관리** (`/membership/admin/business-tests`). 관리자 역할과 2단계 인증을 서버에서 확인한다.
- 관리자가 테스트 이름·기간(1~90일)·참여 범위를 지정해 테스트를 연다. 동시에 진행할 수 있는 테스트는 1개다.
- 기본 참여 범위는 **지정한 테스터**다. 로그인 이메일로 등록한다. **모든 회원**을 선택하면 이메일 인증을 마친 모든 회원이 이용할 수 있다. 해제한 계정은 모든 회원 설정에서도 제외된다.
- 테스터는 샘플 시작 버튼으로 자기 연습 공간을 만든다. 비즈니스 이용권이 없어도 그 연습 공간의 공동 업무를 이용할 수 있다. 실제 업소·개인 기능의 유료 권한은 바뀌지 않는다.
- 한 테스트에서 최대 1,000개 연습 공간. 테스터별 시작 재시도는 동일 공간을 반환한다.

## 20개 구성

| 종류 | 개수 | 테스트할 흐름 |
|---|---:|---|
| 레시피 | 5 | 닭고기 채소 덮밥·두부 버섯 조림·소고기 불고기·버섯 비빔밥·감자 된장국, 연구 수정·재료 요청 |
| 식단 | 3 | 위 레시피를 연결한 오늘·내일·모레의 식단 |
| 구매요청 | 5 | 작성 중 2, 승인 대기 1, 승인 완료 1, 입고 확인 1 |
| 원가·판매가 | 3 | 레시피별 비용·판매가 비교 |
| 판매기록 | 4 | 오늘·어제·7일 전·32일 전, 원가 스냅샷과 연결 |

한국어·영어 템플릿은 `tools/data/business_test_samples.json`에 있다. DB 마이그레이션은 독립 실행 가능한 동일 시드 사본을 포함한다. 배포된 마이그레이션은 변경하지 않는다.
모든 업체·가격은 연습 데이터다. 실제 전화번호·사업자등록번호·배송 주소는 포함하지 않는다. AI 호출이나 실제 공급업체 메시지 발송은 하지 않는다.

## 함께 테스트

1. 관리자가 참여할 직원의 계정을 테스트에 포함한다. 각 계정은 이메일 인증을 완료해야 한다.
2. 연습 공간을 만든 사용자가 기존 **직원·권한 관리**에서 직원을 초대한다.
3. 직원은 자기 계정으로 초대 코드를 수락한다. 구매·조리·경영 권한은 실제 업무와 같은 서버 검사를 거친다.
4. 혼자 테스트하면 공간 책임자로 모든 업무를 이용한다. 역할별 제한은 초대한 직원 계정에서 확인한다.

테스터별 자료가 자동으로 공유되지는 않는다. 초대를 통해 공유한 공간만 함께 볼 수 있다. 비참여자는 초대 코드로 연습 공간에 들어갈 수 없다.

## 초기화·종료·삭제

- **샘플 처음으로**: 본인이 소유한 연습 공간의 모든 자료와 변경 이력을 삭제하고 원래 20개를 다시 만든다. 직원·초대는 유지한다. 확인창에서 추가·수정 자료도 삭제됨을 안내한다. 이전 화면에서 중복 초기화하는 경우 세대 번호 검사로 차단한다.
- **테스트 종료**: 서버에서 해당 테스트의 모든 연습 공간 접근·수정·PDF 출력을 차단한다. 종료만 하면 자료는 보관한다. 기간 만료도 접근을 차단하지만 자동으로 자료를 삭제하지는 않는다.
- **종료하고 샘플 삭제 / 샘플 자료 삭제**: 확인창에 공간·자료 수와 삭제 범위를 보여 준다. 해당 테스트에 등록된 연습 공간만 삭제하며, 사용자가 그 안에서 추가·수정한 자료·변경 이력·직원 초대도 포함한다. 실제 업소 공간은 대상이 아니다.
- 삭제 RPC는 50개 공간씩 처리한다. 실패 시 종료 상태를 유지하며 삭제 버튼으로 재시도할 수 있다. 앱에서 계정이 바뀌면 다음 삭제 요청을 중단한다.
- 삭제 후 테스트 설정과 관리 작업 감사 기록은 유지한다. 실제 회원 계정은 삭제하지 않는다.
- 연습 공간 소유자의 테스트 참여를 해제하면 초대한 직원의 해당 공간 접근도 차단한다.

연습용 표시를 문서에서 임의로 지워도 서버가 다시 넣고, PDF에 연습용 표시가 붙는다. 문서 공유는 사용자가 직접 결정하며 자동 발송하지 않는다.

## 검증 명령

```powershell
node tools/test/business_workspaces_contract.cjs --samples
node tools/test/business_workspaces_contract.cjs --samples --docker
.\.fvm\flutter_sdk\bin\flutter.bat test test/features/business/business_samples_test.dart
powershell -ExecutionPolicy Bypass -File tools/dev/verify.ps1
```

DB 검증은 PGlite 또는 로컬 Docker에 생성한 고유 이름의 임시 DB에서 수행한다. 운영 DB·기존 로컬 데이터는 변경하지 않는다. 로컬 fixture만 사용하는 로그인·MFA 모형이며 실제 테스터 계정 로그인 검증을 대신하지 않는다.

## 운영 반영 이후 확인할 사항

관리자 실제 MFA 로그인 → 테스트 열기 → 실제 테스터 등록 → 각각 로그인해 샘플 생성 → 직원 초대·수락 → 역할별 업무 실행 → 종료 → 샘플 삭제 순서를 확인한다. 실제 사람에게 초대나 메시지를 자동으로 보내지 않는다.

## 2026-09-19 검증 결과

- 로컬 PGlite: 기존 업소 권한 회귀 검사를 포함해 114개 통과.
- 로컬 Docker PostgreSQL 17: 관리자별 MFA 검사와 시드 일치 검사까지 119개 통과. 운영 DB 쓰기 0건.
- 최종 `flutter analyze --no-pub`: 문제 없음.
- 최종 업소 기능 및 번역 관련 Flutter 검사: 32개 모두 통과.
- v75 릴리스 전체 Flutter 실행: 478개 통과, 기존 건너뜀 4개. 분석 문제 없음.
- 한국어·영어 390px 화면 이미지 확인. 320px / 글자 크기 200% 화면 테스트 통과.
- 환경 확인: 고정 Flutter 3.44.8·JDK 17 사용. `flutter doctor`는 전역 PATH의 SDK 불일치, Android 라이선스 상태 확인 불가, Windows용 Visual Studio 설치 미완료를 경고했다. 앱 검증 명령은 고정 SDK의 절대 경로로 실행했다. 이후 고정 SDK와 JDK 17을 사용한 v75 서명 AAB 빌드 및 검증이 성공했다.
- 운영 DB 0047·0063 적용, 공개 웹 v75 배포, 서명 AAB 생성 완료. 웹 검사 28개 통과, 브라우저·HTTP 오류 0건. 실제 테스터 로그인 전체 흐름과 Google Play 업로드·기기 설치는 수행하지 않았다. 상세 기록은 [v75 릴리스](release-v75.md)를 참고한다.
