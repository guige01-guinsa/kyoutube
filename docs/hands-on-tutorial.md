## 첫 화면과 이용 방법

역할별 홈 또는 내 정보의 **체험 튜토리얼**을 연다. 일반 사용자, 업소·전문가, 공급업체가 각자의 과정으로 진입하며 튜토리얼 안에서 자유롭게 다른 과정을 볼 수 있다. 과정 전환은 실제 계정의 역할이나 권한을 변경하지 않는다.

처음에는 해당 과정에서 지금 할 만한 **세 실습**을 표시한다. **전체 과정 보기**로 나머지를 펼친다. 업소·전문가는 **구매 업무 6개**와 **조리·경영 8개** 중 선택한다. 최근 미완료 실습이 있으면 이어서 볼 수 있고 순서에 구애받지 않고 선택할 수 있다.

| 과정 | 실습 | 다루는 업무 |
| --- | ---: | --- |
| 업소·전문가 / 구매 | 6 | 구매량, 내 거래처, 재료별 업체 후보, 비교 기준, 요청서·PDF, 대장·재사용 |
| 업소·전문가 / 조리·경영 | 8 | 표준 레시피, 인분, 단위·수율, 원가, 판매가, 매출, 버전, AI 검토 |
| 일반 사용자 | 5 | 검색, AI 초안 검토, 저장, 장보기, 조리 경험 기록과 다음 요리 |
| 공급업체 | 5 | 업체 정보, 상품·사진, 규격·가격, 회원 공개, 정보 갱신 |

총 24개 실습은 한국어·영어에서 같은 내용과 기능을 제공한다. 각 실습은 목표, 결과물, 직접 조작하는 예제, 실제 화면에서 따라 할 단계, 실무 팁, 선택형 확인 문제, 완료 결과로 구성한다.

## 구매 실습의 순서

1. **구매량부터 준비하기** — 구매할 재료를 선택하고 구매 수량·포장을 입력한다. 조리 원문과 구매량을 별도로 관리한다.
2. **내 거래처 만들기** — 공개 업체를 분류·지역·품목으로 찾고 내 거래처에 연결한다. 기존 거래처를 우선 보여 주는 방식을 익힌다.
3. **재료별 업체 후보 고르기** — 각 재료에 1~3곳을 선택한다. 전체 요청의 업체 수를 세 곳으로 제한하는 의미가 아니다.
4. **기준을 골라 요청서 묶기** — 최소 거래처 수, 최저 구매가격, 평점 우선을 비교한다. 선택한 후보의 포장·배송·최소 주문·가격 유효성을 기준으로 검토한다. 미등록 가격은 확정 견적이 아니다.
5. **요청서 검토와 PDF 준비** — 업체별 초안, 구매자·공급자 사업자등록번호와 연결된 비공개 등록증, 납품 희망 조건, 미리보기·저장·인쇄를 익힌다.
6. **전달 후 대장과 재주문** — 공유 수신자 확인, 실제 전달 여부 기록, 구매자가 확인한 수락·입고 상태, 대장 PDF/CSV와 지난 요청 복사를 익힌다.

조리량 환산은 인분·원가 작업에서 사용한다. 장보기·요청서는 사용자가 확인한 구매 단위를 기준으로 한다. 구매 이력을 기록하며 조리에 따라 재고를 자동 차감하지 않는다. 공유창을 여는 것만으로 발송·수락·입고를 완료 처리하지 않는다.

## 예제와 실제 업무 구분

- **예제로 연습**은 가상 자료를 메모리에서 조작한다. 실제 레시피, 장보기, 매출, 업체, 상품, 요청서를 저장하거나 공개하지 않는다. AI 호출, 메시지 발송, 결제도 실행하지 않는다.
- **내 자료로 시작**은 기존 업무 화면으로 이동한다. 그 화면에서 수행하는 저장·공유에는 기존 로그인, 요금제, 서버 검증과 사용자의 실제 자료가 적용된다.
- 공급업체 사진 실습은 가상 이미지 선택을 표현한다. 파일 업로드를 수행하지 않는다. 실제 상품 사진과 사업자등록증은 별도 용도로 안내한다.
- 문서 실습은 가상 업체별 요청서 구성을 보여 준다. 실제 PDF 생성·저장·프린터 선택은 기존 실제 업무 화면에서 제공한다.

구매 예제는 `GuidePurchaseExample`에서 실제 `createProcurementPlan` 계산을 사용한다. 기본 당근·양파·두부 각 1kg에 대해 최소 거래처 A는 16,000원, 최저 가격 B+C는 8,000원, 평점 우선 D는 25,000원이다. 가상 가격·세금 포함·업체별 배송비 포함이며 현재 시장 견적이 아니다. 구매량·후보를 변경하면 계산 결과와 다음 요청서 예제도 바뀐다.

조리 예제는 기존 `ChefRecipe` 계산을 재사용한다. 기준 4인분, 손질 후 800g, 수율 80%, 구매 1kg에 12,000원이다. 20인분 사용량 4,000g, 수율 100%의 원가 계산용 손질 전 분량 800g, 원가 3,000원에 50% 가산한 판매가 4,500원을 확인한다. 매출에서 기록 원가를 뺀 차액을 회계 순이익으로 설명하지 않는다.

## 진도·건너뛰기·다시 보기

예제를 직접 조작하거나 실제 화면 단계의 체크 항목을 모두 확인하면 완료할 수 있다. 확인 문제는 선택 사항이다. 건너뛰기는 완료와 별도로 기록한다. 다시 연습하기는 해당 실습의 학습 상태를 초기화하고, 구매 실습의 공유 가상 자료도 기본값으로 돌린다. 다른 실습의 완료 기록은 유지한다.

`GuideProgress`는 기기별 SharedPreferences에 `guide_curriculum_v3`, `guide_audience_v3`, `guide_track_v3`, `guide_last_v3_<audience>`를 기록한다. 실습 번호·체크·완료 등 학습 상태만 저장하고 입력한 가상 이름이나 실제 업무 자료는 저장하지 않는다. 계정·기기 간 진도 동기화는 제공하지 않는다. 쓰기를 직렬 처리하고 저장 실패는 화면에 표시한다.

v2에서 내용이 유지된 실습의 학습 기록은 이어받는다. 이전 통합 구매 실습 `pro-purchase`의 완료는 새 구매 6개 실습에 옮기지 않는다. 이전 버전 키를 삭제하지 않는다.

## 업무 중 도움말과 복귀

`/guide?audience=professional|home|supplier`는 역할별 과정, `/guide?lesson=<id>`는 해당 실습을 직접 연다. 장보기 준비, 구매·거래처, 업체 비교 단계, 요청서 편집·PDF 미리보기, 대장, 셰프 작업실·매출, 업체·상품 편집에서 문맥별 도움말을 제공한다.

튜토리얼은 루트 라우트로 열어 편집 대화상자 위에서도 볼 수 있다. 뒤로 돌아오면 작성 중인 입력과 기존 업무 화면을 유지한다. 편집·출력 화면에서 저장·업로드·출력 작업 잠금이 적용되는 동안에는 도움말 버튼도 비활성화한다. 튜토리얼에서 실제 업무를 여는 버튼은 기존 경로로 이동하며 권한을 부여하거나 우회하지 않는다.

## 디자인과 검증

짙은 녹색 과정 소개와 대비가 명확한 역할 선택, 세 개 추천 카드, 결과물 카드, 별도 예제 영역을 사용한다. 데스크톱은 최대 1000px 폭에서 추천을 세 열로 배치하고 모바일은 한 열로 읽는다. 고정 높이를 강제하지 않고 큰 글자에서 줄바꿈한다.

검증은 고정 Flutter 3.44.8로 수행한다. 24개 한영 실습의 320px·200% 글자, 세 역할과 두 전문가 과정, v2 진도 이전, 선택형 문제, 건너뛰기와 다시 보기, 실제 비교 계산과 후보 제한, 가상 공개, 요청서 편집 내용 보존을 확인한다. 검토용 실제 위젯 캡처는 `.artifacts/tutorial-v3-*.png`이며 캡처 글꼴은 앱에 추가하지 않는다. 최종 결과는 `.artifacts/verify-tutorial-v3.json`과 `CURRENT_STATUS.md`에 기록한다.

최종 검증: 정적 분석 0건, 전체 416개 통과·기존 조건부 4개 건너뜀, 최종 한영 캡처 검사 2개 통과·화면 16장 생성. 대표 모바일·PC 화면과 구매/공급 예제의 배치·줄바꿈·역할 선택 대비를 육안으로 확인했다. 변경 소스 28개 해시 일치 확인. doctor의 기존 PATH SDK 차이·Android 라이선스 미확인·Visual Studio 구성 경고는 별도 환경 항목이며 이번 Flutter 분석·테스트는 고정 SDK로 통과했다.
