# 레시피 수집과 이름별 레시피 공간

- 일반 사용자와 업소·전문가의 개인 메뉴에서 `/`는 **레시피 수집**이다.
- 개인 메뉴와 레시피 목록 제목은 계정 표시 이름을 사용한다. `display_name`, `full_name`, `name`, `nickname` 순서로 비어 있지 않은 문자열을 찾는다. 이름이 없거나 로그인하지 않은 경우 **개인 레시피**로 표시한다. 이메일/계정 ID는 대신 노출하지 않는다.
- 이름 변경을 반영하며, 계정 전환 중 이전 계정의 이름을 표시하지 않는다.
- 업소의 메뉴·레시피 메뉴는 해당 경로의 실제 업소명으로 **업소명 레시피**를 표시한다. 개인 화면이 업소 이름으로 표시되는 일은 없다.
- 업소 수집 화면은 `/business-workspaces/:workspace?section=collection`이다. 기존 중앙 라우터와 업소 접근 권한 검사를 이용한다.
- 수집 화면에서 검색·영상 수집을 열고 개인 레시피로 저장·검토한다. 업소 수집 화면으로 돌아와 **개인 레시피에서 가져오기**를 선택한다.
- 개인 레시피 선택 후 대상 업소명, 공유 범위, 판매 메뉴와의 구분을 확인해야 사본이 저장된다. 업소의 `recipes.write` 권한과 활성 이용권을 저장 직전에 재확인한다. 개인 원본/사진은 기존 가져오기 API 정책에 따라 그대로 유지된다.
- 가져오기는 기존 `business_import_recipe`를 사용한다. 판매 메뉴에 자동 등록하지 않으며 기존 개발·버전·메뉴 승인 흐름을 유지한다.
- 조회만 가능한 직원도 개인 수집 화면은 열 수 있지만 업소 가져오기 버튼은 제공하지 않는다.
- 긴 이름은 메뉴에서 줄이고 툴팁으로 전체 이름을 표시한다. 목록 제목에는 전체 이름을 사용한다. 여섯 항목의 모바일 메뉴는 선택한 항목의 이름을 표시한다.

이 기능에는 데이터베이스 마이그레이션이 필요하지 않다. 사용자 승인 후 v80 운영 웹 배포와 새 AAB 생성을 완료했다. 최신 검증 결과는 [v80 릴리스 기록](release-v80.md)에 있다.

## 운영 배포 전 개발 검증 기록 (2026-09-23)

- 프로젝트 고정 SDK Flutter 3.44.8로 실행했다. bootstrap 환경 확인을 마쳤다.
- 최종 `flutter analyze --no-pub`: 문제 없음.
- 수집·권한·이름·업무 메뉴 관련 재검증 68개 통과, 디자인·구매 화면을 포함한 앞선 관련 검사 78개 통과. 두 묶음은 중복 테스트를 포함한다.
- `tools/dev/verify.ps1` 전체 검사: 581개 통과, 4개 건너뜀, 2개 실패. 실패 원인은 새 한국어 문구의 번역 등록 누락과 이전 영문 메뉴 이름을 기대하던 테스트였다. 두 원인을 수정한 뒤 해당 파일 전체를 재실행해 15개 모두 통과했다. 수정 후 전체 묶음을 다시 실행하지는 않았다.
- 계정 변경 시 공유 취소, 복사 직전 권한 재검사, 읽기 전용 직원의 개인 수집 접근, 좁은 화면과 큰 글자 표시를 위젯 테스트로 확인했다. 운영 서버에서 실제 복사를 실행하지 않았다.
- 환경 진단에는 전역 SDK PATH 차이, Android 라이선스 상태 확인 불가, Windows용 Visual Studio 구성 미완료가 남아 있다. 이번 검사는 프로젝트 SDK 경로로 실행했다. Android 릴리스 빌드는 검증하지 않았다.
- 운영 배포·AAB 생성·DB 변경은 수행하지 않았다.
