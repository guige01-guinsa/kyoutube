## 사용 흐름

관리자: 회원 관리자 → **공개 업체 자료 관리**. 공급업체 찾기에도 관리자에게만 진입 버튼이 표시된다.

1. `인터넷 검색`에 업체·재료·지역을 입력한다. 공식 사이트를 바탕으로 최대 5곳의 후보를 제시한다.
2. 업체별 홈페이지·출처·취급 품목·배송 조건을 확인한다. 필요한 내용은 `정보 확인·수정`에서 고친다.
3. 저장할 업체를 최대 20곳 선택하고 `선택한 업체 공개 저장`을 누른다.
4. 공개될 내용을 검토하고 확인 체크 후 저장한다. 이때부터 로그인한 무료·유료 회원에게 보인다.
5. `저장한 후보 / 공개 중 / 비공개`에서 검색·수정·공개 중단할 수 있다. 직접 조사한 업체도 입력할 수 있다.

관리자 검색 결과는 자동 저장·공개되지 않는다. 배송 지역이 미확인이면 수정 전 공개할 수 없다.
공개할 때 최근 90일 이내 자료 확인일과 관리자의 출처 확인이 필요하다.
후보로 저장한 정보는 일반 회원에게 보이지 않는다. 날짜가 지났다고 기존 공개 자료가 자동 비공개되지는 않는다.

구매자: 공급업체 찾기 → `공개 자료로 찾은 공급업체` → 조건 확인 → `내 거래처로 선택`.
내 거래처를 해당 목록에서 먼저 표시하며, 구매요청서의 공급업체 선택에도 사용할 수 있다.
공개 업체 추가를 반복해도 개인 거래처가 중복 생성되지 않으며, 개인 메모·즐겨찾기는 보존한다.

## 정보의 의미

공개 자료 기반 업체는 `public_supplier_listings`에 별도로 저장한다.
공급업체 계정을 생성하거나 기존 관리자 계정에 외부 업체 소유권을 부여하지 않는다.
업체가 직접 등록한 상품·사진은 기존 DB0059 경로를 계속 사용한다.

초기 20곳에는 온라인 식자재몰·계약 유통사·중개 플랫폼이 포함되어 각각 표시된다.
`전국`은 모든 상품을 모든 주소로 즉시 배송한다는 뜻이 아니다. 제주·도서 제한, 직배송 전용 상품,
사업자 인증과 계약 상담 등 공식 안내의 예외를 업체별로 함께 표시한다.

가격·평점·사업자 인증·사진은 만들어 넣거나 복사하지 않는다.
따라서 이 자료는 가격/평점/인증/브랜드/원산지/SKU 하위분류 조건으로 검색할 때 제외한다.
재료별 3곳 후보와 최저가·최소 거래처 최적화에는 실제 등록 상품·포장 단위·가격이 있는 기존 상품 데이터만 사용한다.
공개 자료 회사의 일반 취급 품목을 특정 상품의 확정 재고나 견적으로 취급하지 않는다.

## 보안과 운영

- 관리자 검색·수정·일괄 공개 RPC 및 인터넷 검색 함수는 서버에서 관리자 역할과 AAL2를 확인한다.
- 새 관리자 인증 검사는 DB0060에 독립적으로 포함된다. 과거 선택적 MFA 마이그레이션의 적용을 가정하지 않는다.
- 일반 로그인 회원은 공개 행만 읽고, 비로그인·Supabase 익명 세션은 읽지 못한다.
- 홈페이지 도메인(기본 `www` 정규화) 기준 중복 방지. 기존 업체를 덮어쓰지 않는다.
- 인터넷 검색에서도 같은 도메인의 저장된 업체를 찾아 기존 ID·정보·확인일을 표시한다. 이미 공개된 업체는 검색 결과에서 중복 공개 선택하지 못한다.
- 수정 버전 충돌과 일괄 공개 오류는 전체 트랜잭션을 취소한다. 공개/수정/숨김 이력은 관리자 감사 테이블에 기록한다.
- 개인 거래처의 공개 자료 연결 ID는 클라이언트가 위조할 수 없으며, 검증된 import RPC만 설정한다.
- HTTPS 출처만 허용하며 URL 내 자격 증명, 사설 호스트 표기와 IP 리터럴은 거부한다.
- 직접 URL 크롤러는 만들지 않는다. 외부 검색 자료는 명령이 아닌 비신뢰 입력으로 취급하고 화면에는 텍스트로 표시한다.

## 검색 API와 비용 통제

기존 운영 `OPENAI_API_KEY`로 Responses API의 `gpt-5.4-mini`와 웹 검색을 사용한다.
[모델 지원 범위](https://developers.openai.com/api/docs/models/gpt-5.4-mini),
[웹 검색과 출처 메타데이터](https://developers.openai.com/api/docs/guides/tools-web-search)를 확인했다.

관리자 1명당 한국 시간 하루 20회, 전체 하루 50회, 요청 간격 20초.
한 요청의 검색 도구 호출은 최대 2회, 출력은 최대 5,000 토큰, 서버 대기는 60초로 제한한다.
검색 API 비용은 일반 회원 AI 초안 사용량과 별도이며 검색 사용량 테이블에 호출·토큰·결과를 기록한다.
실패한 시도도 횟수 한도에 포함한다. 원문 검색어·회사 자료·API 키는 로그에 남기지 않는다.
검색 결과 저장은 `store:false`이며, 관리자 검토·공개 저장만 DB에 남는다.
제공자의 미완료/출처 없는 응답과 출처에 없는 링크는 공개 후보에서 제외한다.

실제 API 키는 운영 서버에만 보관한다. 모의 공급자 응답과 운영 함수 인증 거부/CORS는 검증했다.
현재 웹이 로그아웃 상태여서 실제 관리자 AAL2 세션으로 유료 인터넷 검색 1회 확인이 남아 있다.
관리자 역할이나 MFA를 우회해 유료 검색을 실행하지 않았다.

## 검증과 배포 순서

검증 결과는 `.artifacts/public-suppliers-*`에 보관한다. 로컬 DB 계약 검사는 스키마와 데이터까지 전부 롤백한다.
운영 DB0060과 초기 데이터는 사용자 승인 후 적용했고, 후속 역할 검증은 읽기 전용 트랜잭션에서 전부 롤백했다.

- `tools/dev/verify.ps1`: 전체 테스트 358개 통과, 기존 선택형 4개 건너뜀, 분석 0건.
- 마지막 도메인 중복 매칭 개선 후 정적 분석 0건, 관련 테스트와 화면 캡처 29개 통과.
- Deno 검색 함수 모의 테스트 9개 및 함수 진입점 타입 검사 통과. 실검색은 미실행.
- 최종 DB 계약 통과: 한국 시간 날짜, 일반/비로그인 권한, 관리자 MFA, 출처 URL, 검색 분류/지역,
  도메인 매칭/중복, 수정 충돌, 일괄 저장 취소, 검색 한도, 개인 거래처 연결과 감사 이력.
- 한글 데스크톱/모바일 및 영어 모바일 캡처를 직접 확인했고 영어 데스크톱도 레이아웃 검사 통과.
- Flutter doctor의 기존 경고 3종(SDK PATH, Android 라이선스, Windows용 Visual Studio 구성)은 남아 있다.
  이번에는 Android 릴리스 빌드를 실행하지 않았다.

적용한 순서:

1. `tools/data/render_public_supplier_seed.py --published`로 20곳 데이터 검증·SQL 생성.
2. `.artifacts/deploy_public_suppliers.py` 기본 모드로 읽기 전용 사전 검사.
3. 승인 범위·파일 해시 확인 후 같은 스크립트의 `--apply`로 DB0060과 20곳을 한 트랜잭션에 적용.
4. `supplier_discovery` 함수 1개 배포. 기존 함수들은 변경하지 않는다.
5. 기존 Firebase 웹 배포 스크립트로 검증·배포.
6. 운영 웹 공개 검사 9개, 한영 공급업체/관리자 경로 로그인 보호 4개를 확인했다.
   DB의 일반 회원 공개 행 조회, 익명 거부, 일반 회원 관리자 접근 거부, 관리자 AAL1 거부/AAL2 조회는
   읽기 전용 역할·JWT 클레임 시뮬레이션으로 확인했다. 실제 브라우저 로그인 검증과 구별한다.
   관리자 AAL2 실검색 및 로그인 후 UI 저장·개인 거래처 추가의 실사용 검증은 남아 있다.
