# 전국 식자재 업체 검색·선택 설계

2026-09-20. 사용자는 특정 지역 30~50곳이 아닌 전국 시·군·구와 품목별 검색을 요청했고, 공공데이터 API 이용 신청을 했다고 답했다. 신청 기관·서비스명·승인 여부는 확인 대기 중이다. 아래는 구현 기준이며 전국 DB 구축이나 운영 반영 완료를 뜻하지 않는다.

## 선택: 공공데이터 동기화 DB와 납품 정보 결합

공식 API/파일 자료를 서버에서 수집해 검색 DB를 유지한다. 구매자는 레시피 스카우트 DB에서 조회하고 선택한다. 외부 서비스 장애·호출 제한이 구매요청서 작성을 직접 막지 않게 한다. 운영자는 최초 적재 및 변경분 동기화 상태, 제공기관 기준일, 지역별 수집 건수를 확인한다.

전국은 검색 대상 범위다. 인허가 자료에 없는 업체까지 포함한 모든 식자재 업체의 완전한 명부라고 표시하지 않는다. 미수집 지역과 검색 결과가 없는 지역을 구분한다. 인허가 업종만으로 특정 재료의 판매·재고·배송을 확정하지 않는다.

## 확인한 공식 자료

- 식품안전나라 인허가 업소 정보 I2500: 인허가번호, 업종, 업체명, 허가일자, 주소 등. 이름/업종/인허가번호/변경일자 요청 조건을 제공한다. 시·군·구 검색은 수집 후 내부 인덱스로 지원해야 한다.
  https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_grp=MENU_GRP31&menu_no=656&show_cnt=10&start_idx=1&svc_no=I2500&svc_type_cd=API_TYPE06
- 2026-09-20 인증키 없는 공식 I2500 sample HTTPS 호출: HTTP 200, INFO-000, 5행 응답 확인. 실제 신청 키의 승인·쿼터·전국 전체 수집 가능 여부는 검증하지 않았다.
- 식품제조가공업정보 I1220은 제조업 한 종류이므로 단독 사용으로 전국 식자재 유통·판매업을 포괄하지 않는다.
  https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_grp=MENU_GRP31&menu_no=656&show_cnt=10&start_idx=1&svc_no=I1220&svc_type_cd=API_TYPE06
- 행정안전부 식품판매업(기타) 조회서비스는 전국 지자체 인허가·영업상태·소재지 자료를 제공한다. 실제 신청 서비스에 따라 집단급식소식품판매업, 유통전문판매업, 축산물 판매 관련 자료 등을 추가 대조한다. 일반 마트·제조업·급식 납품업을 한 종류로 취급하지 않는다.
  https://www.data.go.kr/data/15155170/openapi.do
- 식품안전나라에는 2026년 7월 제한 운영 및 8월 개인정보 항목 변경 공지가 있으므로 수집 주기·이용 조건은 실제 승인 서비스 기준으로 확인한다.
  https://www.foodsafetykorea.go.kr/api/main.do

## 기존 기능에서 확장할 지점

현재 `public_supplier_listings`는 홈페이지 도메인 기준 중복 방지, 운영자 확인, 시·도 단위 배송지역, 취급 품목을 전제로 한다. `SupplierDirectoryPage`에서 선택하면 기존 구매요청서로 업체가 전달된다. 이 흐름은 유지한다.

인허가 업소에는 홈페이지가 없을 수 있고 동일 업체가 여러 인허가/사업장을 가질 수 있으므로 현재 공개 업체 테이블에 무리하게 끼워 넣지 않는다. 원본 인허가와 실제 납품 업체의 연결을 별도로 둔다. 같은 이름이나 홈페이지만으로 서로 다른 사업장을 합치지 않는다.

현재 가격·평점·인증 등 상품 조건은 공개 자료 업체를 검색에서 제외한다. 전국 업체 선택에서는 기본 조건을 업체명/업종/소재지/확인된 품목으로 단순화하고, 상품·가격 비교 기능은 별도로 유지한다.

## 데이터 구조

| 자료 | 주요 필드와 관리 원칙 |
| --- | --- |
| 공식 인허가 원본 정규화 | 제공기관, 서비스 ID, 원본 식별자, 인허가번호, 업체명, 업종, 공개 주소, 영업상태, 원본 기준일, 수집일, 출처 |
| 지역 검색 | 시·도 및 시·군·구 공식 코드·이름·변경 이력. 시 아래 일반구를 보존하며 주소가 불완전하면 미분류로 둔다. 주소에서 위치를 추측하지 않는다. |
| 납품 업체 정보 | 기존 등록 업체/운영자 검토 업체와 연결, 확인된 품목, 실제 배송지역, 주문 마감, 최소 주문, 공개 대표 연락처, 확인일 |
| 개인·사업장 거래처 | 선택한 업체, 즐겨찾기, 최근 선택, 내부 담당자·협의단가·메모. 소유자/사업장 권한으로 분리 |
| 수집 작업 | 서비스별 체크포인트, 성공·실패, 처리 건수, 마지막 성공일, 원본 지문. API 키·키가 포함된 요청 URL은 기록 금지 |

소재지는 업체의 위치이고 배송지역은 거래 조건이다. 둘을 같은 값으로 자동 채우지 않는다. 제품 인허가·제조 품목과 실제 도매 판매 재고도 구분한다. 개인정보 제공이 제한된 대표자명·연락처를 다른 자료로 무리하게 복원하지 않는다.

## 구매자 화면

1. 구매요청서 → 업체 선택. 내 거래처/최근 선택을 먼저 표시하고 전국 업체 검색으로 전환한다.
2. 시·도 → 시·군·구, 업체명·업종, 확인된 취급 품목으로 검색한다. 소재지 기준인지 배송 가능 지역 기준인지 표시한다.
3. 결과 카드에 업체명, 소재지, 업종, 확인된 품목, 배송 조건의 확인 여부, 자료 출처와 기준일을 보여 준다. 인허가 자료라는 이유만으로 추천/사업자 인증 배지를 붙이지 않는다.
4. 업체 확인 → 이 업체 선택. 작성 중인 요청서·품목·수량을 보존하고 해당 업체를 내 거래처에 연결한다. 선택은 주문·계약·메시지 발송을 실행하지 않는다.
5. 품목이 미확인인 인허가 후보를 별도로 볼 수 있게 하여 검색 결과가 없다는 의미와 취급 품목을 모른다는 의미를 구분한다.

위치 좌표가 없거나 상세 주소가 비공개이면 정확한 거리순·지도 핀을 표시하지 않는다. 초기에는 시·군·구 목록 중심 검색으로 제공한다.

## 적재·갱신 절차

1. 신청한 서비스·승인·필드·이용 조건을 확인한다. 서버 비밀 저장소에 키를 설정하며 앱/웹 번들 또는 채팅에 넣지 않는다.
2. 소량 읽기 요청으로 승인, 누락 필드, 주소 수준, 영업상태 코드, 응답 오류와 호출 한도를 검증한다.
3. 공식 전체 파일이 제공되면 초기 적재에 이용하고, 이후 승인된 API 변경분으로 갱신한다. 페이지당 상한·일/시간 한도와 제공기관 운영 시간을 지킨다.
4. 원본 식별자 기반 멱등 upsert, 중복·폐업·주소 미분류·품목 미확인 통계를 만든다. 변경분 실패나 단순 누락을 폐업으로 해석하지 않는다. 개인정보 제공 범위가 축소되면 예전 값을 계속 공개하지 않도록 정리한다.
5. 스테이징에서 지역별 수집 범위와 품질을 확인한 뒤 검색용 버전을 교체한다. 중간 실패는 마지막 정상 버전을 보존하고 기준일을 표시한다.
6. 저장된 개인 메모와 협의단가는 동기화로 덮어쓰지 않는다. 폐업 상태가 확인되면 새 선택을 차단하되 과거 요청서 기록은 보존한다.

갱신 예약은 서버 운영 작업으로 구현할 대상이다. 이 문서 작성만으로 예약·자동화·운영 쓰기가 생성되지 않는다.

## 구현 검증 기준과 선행 조건

- 대표 시·도, 군 지역, 시 아래 구, 세종, 제주, 주소 미분류 및 구 행정명칭을 포함한 지역 처리 검사.
- 중복 인허가/다수 사업장, 변경분 재실행, 폐업·재개업, 누락·잘못된 응답, 장애 복구 검사.
- 다른 사용자 거래처·메모 접근 차단, 일반 사용자의 수집/수정 금지, 관리자 MFA, 키 로그 노출 방지 검사.
- 실제 전국 규모 자료로 검색 지연·페이지 중복·인덱스 실행계획 검사. 성능 수치를 측정 전 약속하지 않는다.
- 요청서 선택 후 품목·수량·작성 내용 보존, 한영·모바일·큰 글씨 검사.

현재 대기: 신청 기관·서비스명과 승인 상태. 실제 전국 데이터를 읽고 운영 DB에 반영하려면 안전한 서버 키 설정과 배포 범위 확정이 필요하다. 기존 `AGENTS.md`의 운영 마이그레이션·배포 승인 규칙을 따른다.
