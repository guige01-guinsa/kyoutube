# 장보기 도우미 + 구매처 연결

2026-09-13. v62 출시 기능으로 운영 DB 적용을 완료했습니다. AAB 생성·검증 상태는 [v62 출시 기록](release-v62.md)을 참고합니다. 기존 v61 설치본에는 포함되지 않습니다.

## 이용 흐름

장보기 목록 상단의 ‘장보기 도우미 · 구매처 찾기’ 또는 각 목록의 구매처 찾기를 엽니다.
구매 준비 / 구매 기록 / 자주 사는 상품의 세 탭을 제공합니다. 한국어와 영어를 지원합니다.

- 모든 활성 목록 또는 한 목록에서 아직 구매하지 않은 재료를 확인합니다.
- 이름의 앞뒤 공백과 대소문자를 정리한 정확한 이름만 합칩니다. g/kg, mL/L, ea를 합산하며 다른 단위·포장·검토 전 항목은 분리합니다. 비슷한 재료명이나 밀도·컵 용량을 추정하지 않습니다.
- 네이버 쇼핑(한국) 또는 Google 웹 검색을 선택하거나, 별표로 저장한 상품 링크를 외부 브라우저/앱에서 엽니다. 한국어/영어 기본 검색처가 달라도 사용자가 직접 바꿀 수 있습니다. 배송 가능 지역은 판매처에서 확인합니다.
- 링크 열기는 구매 상태를 변경하지 않습니다. 결제·배송·환불은 외부 판매처에서 진행합니다. 상품 가격, 배송비, 재고, 결제 성공 여부를 자동 조회하지 않습니다.
- 구매 확인에서 실제 보유량을 직접 입력하면 추가 필요량과 포장 수를 계산합니다. 앱 재고 기록은 참고만 표시합니다. 다른 장보기에 이미 사용할 재고나 다른 크기의 포장을 중복 반영하지 않도록 사용자가 확인합니다.
- 실제 구매 수량, 선택적인 해당 재료의 결제 금액, 통화를 확인한 뒤 기록합니다. 실제 배송 상품은 수령 후 기록을 권합니다.
- 실제 구매량은 관련 목록에 배분하고 원래 조리 문구는 보존합니다. 재고는 기존 방식으로 각 목록의 ‘장보기 완료’ 때만 반영합니다. 실제 구매 0은 건너뜀입니다.
- 기록 전 목록별 배분량을 미리 표시합니다. 필요량보다 적게 구매하면 부족분을 이번 목록에서 제외한다는 추가 확인이 필요합니다. 부족분을 새 항목으로 자동 생성하지는 않습니다.
- 구매 기록에서 결제 금액/통화를 수정할 수 있습니다. 수량은 확인 당시 기록이며, 이후 목록 수량 변경으로 기록/원가가 자동 변경되지는 않습니다.
- 유료 회원은 셰프 작업실의 재료 수정 / 단가 바로 수정에서 동일 재료명·동일 통화의 구매 기록을 선택할 수 있습니다. 편집 중인 원가에 불러온 후 확인과 작업 저장을 거칩니다. 수량·수율은 보존하고 수동 포장 환산 기준은 다시 입력합니다. 기존 유료 권한과 서버의 저장 검사는 유지됩니다.

일반 구매 기록과 구매처 연결은 로그인 회원에게 제공합니다. 전문 원가·매출 기능의 유료 제한은 유지합니다.

## 운영 구성

새 AI 호출, 상품 API 키, 판매자 센터, 결제대행 계약, 추가 Edge Function, 별도 서버가 필요하지 않습니다.
기존 Supabase에 아래 두 테이블과 구매 기록용 RPC를 추가하는 DB 0051을 운영 적용했습니다.

- `shopping_product_favorites`: 계정별 최대 200개. 재료명·단위당 한 상품. 사용자 본인의 읽기/수정/삭제만 허용합니다.
- `shopping_purchase_records`: 확인 당시 수량·금액·날짜·대상 목록 기록. 최근 100건을 화면에 표시하고, 셰프 불러오기는 재료명으로 검색한 최근 100건에서 같은 통화를 고릅니다.
- `record_shopping_purchase`: 로그인 필수, 사용자 소유의 활성 목록·미처리 항목만 처리. 목록/항목 잠금, 기대 revision 확인, 합계 검증, 원자적 상태 변경+기록, 요청 키 재사용 검증을 수행합니다.

응답 불확실 시 같은 내용으로 재시도합니다. 앱 재시작 이후에도 같은 요청 키를 사용하도록 사용자별 로컬 저장을 이용합니다. 성공을 확인하면 로컬 키를 정리합니다. 계정 변경 시 화면 캐시와 개인 편집 대화상자를 분리합니다.

기존 수량 열의 `numeric(12,2)` 정밀도에 맞춰 구매/배분량을 소수점 두 자리로 기록합니다. 한 번의 공동 구매는 최대 100개 원본 항목입니다. 더 많으면 그룹을 나눕니다. 최대 수량은 10억, 금액은 1조, 통화는 KRW/USD입니다. 금액 미입력은 0원과 구분합니다.

재고 열은 `numeric(18,6)`으로 확장합니다. 예를 들어 재고 0.5kg에 구매 1.23g을 합칠 때 0.50123kg을 보존합니다. 구매 목록 자체의 두 자리 정밀도는 유지하며, g/kg·mL/L 환산 중 손실을 막기 위한 변경입니다.

저장 URL은 공개 HTTPS 링크만 앱에서 허용하고 외부 앱으로 엽니다. 서버가 사용자 URL을 가져오거나 계정 토큰을 전달하지 않습니다. 링크와 구매 기록은 계정 삭제 시 함께 삭제됩니다. 즐겨찾기나 기록을 공개하는 정책은 없습니다.

## 적용/검증

- 마이그레이션: `supabase/migrations/0051_shopping_assistant.sql` (운영 적용 완료)
- 앱 버전 `1.0.1+62`. 서명 AAB 및 출시 검증은 [v62 출시 기록](release-v62.md)을 따릅니다.
- 승인받은 0051·0052·0053을 한 트랜잭션으로 적용했습니다. 보류 중인 0047·0048은 적용하지 않았습니다.
- 로컬 SQL 검증: `tools/test/run_shopping_assistant_contract.ps1`. 로컬 DB의 0035 기준에서 0036~0051을 단일 트랜잭션에 올리고 계약 테스트 후 롤백합니다. 운영 DB/계정/결제에는 접근하지 않습니다.
- Flutter 3.44.8 검증: analyze 오류 없음. 전체 테스트 248개 통과, 기존 4개 건너뜀. 신규 도메인·재시도·계정 전환·구매 확인 화면과 기존 셰프 편집을 포함합니다.
- 로컬 SQL 계약 테스트 통과: 사용자 격리, 금액만 수정 허용, 중복 요청/오래된 목록 거부, 원자적 기록, 목록 완료 시 재고 반영, 0.50123kg 정밀도 보존. 테스트 변경은 전부 롤백했습니다.
- 한국어/영어 화면은 360×800, 글자 배율 1.15의 Flutter 위젯 테스트로 검증합니다. `.artifacts/shopping-assistant-ko.png`와 `shopping-assistant-en.png`는 테스트 자료로 만든 화면 미리보기이며 휴대폰 촬영본이 아닙니다.
- 개발 환경 점검에는 `.env.local` 없음, 전역 SDK PATH 경고, Android 라이선스 상태 미확인, Windows 데스크톱 빌드 구성요소 부족이 남아 있습니다. 검증에는 고정된 로컬 Flutter SDK를 사용했으며 릴리스 빌드 전 Android 환경을 별도 확인해야 합니다.
- 실제 외부 판매처 결제, 운영 DB 동작, 실기기 설치는 이 구현 검증 범위에 포함되지 않습니다.
- `docs/privacy-policy.md`와 `docs/google-play-data-safety.md`의 새 수집 내용을 출시 전 공개 정책/신고에 반영해야 합니다. 해당 문서는 초안이며 공개 사이트를 게시하지 않았습니다.

## 이후 확장 판단

협력업체 구매 요청서는 [구매 요청서](supplier-purchase-requests.md), 사용자 구매처 관리는 [내 구매처 관리](shopping-store-management.md)를 참고합니다. 관련 DB 0051·0052·0053은 운영 적용을 완료했습니다.

상품 링크 사용성, 반복 구매, 운영 문의량을 확인한 뒤 제휴 판매처 한 곳과의 장바구니 연동을 검토합니다. 자동 결제, 실시간 가격 비교, 판매자 입점·정산은 현재 구현 범위에 포함하지 않습니다.
