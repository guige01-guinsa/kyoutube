# 구매 흐름과 역할별 메뉴 간소화

2026-09-17 · 사용자 승인으로 운영 웹 배포·v70 서명 AAB 생성 완료. [릴리스 검증과 산출물](release-v70.md).

## 메뉴

| 이용 목적 | 주요 메뉴 |
|---|---|
| 일반 사용자 | 검색 / 내 레시피 / 장보기 / 내 정보 |
| 업소·전문가 | 홈 / 구매 / 거래처 / 셰프 / 내 정보 |
| 식자재 공급업체 | 홈 / 업체·상품 / 내 정보 |

휴대폰 하단과 넓은 웹의 왼쪽 메뉴가 같은 목적지와 순서를 사용한다. 일반 사용자는 첫 목적 선택 후 검색에서 시작한다. 계정·구독·목적 관리·튜토리얼과 다른 도구는 내 정보에 모았다. 공급업체 찾기는 내 정보와 업체 홈에서 계속 접근할 수 있다. 공급자 수신함은 아직 없는 기능이므로 메뉴에 표시하지 않는다.

## 구매에서 시작

- `/purchases`가 구매 업무의 진입점이다. 기존 `/supplier-requests` 주소도 같은 화면으로 연결한다.
- 준비 중(초안) / 진행 중(전달·수락 확인) / 완료(입고 확인·취소)를 구분한다. 상태는 구매자가 직접 확인해 기록하며 공급자가 앱에서 응답했다는 뜻으로 표시하지 않는다.
- 업체·재료·요청번호 검색, 기존 대장·기간 검색·집계·PDF/CSV 출력에 바로 접근한다. 최근 요청은 기본 50개씩 최대 1,000개를 불러오며 전체 기간 조회는 대장으로 연결한다. 검색 범위가 불러온 요청임을 더 보기 영역에 안내한다.
- 새 구매요청은 장보기 재료 / 이전 요청 복제 / 직접 작성 중 선택한다. 거래처에서 직접 요청하면 후보 업체 비교 단계를 거치지 않는다.
- 업소 홈은 이어서 작성 / 확인할 일 / 지난 요청 다시 만들기를 먼저 보여 준다. 요청을 누르면 요청번호로 본인 자료 1건을 조회해 바로 연다. 목록의 첫 50건 밖에 있는 요청도 조회한다. 계정 변경·삭제·접근 불가를 검사한다.

## 재료부터 요청서까지

1. 장보기에서 구매할 재료와 구매 수량·단위를 선택한다.
2. 재료별 후보 업체를 1~3곳 선택한 뒤 최소 거래처 수 / 최저 구매가격 / 평점 우선 중 하나를 고른다. 원래의 내 거래처 우선 표시·견적 필요·구매 단위 환산·서버 가격 재확인 규칙을 유지한다.
3. 업체별 초안을 검토하고 업체·품목·납품 정보 등을 수정한다.
4. 사용자가 저장한 뒤 미리보기·PDF·공유를 실행한다. 공유창 열기·텍스트 복사·PDF 생성만으로 전달 또는 수락 상태를 바꾸지 않는다.

이전 단계로 돌아갈 때 선택한 재료와 후보·기준을 유지한다. 화면을 나갔다 돌아오면 같은 앱 실행 중의 비교 작업을 이어간다. 장보기 원본이 달라진 경우에는 현재 장보기로 새 비교를 시작한다. 저장된 요청을 다시 미리 볼 때 서버의 최신 상태를 확인한다.

업소의 장보기 목록에는 ‘이 목록으로 구매요청’을 추가했다. 셰프 작업실에는 작업 저장 후 원본 레시피의 장보기 준비로 이동하는 버튼을 제공한다. 셰프의 조리량·원가는 구매 수량으로 자동 확정하지 않는다. 구매 수량은 장보기 준비에서 사용자가 따로 정한다.

## 중간 저장과 계정 분리

- 편집기의 ‘나중에 계속’과 뒤로가기는 미완성 요청을 현재 앱의 메모리에 보관한다. 구매의 준비 중에서 다시 열 수 있다.
- 이 보관은 앱 종료·웹 새로고침·다른 기기까지 유지하는 저장이 아니다. 화면에서 서버 저장을 안내한다. 서버 저장은 기존 입력 검증과 요금제 한도를 유지한다.
- 저장 성공 시 임시본을 지우고, 저장 결과가 불확실하면 동일 요청 ID와 전송 내용을 보관하여 중복 생성을 방지한다.
- ‘변경 버리기’는 확인 후 편집 변경만 버리며 서버의 기존 요청서를 삭제하지 않는다. 임시 보관한 첨부 파일은 이어쓰기 동안 보존한다.
- 계정이 바뀌면 요청 편집과 업체 비교의 메모리 상태를 비운다. 저장 중에는 이탈을 막고, 비동기 조회 이후에도 계정을 재확인한다.

## 범위

기존 권한·요금제·구매 단위와 조리 단위 분리·조리 재고 제외 원칙을 유지한다. DB 마이그레이션, Edge Function 변경, 공급자 수신·견적 승인·배송 추적·정산은 이번 메뉴 개편에 포함하지 않는다. 사용자나 공급자에게 메시지를 발송하지 않았다.

## 검증

고정 Flutter 3.44.8과 JDK 17로 필수 `tools/dev/verify.ps1` 실행을 완료했다. 정적 분석 0건, 전체 테스트 **405개 통과·기존 조건부 4개 건너뜀·실패 0개**, 종료 코드 0. 검사 도중 최종 소스를 수정하지 않았으며 검증 JSON에 소스 해시를 기록했다.

- `.artifacts/purchase-navigation-verified.log`: 최종 필수 doctor/analyze/test 통과 로그.
- `.artifacts/verify-purchase-navigation.json`: 실행 결과·소스 해시·배포 범위 기록.
- 기존 doctor 환경 경고(PATH의 다른 SDK, Android 라이선스 확인, Visual Studio 구성)는 남아 있다. 검사는 고정 SDK와 JDK 17로 통과했다.
- `.artifacts/purchase-navigation-recheck.log`: 구매처 후보 선택 후 이전 단계 복귀·다시 진행·저장과 200% 글씨의 바로가기 검사 18개 통과. 이전 `targeted*`·`verify-final` 로그는 보완 과정 기록이며 최종 결과는 위 `verified` 로그를 기준으로 한다.
- `.artifacts/purchase-navigation/`: 실제 위젯을 렌더링한 한글·영문 휴대폰/웹 화면. 업체와 요청서는 테스트 자료다.
- 새 회귀 검사: 계정 변경 시 초안 제거, 불완전 초안 닫기·복구·버리기, 첫 페이지 밖 요청 직접 열기, 상태별 검색, 역할별 메뉴와 관련 화면의 선택 표시.
