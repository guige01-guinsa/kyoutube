# 역할별 첫 화면과 메뉴 개편

2026-09-16 · 운영 웹 및 v69 서명 AAB 반영 완료 · [배포 기록](release-v69.md)

사용자 결정: 기존 레시피·장보기·셰프·구매요청·업체등록 기능으로 역할별 화면을 먼저 정리한다. 개인용·업소용 자료는 이번에 분리하지 않고 같은 계정의 기존 자료를 함께 사용한다.

> 이후 v70 운영 반영 메뉴 간소화: [구매 흐름 개편](purchase-navigation.md). 아래 표는 운영 v69 배포 시점 기록이다.

## 화면과 메뉴

| 이용 목적 | 주요 메뉴 | 첫 화면에서 먼저 보는 내용 |
|---|---|---|
| 일반 사용자 | 홈 / 검색 / 내 레시피 / 장보기 / 전체 메뉴 | 최근 내 레시피, 요리 검색과 장보기, 일반 사용자 튜토리얼 |
| 업소·전문가 | 홈 / 요청하기 / 거래처 / 셰프 / 전체 메뉴 | 최근 구매요청과 기록된 상태, 장보기·구매요청 대장·원가·매출 도구 |
| 식자재 공급업체 | 홈 / 업체·상품 / 공급업체 찾기 / 전체 메뉴 | 업체 공개 상태와 등록 상품 수, 업체·상품 등록 3단계 안내 |

- 이메일 가입 시 이용 목적 1개를 선택한다. 기존 회원·소셜 로그인 사용자는 아직 설정이 없으면 첫 홈에서 선택한다.
- 첫 홈과 `전체 메뉴 → 이용 목적 관리`, `내 계정 → 이용 목적 관리`에서 목적을 여러 개 선택하거나 바꿀 수 있다.
- 여러 목적을 선택한 사용자에게만 역할 전환 메뉴가 표시된다. 선택한 목적이 1개이면 목적 관리로 연결한다.
- 휴대폰은 4~5개 하단 메뉴, 넓은 웹 화면은 역할별 왼쪽 메뉴를 사용한다. 큰 글씨에서는 휴대폰 구성을 사용한다.
- 모든 기존 도구는 전체 메뉴의 주요 도구/다른 도구에서 접근 가능하다. 유료 기능과 관리자 기능은 기존 권한 검사를 따른다.
- 최근 구매요청을 선택하면 구매요청 목록으로 이동한다. 기존 요청의 복사·편집·PDF·공유 절차를 계속 사용한다.
- 공급업체 등록은 기존 공개하기 절차를 유지하며, 공개한 업체 정보는 로그인한 회원에게 표시된다.

## 데이터와 저장

회원 설정은 기존 Supabase 사용자 메타데이터 `scout_workspace_v1`에 저장한다. 앱/웹에서 같은 계정으로 접속할 때 설정을 불러온다. 계정 시작 시 최신 설정을 조회하며 통신 실패 시 해당 계정에 캐시된 설정을 사용한다. 다른 기기의 변경을 즉시 실시간 전달하는 기능은 아니다.

비회원 설정은 기기의 로컬 저장소에만 보관하고 로그인한 계정에 자동 이관하지 않는다. 계정 변경 시 이전 계정의 비동기 저장 결과가 새 계정 화면에 적용되지 않도록 검사한다. 역할은 화면 선택값이며 DB 권한·회원 등급·구독을 부여하지 않는다.

레시피, 장보기, 거래처, 구매요청 자료는 같은 계정 안에서 공유한다. 개인/업소별 자료 분리, 앱 내 결제, 배송 추적, 반품·정산, 공급업체 주문 수신은 이번 범위에 포함하지 않는다. 조리로 인한 재고 차감도 추가하지 않는다.

## 검증과 배포

- 고정 Flutter 3.44.8·JDK 17로 `tools/dev/verify.ps1` 실행 완료. 정적 분석 0건, 전체 테스트 **395개 통과·기존 조건부 4개 건너뜀**, 실패 0개.
- 역할별 개편 22개 새 검사: 설정 형식 검증, 비회원/회원 설정 분리, 계정 변경 중 저장 보호, 저장 실패와 재시도, 첫 선택과 재진입, 편집 중 전환 취소, 기존 메뉴 접근, 로그인 업소의 최근 요청, 저장 중 하단 메뉴 차단을 포함한다.
- 한글/영문 × 세 목적 × 휴대폰 390px/웹 1440px 화면을 렌더링했다. 320px·글자 크기 200%와 여러 목적의 영문 전환 메뉴를 검사했다. 미리보기는 위젯 테스트와 예시 자료를 사용했다.
- 별도 관련 회귀 검사 32개 통과. 신규 첫 화면에 맞춰 기존 검색·방문자 메뉴 검사를 갱신하고, OAuth 계약 검사는 Windows 줄바꿈과 무관하게 기존 보안 조건을 검사하도록 정리했다.
- 검증 기록: [소스 해시·검증 범위](../.artifacts/verify-role-workspaces.json). [업소 홈 예시](../.artifacts/role-workspaces/professional-ko-1440-signed-in.png) · [일반 사용자 휴대폰](../.artifacts/role-workspaces/personal-ko-390.png) · [공급업체 휴대폰](../.artifacts/role-workspaces/supplier-ko-390.png).
- Flutter doctor에는 전역 PATH의 다른 Flutter, Android 라이선스 상태 미확인, Windows Visual Studio 구성 미완료 경고가 남아 있다. 검사는 고정 SDK를 직접 호출했다. 실제 계정의 앱/웹 간 설정 동기화와 휴대폰 실기기 검증은 이번 로컬 검사에 포함하지 않았다.
