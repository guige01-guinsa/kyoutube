# 쿠팡 파트너스 API 연동

2026-09-26 개발 변경. 운영 DB·Edge Function·앱·웹 배포는 수행하지 않았습니다.

## 사용 흐름

관리자 로그인 및 2단계 인증 → 회원 관리자 → 제휴 상품 관리 → **쿠팡 상품 검색·링크 생성**.

- 재료·상품 검색어를 입력하고 검색하면 최대 10개 상품명과 조회 당시 가격을 표시합니다. **링크 생성 후 검토**를 누르면 쿠팡이 발급한 링크, 상품명, 검색한 재료 별칭이 기존 편집기에 채워집니다.
- 상품을 이미 골랐다면 `https://www.coupang.com/vp/products/…` 상세 주소를 붙여 넣고 **주소로 제휴 링크 생성**을 누릅니다. `itemId`·`vendorItemId`를 포함한 원문 주소를 서버로 전달합니다. 이 방식은 편집기에서 상품명과 재료 별칭을 직접 입력합니다.
- 링크 생성만으로 DB에 저장하거나 공개하지 않습니다. 편집기에서 상품명(120자 이내), 재료 별칭, 규격을 검토하고 초안으로 저장하세요. 공개에는 기존 상품 확인·게시 위치·근거 입력 조건이 그대로 적용됩니다.
- API 검색은 상품 ID의 기본 상세 페이지를 링크 생성에 사용합니다. 특정 옵션이 필요하면 옵션을 선택한 실제 상세 주소를 URL 방식으로 입력하고 목적지를 확인하세요. 검색어가 여러 단어이면 재료 별칭도 실제 장보기 재료 이름에 맞게 수정합니다.
- 일반 회원에게는 기존 구매처 찾기의 공개·유효한 상품과 수수료 고지·쿠팡 구매 버튼이 표시됩니다. 검색 가격은 카탈로그에 저장하지 않으며 결제·주문·수익 확인은 쿠팡에서 합니다.

## 서버 연결 준비

공식 [쿠팡 파트너스](https://partners.coupang.com/)의 추가 기능 → 파트너스 API에서 해당 계정의 이용 가능 여부와 키 발급 상태를 확인합니다. 판매자 상품 관리용 Open API 키와 혼동하지 않습니다. 공식 웹앱의 공개 메뉴는 API 메뉴 노출을 계정 활성화·API 사용 가능 상태에 따라 구분합니다. 계정별 승인이나 현재 이용 자격을 이 코드가 부여하지 않습니다.

서버 전용 설정 이름:

- `COUPANG_PARTNERS_ACCESS_KEY`
- `COUPANG_PARTNERS_SECRET_KEY`

실제 값은 Supabase 서버 비밀 설정에 직접 등록합니다. 앱의 설정 파일, Dart define, 소스, 채팅, 로그에 넣지 않습니다. 기존 Supabase URL·anon key를 사용해 요청자의 세션과 권한을 검증하며 서비스 역할 키는 이 함수에 필요하지 않습니다.

사용자 승인 후 운영 적용 순서:

1. 신규 `0073_coupang_partner_api.sql` 적용. 기존 관리자 MFA 함수가 있는 0060과 상품 관리 0065·0071을 전제로 합니다. 기존 마이그레이션 파일은 수정하지 않았습니다.
2. 위 비밀 설정을 서버에 등록하고 `coupang_partners` 함수를 배포합니다. 함수의 JWT 검증을 유지합니다.
3. 관리자 2단계 인증 상태에서 상품 검색 1회와 상품 URL 링크 생성 1회를 확인합니다. 생성 링크의 상품·옵션과 게시 허용 위치를 직접 대조합니다.
4. 앱·웹 업데이트를 배포하고, 초안 등록 → 검토 → 공개 → 일반 회원의 재료별 상품 표시를 확인합니다.

첨부된 내 정보 화면의 블로그·유튜브 등록은 앱 등록 상태를 입증하지 않습니다. 앱 스토어 주소·웹 게시 위치는 파트너스에서 별도로 확인해야 합니다.

## 구현과 제한

- `POST coupang_partners`: `action=search` + `keyword`, 또는 `action=deeplink` + `url`.
- 서버에서만 HMAC-SHA256 서명을 생성하여 고정된 쿠팡 API 게이트웨이의 `/v2/providers/affiliate_open_api/apis/openapi/products/search`와 `/deeplink`에 요청합니다.
- 발급 응답의 `shortenUrl`을 변경 없이 사용합니다. 현재 카탈로그가 지원하는 HTTPS `link.coupang.com/a/…` 형식 이외의 응답은 오류로 처리합니다. 임의 추적 코드나 수익 링크를 만들지 않습니다.
- 관리자·2단계 인증 검증 이후 서버 DB에서 호출을 예약합니다. 모든 관리자·서버 인스턴스가 검색 분당 5회, 링크 생성 분당 30회 및 작업별 UTC 일일 500회 한도를 공유합니다. 이는 앱 내부 제한이며 쿠팡의 공식 한도를 뜻하지 않습니다. 실패한 요청도 예약 횟수에 포함됩니다.
- 요청 본문 8KB, 검색어 80자, 상품 URL 2,048자, 쿠팡 응답 제한 시간 12초. 자동 재시도·백그라운드 호출·상품 이미지 복제는 추가하지 않았습니다.
- 오류 응답에는 정해진 코드만 반환하며 키, 서명, 원본 오류 본문을 기록하지 않습니다. 주소 입력은 쿠팡 상세 페이지로 제한하고 사용자 입력 주소에 직접 접속하지 않습니다.
- 비밀 설정 누락·이용 권한 거절·호출 제한·통신 오류는 화면에서 안내합니다. 기존 수동 발급 링크 등록 기능은 유지됩니다.

## 검증과 남은 확인

서버 테스트는 외부 요청을 대체한 응답으로 서명·입력·권한 차단·오류 정제를 검증합니다. DB 검사는 격리된 PGlite PostgreSQL에서 수행합니다. 실제 쿠팡 API 키나 운영 DB는 사용하지 않았습니다.

- Deno 서버 테스트 7개 및 서버 진입점 타입 검사 통과.
- 신규 DB 계약 19개, 기존 제휴 카탈로그 DB 계약 66개 통과.
- API 응답 처리·검색 화면·기존 제휴 기능 집중 Flutter 테스트 26개 통과. 이후 추가한 재시도 테스트를 포함해 번역 및 제휴 위젯 테스트 10개 통과.
- 최종 `flutter analyze --no-pub`: 문제 없음. 로그 `.artifacts/coupang-api-analyze.log`.
- 지정 `tools/dev/verify.ps1`의 전체 테스트: 668개 통과, 기존 조건부 4개 제외, 신규 화면의 번역 카탈로그 누락 검사 1개 실패. 누락 항목을 보완한 후 해당 검사를 포함한 번역·제휴 위젯 10개를 재실행해 모두 통과했습니다. 전체 테스트를 다시 실행한 결과로 표기하지 않습니다. 원본 로그 `.artifacts/coupang-api-verify.log`, 보완 검증 로그 `.artifacts/coupang-api-localization.log`.
- Flutter doctor의 기존 PATH, Android 라이선스 상태, Visual Studio 설치 경고가 있습니다. 지정된 FVM Flutter 3.44.8 및 JDK 17을 확인해 사용했습니다. 로컬 Docker가 실행되지 않아 전체 Supabase 게이트웨이 구동 대신 Deno 및 격리 DB로 검증했습니다.

실제 계정의 API 사용 권한, 실응답 및 상품 목적지, 모바일 브라우저 이동, 앱 게시 승인과 수수료 정산은 미검증입니다. 공식 파트너스의 상세 API 화면은 이 세션에서 로그인 없이 확인하지 못했으므로 운영 적용 전에 계정 내 최신 API 명세와 실응답을 대조해야 합니다. HMAC 방식은 [쿠팡 공식 서명 안내](https://developers.coupang.com/en/getting-started/creating-hmac-signature)도 참고했습니다.
