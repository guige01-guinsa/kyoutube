# 업소 공동 거래처와 상품 규격 — 2차 개편

> 2026-09-22: 이 문서의 기능은 v79 통합 운영 배포와 새 서명 AAB에 포함되었다. 아래 소스 단계의 미배포 설명은 당시 기록이다. [최종 배포·검증](release-v79.md) · [메뉴 기반 빠른 구매](business-menu-fast-purchase.md).

2026-09-21. 소스 구현, 운영 미반영. DB0068이 필요하며 기존 DB0067과 기존 구매 RPC는 변경하지 않는다.

## 사용 흐름

1. **작업공간 → 소속 업소 → 구매 → 업소 거래처·상품**에서 거래처를 등록한다. 업체명·담당자·연락처·주소·홈페이지를 검색할 수 있다.
2. **개인 거래처에서 가져오기**는 업체명을 기본으로 복사한다. 담당자·전화·주소·홈페이지는 체크한 항목만 공유하며, 저장 전에 사본을 수정할 수 있다. 개인 메모·즐겨찾기·개인 DB 식별자·개인 상품 메모는 가져오지 않는다. 개인 원본과 자동 동기화하지 않는다.
3. 거래처별 상품명·규격·포장당 내용량·내용량 단위·구매 단위를 등록한다. 예: `국산 양파 / 2000 g / 봉`. 업소당 거래처 최대 300개, 상품 규격 최대 1000개(중지 항목 포함).
4. **메뉴·레시피에서 구매**에서 구매 목적과 조리 인분을 선택하고 필요량을 계산한다.
5. **업소 공동 거래처 선택** 후 각 재료에 **공급업체 상품 연결**을 선택한다. 내용량 단위가 같은 활성 상품만 표시한다. 상품의 실제 재료·규격이 맞는지는 사용자가 확인한다. 포장 내용량과 구매 단위는 선택한 규격으로 채운다.
6. 다른 작업에 배정하지 않은 재고·입고 예정량을 입력하고 계산 결과를 확인한다. 서버가 다시 계산하고 거래처·상품 버전이 바뀌었으면 선택을 다시 요구한다. 초안 생성 후 기존 화면에서 단가·납품일·거래조건을 확인하고 승인·전달·입고 기록을 진행한다.

거래처 이름 직접 입력과 상품을 연결하지 않은 재료의 수동 포장 규격 입력도 유지한다. 한 요청서는 한 거래처를 대상으로 한다. 다른 거래처에 요청할 재료는 제외하고 별도 요청서를 작성한다.

## 역할과 기록

- `purchasing.read`: 이 업소 거래처·상품 및 구매 당시 사본 조회.
- `purchasing.write`: 거래처·상품 등록/수정/사용 중지. 메뉴 구매 생성에는 기존과 같이 `recipes.read`도 필요하다.
- 선호 직무를 바꾸어도 실제 권한은 늘어나지 않는다. 조리 담당자와 재무 담당자에게 구매 쓰기 권한을 자동 부여하지 않는다.
- 공급업체 자체 운영 영역의 공개 상품 카탈로그와 **구매 업소의 공동 거래처 장부**는 별도 데이터다. 이 기능은 거래처를 공급업체 회원으로 가입시키거나 공개 정보를 게시하지 않는다.
- 단가·세금·배송비·최소 주문량은 자동 확정하지 않는다. 현재 등록 대상은 거래처와 포장 규격이다. 승인 전 실제 조건을 확인한다.
- 거래처·상품은 사용 중지할 수 있다. 변경·중지해도 생성된 요청서의 **작성 당시 거래처·상품** 사본과 메뉴·레시피 구매 근거는 유지된다. 현재 요청서를 수동 수정하면 최초 선택 당시 사본과 달라질 수 있으며 화면에서 이를 명시한다.
- 업소/계정 범위로 조회하고 모든 변경은 서버 권한 검사를 거친다. 직접 테이블 쓰기는 차단한다. 공유 사본은 클라이언트에서 수정할 수 없다.
- 기존의 명시적 요청서 공유 절차를 사용한다. 새 기능은 외부 발송, 주문·결제, 재고 자동 차감, 공급업체 응답 수집을 하지 않는다.

## 구현과 검증

- DB: `0068_business_suppliers.sql` — `business_suppliers`, `business_supplier_products`, `business_purchase_supplier_snapshots` 및 저장/구매 RPC.
- 신규 RPC `business_supplier_purchase`는 기존 `business_menu_purchase`의 계산·원본 근거 보존을 재사용한다. 선택한 상품 버전·업소·거래처·활성 상태·단위·포장 내용을 확인한다. 같은 요청의 동일 재시도는 한 건을 반환하며 다른 입력 재시도는 거부한다.
- 원본 구매 초안 후 상품 표시 정보를 반영한 버전이 추가될 수 있다. 단가는 미확정(null)이며 기존 승인 절차를 건너뛰지 않는다.
- 로컬 DB 검사: `node tools/test/business_workspaces_contract.cjs --suppliers --samples --staff` (격리된 PGlite PostgreSQL, 운영 쓰기 없음).
- Flutter 동작 검사: `test/features/business/business_supplier_test.dart`, 기존 메뉴·업소 테스트, 전체 `tools/dev/verify.ps1`.
- 이 단계에 AI 호출과 AI 사용량 비용은 추가하지 않는다. 일반 DB 읽기·저장 비용은 기존 인프라 사용량에 포함된다.

운영 적용은 DB0068 검토·적용 후 웹/AAB 반영 순서가 필요하다. 현재 릴리스 버전과 서명 설정은 변경하지 않았다. 기존 DB0064의 미적용 상태를 이유로 전체 마이그레이션을 일괄 push하지 않는다.
