# 소유자 영구 삭제·재고 단위 변경

2026-09-30 사용자 명시적 승인 후 구현. 이전 보고서의 ‘기록 보존 때문에 삭제와 단위 변경 제외’ 방침을 이 문서로 대체한다.

## 사용 위치와 결과

| 위치의 관리 메뉴 | 새 작업 | 처리 결과 |
|---|---|---|
| 개인 구매처 | 영구 삭제 | 구매처 제거. 기존 요청서 사본과 재고 유지. |
| 개인 구매요청서 상세 | 영구 삭제 | 전달/완료 상태도 삭제 가능. 상태 이력·거래 평가도 삭제. 외부 주문 취소·환불은 별도. |
| 업소 공급업체/취급상품 | 영구 삭제 | 소유자만 실행. 업체 삭제 시 상품도 삭제하고 기본 구매 연결 해제. 발행된 문서 사본 유지. |
| 공개 취급상품 | 영구 삭제 | 본인 상품 삭제. 공개할 상품이 남지 않으면 업체 비공개 전환. |
| 개인 매출 / 업소 구매·매출 상세 | 영구 삭제 | 기록과 연결 이력 삭제. 개인 매출 집계에서도 제외. 실제 입고·반품 수량은 유지. |
| 저장한 구매 계획 | 영구 삭제 | 정의만 삭제. 이미 생성된 발주·예약은 유지. |
| 업소 재고 품목 | 단위 변경 / 영구 삭제 | 아래 환산·삭제 규칙 적용. |

기존 수정·복사·보관·복원은 유지한다. 서버가 최신 대상과 영향 건수를 표시하며, 사용자가 확인란을 선택해야 실행한다.

## 단위 환산

- g↔kg, mL↔L은 비율을 제안한다. 개·봉·박스 또는 서로 다른 차원의 단위는 실제 규격을 확인하여 `기존 1단위에 해당하는 새 단위 수량`을 입력한다.
- 현재고·예약량·사용 가능량의 전후 값을 미리 보여준다. 입력 변경 시 미리보기와 확인 상태를 해제한다.
- 수불 수량, 예약 원수량·잔량, 입고 환산 계수를 같은 트랜잭션으로 변환한다. 구매 포장 개수·단가·원가는 유지한다.
- 품목 ID 교체와 예약 수정 번호 증가로 예전 단위 화면의 수량 저장을 차단한다. 일괄 구매 결과의 예약 연결도 새 ID로 갱신한다.
- 레시피 기본 구매 규칙의 재고 연결은 해제하여 새 단위와 다시 맞추게 한다. 과거 발주/입고 마감의 원본 사본은 유지한다.
- 동일 재료·규격·새 단위 품목이 있으면 자동 합치지 않는다. 허용 수량 또는 소수점 6자리 범위를 벗어난 결과는 반올림하여 강행하지 않는다.

## 삭제와 연결 보호

- 공동 업무는 업소 소유자, 개인 업무·공개 상품은 해당 소유자만 가능하다. 기존 유료 기능의 이용 권한도 검사한다. 일반 직원의 수정 권한으로는 실행할 수 없다.
- 미리보기 토큰에 계정·업무 공간·작업·대상 전체 내용·연결 자료·환산 입력값을 포함한다. 서버가 잠금 안에서 재비교하여 달라졌으면 전체 작업을 거절한다.
- 성공 결과를 소유자에게만 보관하여 재시도가 중복 실행되지 않게 한다. 삭제 ID와 매출 요청 키에는 재생성 방지 표식을 남긴다.
- 구매요청서 삭제 후에도 입고/반품 수불은 남아 현재고·반품 가능량을 유지한다. 식단/일괄 구매 결과에는 삭제 상태를 표시하고 해당 링크를 비활성화한다.
- 활성 예약이 있는 재고는 먼저 예약을 해제해야 한다. 연결 요청서가 남은 입고/반품은 먼저 요청서를 정리해야 한다. 입고만 삭제하면 같은 요청서에 중복 입고될 수 있기 때문이다.
- 위 연결 정리 후에는 현재고가 0이 아니어도 품목·수불·종료된 예약 이력을 명시적으로 함께 삭제할 수 있다. 삭제 전에 현재고와 영향 건수를 표시한다.
- 식단 통합 검사에서 기존 계정 삭제를 막는 구매 준비 연결 문제를 발견했다. 0079에서 부모 삭제 시 연결도 정리하도록 보완했다. 개별 요청서 삭제는 구매 준비 묶음을 지우지 않는다.
- 이미 외부에 전달한 주문/파일은 자동 취소하지 않는다. 사진·증빙 Storage 파일은 다른 문서에서 재사용될 수 있어 일괄 삭제하지 않는다.
