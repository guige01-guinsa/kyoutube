# 구매요청서 문서·대장 관리

2026-09-16. 사용자 승인으로 DB0061·delete-account v25·운영 웹·v68 서명 AAB 반영 완료. [운영 검증·산출물](release-v68.md).

## 사용자 흐름

1. 장보기 → 구매 요청서 → **구매요청 대장 · 검색·집계·출력**.
2. 작성일 기간, 업체/요청자/요청번호/사업자번호 검색, 진행 상태로 조회한다. 기본 기간은 이번 달이며 전체 기간도 선택할 수 있다.
3. 요청서 열기에서 작성 중인 내용 수정, 새 요청서로 복제, 전달/업체 수락/입고/취소 확인을 기록한다. 공유·인쇄만으로 상태가 바뀌지 않는다.
4. 처리 이력에서 생성·수정·상태 변경 시각과 버전을 조회한다. 기존 요청서는 DB 적용 당시 상태부터 이력을 시작하며 과거 변경을 추정하지 않는다.
5. 대장 CSV 또는 PDF 미리보기·인쇄로 출력한다. 검색에 맞는 전체 결과를 한 번에 조회하며 1,000건을 넘으면 기간/업체 조건을 좁히도록 안내한다. 결과를 조용히 잘라 내지 않는다.

대장 금액은 **입력한 구매 단가 × 구매 수량**을 통화별 최소 단위(KRW 정수, USD 소수 2자리)로 품목별 반올림해 합산한다. 취소 요청은 합계에서 제외하고, 단가가 없는 품목은 견적 대기 건수로 구분한다. 통화는 합치지 않으며 배송비·세금·결제금액·확정 구매금액을 임의로 추정하지 않는다. 큰 금액은 DB decimal 문자열로 전달해 웹의 부동소수점 손실을 피한다.

요청서 삭제 시 그 요청의 대장 이력도 삭제된다. 기록을 보존하려면 **취소**를 선택한다. 실제 구매 이력은 기존 장보기 구매 기록에서 관리하며, 조리에 따른 재고 차감은 추가하지 않는다.

## 양쪽 사업자 정보와 PDF

- 요청 업소와 공급업체 각각 사업자등록번호(선택, 국내 번호 10자리)와 등록증 사진(선택)을 입력한다. 사진이 있으면 번호도 입력한다. 번호 형식 확인은 사업자 실재 여부 검증을 뜻하지 않는다.
- 등록번호를 누르면 저장한 사진을 확대 조회한다. 작성 계정만 접근 가능하며 공개 공급업체 카탈로그에는 사진을 노출하지 않는다.
- 이미지 선택 후 기기에서 크기를 제한하고 PNG로 다시 인코딩해 메타데이터를 제거한다. 파일당 5 MB, 최대 변 2,048px, 원본 최대 24MP, 계정당 최대 200개를 허용한다. 반복 요청서는 기존 사진을 재사용한다.
- 작성 중 **저장 전 PDF 미리보기**, 저장 후 **PDF 미리보기 · 인쇄**를 제공한다. 요청서와 대장 모두 미리보기·다운로드·인쇄가 같은 PDF 바이트를 사용한다.
- 등록증 사본 포함은 기본 해제다. 사용자가 양쪽 사본을 각각 선택하면 PDF 뒤에 첨부하고, 본문의 번호는 해당 첨부 페이지로 이동한다. 개인 Storage URL이나 접근 토큰은 PDF에 넣지 않는다.
- 기본 텍스트 미리보기·공유와 CSV는 기존 요청서 이용권한을 따른다. PDF 미리보기·출력·인쇄는 기존 **Plus/Business** 서버 권한 검사를 유지한다.
- Android는 시스템 인쇄 서비스를, 웹은 브라우저 인쇄 화면을 연다. 사용자가 프린터·용지·방향을 확인하고 최종 인쇄한다. 취소해도 요청서 상태는 바뀌지 않는다.

## 구성 및 보안

- `0061_purchase_request_business_documents.sql`: 비공개 Storage 버킷/소유권 정책, 요청서 첨부 검증, 변경 이력, 대장 검색/통화별 집계 RPC.
- Storage 파일은 덮어쓰기를 허용하지 않는다. 요청서가 참조하는 파일은 삭제할 수 없다. 전달 확인 후 요청 내용 고정 규칙은 기존 RPC에서 유지한다.
- 사진을 바꾸거나 편집을 취소하면 이번 편집에서 올린 미참조 사진을 정리한다. 요청서를 삭제할 때도 미참조 파일 정리를 시도한다. 중단된 업로드는 비공개로 남을 수 있으며 계정 삭제 함수에서 함께 정리한다.
- `delete-account/business_documents.ts`: Storage API로 해당 계정의 등록증 파일만 삭제하며 오류 시 계정 삭제를 중단해 재시도할 수 있다.
- `supplier_request_events`: 사용자별 SELECT만 허용하는 변경 이력. 테이블 직접 생성·수정·삭제 권한은 클라이언트에 주지 않는다. 요청/계정 삭제는 FK로 함께 정리한다.
- `search_purchase_request_ledger`: 인증·비익명·본인 소유 요청만 조회, 매개변수 검증, 정렬 고정, 서버 집계. 사진 경로나 상세 품목 전체를 대장 목록에 노출하지 않는다.
- CSV는 UTF-8 BOM, 필드 인용, 수식 접두문자 무력화를 적용한다.
- 웹 PDF 렌더러는 공식 `pdfjs-dist 5.7.284`를 npm SHA-512 확인 후 같은 출처에서 로드한다. 재현: `tools/dev/vendor-request-pdfjs.py`. 라이선스와 파일 SHA-256 목록은 `web/vendor/pdfjs/`에 포함한다.
- 기존 CSP에서 `frame-src`에 `'self' blob:`만 추가한다. 외부 PDF 서비스, 원격 스크립트 CDN, `unsafe-eval`은 사용하지 않는다. `object-src 'none'` 유지.

## 검증 및 배포 순서

검증 기록은 `.artifacts/request-documents/`, `.artifacts/request-verify.log`에 저장한다. 테스트 PDF의 업체·번호·등록증은 가상 자료다. 실제 프린터로 종이가 출력되는지와 운영 계정의 업로드/다운로드는 운영 적용 후 사용자 기기에서 확인해야 한다.

1. `tools/dev/verify.ps1`로 doctor, analyze, 전체 Flutter 테스트.
2. `tools/test/run_request_documents_contract.ps1`로 로컬 DB 0058 위에 0059·0060·0061을 트랜잭션 적용해 인증/첨부/금액/이력을 검증하고 전부 롤백. DB reset 금지.
3. Deno 계정 삭제 보조 함수 테스트, 실제 한글·영문/다중 페이지 PDF 렌더링·검수, 브라우저 CSP 및 인쇄 진입점 검사(실제 인쇄는 대체).
4. 사용자 승인 후 운영 백업 상태 확인 → **DB 0061만** 적용 → **delete-account 1개** 배포 → 웹 배포 → 별도 버전 증가 및 서명 AAB 생성.
5. 운영 계정에서 작성·등록증 클릭·PDF 사본 선택·대장 조회/CSV·프린터 화면을 확인. 사용자 동의 없이 요청서를 전송하거나 실제 인쇄하지 않는다.

운영 문서는 적용 완료 후에만 배포 완료로 변경한다. 전체 마이그레이션을 무차별 db push하지 않는다.
