# 원본 레시피 자동 제작 엔진

상태: 운영 반영 전 개발본. 아직 새 유료 제작·업로드·배포를 실행하지 않았다.

## 사용 흐름

기존 **스토리 영상 제작소** 상단의 **레시피 영상 · 원고와 완성본**에서 시작한다.

1. 음식 이름과 기준 유튜브 주소를 입력한다. 원고 준비 비용을 확인한다.
2. 서버가 공식 YouTube API로 해당 영상의 설명란·제목·채널을 읽는다. AI는 한국어 원본 레시피의 줄 범위와 인사말·마무리만 제안한다. 재료표와 조리 단계는 원문에서 그대로 가져온다.
3. 관리자는 원본 링크와 원고를 확인하고 필요하면 수정한다. 재료·분량·단위·선택 사항·순서를 원본과 대조한다. 설명란에 필요한 정보가 없으면 추측하지 않고 검토 상태로 멈춘다. 원문 직접 입력도 가능하다.
4. 원고 확인과 기존 한국어 여성 목소리 사용에 동의한 뒤 영상 제작 비용을 확인한다. 새 시험 음성을 듣지 않았다는 사실을 그대로 기록하며, 청취 완료로 처리하지 않는다.
5. 음성·재료표·조리 안내 화면·배경음악·영상 검사를 자동 실행한다. 완성본은 같은 제작소 상단에서 확인한다. 비공개 업로드는 영상 검토 후 별도로 승인한다.

## 원본 보존

- 기준 영상은 하나다. 다른 영상의 양념·분량을 섞지 않는다.
- 원본의 약간은 그대로 둔다. 큰술과 g의 병기 수치를 모두 보존하고 15mL로 다시 환산하지 않는다.
- 레시피 음성과 화면을 동일한 데이터로 만든다. 원고를 바꾸면 다시 확인해야 한다.
- 줄 범위가 원본 전체를 포함하는지와 영상 속 조리 내용까지 일치하는지는 관리자 확인이 필요하다. 자동 검사는 확인된 원문에서 제작 원고로 옮길 때의 변조를 차단하며 외부 정보의 진위를 보장하지 않는다.
- 원본 영상은 다운로드하거나 재업로드하지 않는다. 제목·채널·원본 링크를 소개한다.

## 속도 기준

목표는 **원고 준비와 영상 제작의 자동 처리 합계 300초 이내**다. 두 작업의 서버 대기·실행 시간을 포함하고 사람이 원고를 읽고 수정하는 시간은 제외한다. 자동 처리 한 단계의 기록이 없으면 목표 달성으로 표시하지 않는다.

- 원본 설명은 관리자 전용 저장소에서 24시간 재사용한다.
- 음성은 기존 비공개 보관본을 우선 재사용한다. 첫 구간을 확인한 뒤 최대 두 구간을 동시에 처리한다.
- 새 AI 그림을 생성하지 않고 재료와 조리 방법 중심의 고정 화면을 사용한다. 기존 삽화 영상은 보존한다.
- 실제 음성 길이에 따라 장면 길이를 맞춘다. 음성을 자르거나 빠르게 재생하지 않는다.
- 결과 길이는 150~180초다. 원본을 임의로 줄이거나 빈 화면을 늘려 시간을 맞추지 않는다. 범위를 벗어나면 원고 검토가 필요하다.
- 실패한 요청을 자동으로 새로 만들지 않는다. 별도 승인된 재시작에서 같은 음성은 재사용한다. 기존 음성 저장 한도(프로젝트당 20개·전체 96MB)는 유지하며, 한도에 도달하면 제작을 중단한다. 장기 운영용 보관·정리 정책은 후속 과제다.

오프라인 합성 음성으로 180초 출력·전체 프레임 해독·오디오 존재를 검사했다. 실제 AI와 운영 서버를 포함한 5분 달성 여부는 아직 측정하지 않았다. 외부 응답과 GitHub 대기 때문에 보장할 수 없다.

## 즉시 실행 연결

새 Edge Function `story_studio_dispatch`는 로그인·관리자·MFA·작업 소유자·승인된 대기 작업을 DB에서 검사한 뒤 같은 작업에 대해 한 번만 실행을 요청한다. 유료 작업을 생성하거나 재등록하지 않는다. GitHub 대상 저장소·워크플로·분기는 서버에 고정한다.

서버 비밀값 이름: `STORY_STUDIO_GITHUB_DISPATCH_TOKEN`. GitHub에서 `guige01-guinsa/kyoutube` 하나만 선택하고 **Actions: write** 권한을 가진 세분화 토큰 또는 적절한 GitHub App 토큰을 사용한다. 광범위한 로컬 로그인 자격증명을 복사하지 않는다. 키는 채팅·코드·웹 브라우저 저장소에 넣지 않는다.

연결이 없거나 응답이 불확실하면 대기 작업을 보존하고 사용자에게 표시한다. 기존 10분 간격 정기 실행이 남아 있으므로 연결 전에는 5분 목표를 기대할 수 없다. 즉시 요청 자체도 GitHub 실행 시작 시간을 보장하지 않는다.

공식 근거:
- [YouTube videos.list](https://developers.google.com/youtube/data/reference/rest/v3/videos/list): 지정 영상의 설명·제목·채널 조회.
- [GitHub workflow dispatch](https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event): Actions write 권한, 승인된 워크플로 실행 요청.

## 배포와 비용

기존 60초 기능·작품·MFA·공유 예산·월 30만 원·중복 방지·비공개 업로드 승인을 보존한다. 새로운 DB 구성은 새 migration만 사용한다. 공개 서버 코드와 비공개 웹 이력을 섞지 않는다. 서버 코드·DB·Edge Function·검사·웹 변경본의 검토와 전체 커밋 승인이 필요하다. 유료 검증은 배포 승인과 별개이며, 본 개발 중 추가 유료 호출은 하지 않았다.
