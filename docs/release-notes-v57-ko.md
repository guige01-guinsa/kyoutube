2026-09-13. 사용자 명시적 승인으로 관리자 알림 DB·함수·5분 점검과 서명 AAB를 적용했다.

## 포함 기능

회원 관리자 → 서비스 운영 현황 → 알림 아이콘에서 한/영 관리자 알림함을 연다. 상태 변화, 판단 수치, 조치 안내, 읽음 처리와 페이지 조회를 제공한다. 관리자 기기에서 푸시 수신을 선택하면 OS 권한을 요청하고 로그인 세션에 연결된 기기를 등록한다.

AI 성공률·지연, 관측된 서버 오류, DB 크기/연결 비율, 수동 입력한 월 비용의 예산 비율을 점검한다. 표본 부족은 정상으로 단정하지 않고, 동일 상태는 중복 경고를 생성하지 않는다. 악화와 회복을 구분한다. DB 예산 설정은 경고 기준이며 서버 증설이나 요금제를 변경하지 않는다.

## 운영 적용

- DB 0036·0040을 이력과 함께 하나의 트랜잭션으로 적용했다. 기존 0037~0039는 재실행하지 않았다.
- 최초 실제 REST 실행에서 운영 `safeupdate`가 WHERE 없는 singleton UPDATE를 거절했다. 기존 마이그레이션을 수정하지 않고, 0041에서 점검 시간·발송 상태·관리자 DB 예산 UPDATE 세 곳에 `WHERE singleton = true`를 추가했다. 동일 보호 모듈을 켠 로컬 회귀 테스트를 통과한 후 적용했다.
- 운영 함수 원본을 개별 백업하고 `recipe_api`, `youtube_search`, `ai_recipe_assistant`, `delete-account`, `youtube_recipe_context`, `ai_youtube_recipe_assistant`, `membership`에 관측 래퍼만 추가했다. 현재 영어 초안 처리와 기존 인증 설정을 보존했다.
- 신규 `operations_monitor`를 배포했다. 이 엔드포인트만 전용 스케줄러 헤더로 인증하며 기존 함수의 JWT 설정은 유지했다.
- 무작위 전용 시크릿과 Vault URL/시크릿을 설정하고 `recipe-scout-operations-monitor`를 5분 주기로 활성화했다. 인증값은 소스·문서·로그에 기록하지 않았다.
- 실제 배포 소스를 다시 다운로드하여 준비한 8개 패키지의 파일 해시와 JWT 설정을 확인했다.

- 운영 테이블 9개의 RLS 및 직접 조회 차단, 관리자 RPC와 service-role RPC 권한을 확인했다.

- recipe_api와 delete-account의 실제 관측 이벤트 저장을 확인했다. 게이트웨이에서 거절된 요청은 함수 관측에 포함되지 않는다.
- 자세한 최종 실행 시각과 결과는 `release/deployment-v57.json`에 기록한다.

## 남은 설정과 범위

**Firebase 서버 발송용 `FCM_SERVICE_ACCOUNT_JSON`이 미설정이어서 휴대폰 푸시 발송은 완료되지 않았다.** 앱용 google-services.json으로 대체할 수 없다. 발송 자격 증명을 안전하게 설정한 뒤 관리자 기기 등록 → 실제 수신 → 알림함 열기 → 읽음 → 로그아웃 후 차단을 확인해야 한다. 서버는 발송 실패를 기록하며 앱 알림함의 점검 결과는 보존한다. 정상 발송으로 표시하지 않는다.

0036의 원시 관측 이벤트 정리를 위한 일일 `purge_ops_events()` 예약은 별도 운영 작업으로 남아 있다. 0040의 알림 이벤트·만료 기기 정리는 5분 점검에 포함된다. 월 실제 비용은 관리자 입력값이며 공급자 청구서를 자동 수집하지 않는다. 같은 DB에서 실행하므로 Supabase/DB 전체 장애에 대한 외부 즉시 통지는 제공하지 않는다.

개인정보처리방침/Data safety 저장소 초안을 v57 범위에 맞춰 갱신했다. 공개 사이트 게시와 Play 양식 제출은 수행하지 않았다. 원가·매출 유료 회원 전용 제한과 영어 초안 90% 성공률 재검증은 이번 배포에 포함되지 않는다.
