# 메뉴·회원 정책 안전 전환안

작성: 2026-09-13. 기준 출시 파일: **v62 / 1.0.1+62**.
이 문서는 로컬 개편과 이후 운영 전환을 구분합니다. v63 AAB, DB 0054 운영 적용,
새 요금제 판매는 아직 실행하지 않았습니다.

## 이번 개편

| 영역 | 구현한 동작 |
|---|---|
| 발견 | 기존 홈·언어별 한식 15종·영상 검색·튜토리얼 유지. 하단 이름을 ‘발견 / Discover’로 변경 |
| 내 레시피 | 저장·검색·편집 중심. 작은 새 레시피 버튼 유지. 매출 아이콘은 셰프 화면으로 이동 |
| 장보기 | 도우미·내 구매처·구매 요청서를 동일한 버튼 스타일로 상단 배치. 빈 목록에서도 접근 가능. 재료 검색은 상단 아이콘으로 접근 |
| 셰프 | 새 `/chef` 화면. 내 작업용 레시피 선택 → 기존 작업실. 유료 회원 매출 현황, 구매 요청서 바로가기. 비로그인은 소개·로그인, 무료는 인분·버전 이용 안내 |
| 회원 | 현재 이용 가능한 기능을 서버 권한으로 표시. 회원 조회가 로딩·실패 상태이면 신규 결제 버튼 비활성화 |

셰프 하단 탭은 좁은 화면에서 `셰프 / Chef`, 페이지 제목은 `셰프 작업실 / Chef studio`입니다.
공개/구독 레시피는 기존 흐름에서 개인 레시피로 복사한 뒤 작업합니다.
사용 목적을 영구 선택하거나 별도 계정을 만들 필요 없이 네 메뉴를 오갈 수 있습니다.

## 안전한 실행 순서와 완료 조건

1. **메뉴와 안내 개편 — 로컬 구현.** 기존 URL·문서·회원 상태를 유지하며 새 진입점만 연결합니다.
2. **권한 정책 분리 — DB 0054 준비.** 월간/연간 청구 주기와 별개인 기능 프로필을 도입합니다.
   기존 `free / paid_monthly / paid_annual`만 기존 기능에 연결합니다. 새 상품은 draft이고 새 프로필은 비활성입니다.
   신규 앱의 기능 조회는 0054가 없는 v62 서버에서도 기존 RPC로 호환합니다. 없는 함수 오류(PGRST202)만 호환 경로를 허용하며
   인증·권한·통신 실패는 권한 부여로 처리하지 않습니다.
3. **DB 0054 운영 적용 및 새 앱 내부 테스트 — 별도 승인 후.** 복구 가능한 백업·사전 비교 → 0054만 트랜잭션 적용
   → 기존 회원/구매 데이터·권한 검증 → 승인된 다음 버전 AAB 생성 → Play 내부 테스트 → 실기기 확인 순서입니다.
   0047·0048은 별도 MFA 선행 조건이 있으므로 일반 `db push`로 함께 밀지 않습니다.
4. **신규 요금제 판매 — 결제 전환 구현·검증 후 별도 출시.** Google Play 상품·기본 요금제,
   구매 검증, RTDN, 업/다운그레이드, 무료 신규 가입자 구분, 새 한도 예약/복구를 한 묶음으로 검증합니다.
   준비 단계에서 상품 ID를 추측하여 기존 결제 매핑에 등록하지 않습니다.

## 현재 회원 보호

| 현재 회원 | 이번 변경 이후 |
|---|---|
| 무료 | AI 초안 10회/월 및 기존 일·주 한도 유지. 인분·버전, 구매처 최대 200개, 요청서 및 PDF 유지 |
| 월간 프리미엄 | 기존 월 9,000원 상품·AI 100회/월·영상 분석 20회/월·원가/매출 유지 |
| 연간 베이직 | 기존 연 30,000원 상품·AI 30회/월·원가/매출 유지. 영상 분석을 새로 부여하지 않음 |
| 만료·해지 | 유효 기간 내 해지 회원은 기존 권한 유지. 만료 시 기존 무료 접근 규칙으로 복귀. 저장된 금융 데이터를 삭제하지 않음 |

위 가격은 기존 등록 정책이며 실제 구매 화면은 Google Play가 반환한 가격을 따릅니다.
일·주·월 초안 한도와 영상 길이 20분 제한은 기존 서버에서 계속 집행합니다.
요청서에는 기존 총 저장 상한 1,000건이 있으며 ‘월 제한 없음’은 저장 용량 무제한을 뜻하지 않습니다.
만료 후 금융 원문 조회는 0046의 기존 보호 정책을 유지합니다. 이번 작업은 유료 금융 데이터의 무료 공개를 추가하지 않습니다.

기존 회원에 대해서는 기능별 권한을 보존하고, 기존 구독의 금액/상품/자동 갱신을 자동 변경하지 않습니다.
향후 신규 가입자에게만 다른 무료 정책을 적용하려면 서버에서 고정한 전환 시점과 명시적인 회원별 정책 배정이 필요합니다.
해지/업그레이드/재가입 시 기존 조건으로 복귀할 수 있는지 사용자에게 구매 전에 안내해야 합니다.

| 구분 | Scout | Recipe Plus | Chef Business |
|---|---|---|---|
| 대상 | 발견·일상 장보기 | 요리를 자주 기록하는 개인 | 셰프·소규모 업장 |
| 제안 가격 | 무료 | 월 9,900원 / 연 99,000원 | 월 19,000원 / 연 189,000원 |
| AI 초안 월간 제안 한도 | 10회 | 50회 | 100회 |
| 영상 분석 월간 제안 한도 | 없음 | 5회 | 20회 |
| 인분·일반 레시피 버전 | 제공 | 제공 | 제공 |
| 구매처 / 새 요청서 월간 제안 한도 | 3개 / 3건 | 30개 / 30건 | 200개 / 별도 월 제한 없음 |
| PDF 공유 | 새 정책에서는 제외 제안 | 제공 | 제공 |
| 원가·판매가·매출 | 제외 | 제외 | 제공 |

Plus 구매처·요청서 30개/30건은 무제한 운영을 피하기 위한 초기 제안값입니다.
모든 신규 플랜은 **청구 주기와 관계없이 같은 월간 기능 한도**를 갖는 방향입니다.
이는 기존 ‘월간 프리미엄만 영상 분석’ 정책을 바꾸므로 실제 판매 전 별도 전환 안내가 필요합니다.
기존 무료 인분·버전 기능을 다시 유료화하지 않습니다.

`membership_feature_profiles`의 신규 3개 프로필과 `membership_offer_drafts`의 가격 4개가 준비되어 있지만
기존 상품/회원에 연결되지 않습니다. `draft` 테이블은 기존 결제 함수나 앱의 구매 상품 목록에서 읽지 않습니다.
새 정책을 활성화하는 버튼이나 환경 변수 우회 경로도 없습니다.
수익성이 검증된 가격이 아니므로 측정된 AI 사용량, Gemini 영상 분당 비용, 스토어 수수료, 환율/세금,
지원·인프라 비용을 반영해 판매 가격과 한도를 재확인해야 합니다.

## 신규 판매 전에 반드시 끝낼 구현

- 상품별 base plan / offer를 검증된 Play 정보에 매핑하고, 앱·서버·관리자 화면의 현재 3개 플랜 하드코딩을 교체합니다.
- RTDN 수신 후 Play Developer API로 현재 구독 상태를 다시 조회합니다. 중복/역순 알림, 구매 토큰 연결,
  계정 귀속, 갱신·유예·일시정지·취소·환불·복원·재가입을 시험합니다.
- 영상 분석의 0050 / Edge Function / Flutter에 남아 있는 `paid_monthly` 및 20회 고정 조건을
  새 기능 권한과 원자적 한도 예약으로 함께 교체합니다. DB 프로필 값만 바꿔 판매하면 안 됩니다.
- 구매처·요청서 제한은 서버의 생성 시점에 검사합니다. 기존 문서 조회/수정/삭제, 저장 재시도,
  동일 UUID 요청의 재전송은 새 요청으로 중복 차감하지 않습니다. 기존 상한 초과 데이터도 삭제하지 않습니다.
- 원가/매출은 현재 단일 유료 접근 경계를 공유합니다. 0054는 두 기능 권한이 다르게 설정되는 것을 제약으로 막습니다.
  향후 두 권한을 분리하려면 RLS와 각 저장/조회 RPC를 함께 수정해야 합니다.
- 금액·권한·일/주/월 한도·데이터 보존·이전 요금 복귀 조건을 한영 구매 화면에 먼저 표시합니다.
- Play 내부 테스트에서 신규 구매와 기존 회원 전환을 실기기로 확인한 뒤 제한된 신규 가입자부터 적용합니다.

Google 공식 근거: [구독 구성과 변경](https://developer.android.com/google/play/billing/subscriptions),
[구매 수명주기와 RTDN](https://developer.android.com/google/play/billing/lifecycle),
[기존 가격 그룹](https://support.google.com/googleplay/android-developer/answer/12154973?hl=en).
기존 가격 그룹을 유지하는 구조를 선택했으며, 자동 가격 인상을 실행하지 않습니다.

## 검증과 되돌리기

- Flutter 고정 SDK로 한국어/영어, 좁은 화면·200% 글자, 네 메뉴 이동, 작업 레시피 선택,
  로그아웃과 늦은 계정 응답, 기능 조회 실패/호환 경로를 시험합니다.
- `tools/test/run_membership_features_contract.ps1`은 로컬 Docker DB에서 0036–0054를 트랜잭션에 적용하고
  기존 플랜/회원 행 불변, 무료/월간/연간/만료/유예/해지/미래 시작, 타 계정·익명·정책 수정 차단,
  셰프 금융 RLS와 저장 보존, 구매 기능 계약을 확인한 뒤 전부 ROLLBACK 합니다.
- DB 0054만 운영에 적용해도 v62 앱이 동작하도록 기존 `has_chef_paid_access()` 서명을 유지합니다.
  앱 개편 문제는 이전 내부 테스트 빌드로 확인할 수 있으며 새 DB 표를 삭제할 필요가 없습니다.
  이미 더 높은 versionCode가 설치됐다면 이전 AAB를 덮어쓰지 말고 수정한 더 높은 빌드를 배포합니다.
- DB 문제는 검증된 0046 함수 정의를 새 보정 마이그레이션으로 복구합니다. 적용한 0054 파일을 수정하거나
  구독 행·구매 이력을 역변환하지 않습니다.
