# 메뉴 후보·판매 승인과 빠른 구매 준비

이번 개편은 기존 업소 업무 개편, 공동 거래처, 입고·재고 기능을 연결한다. 운영 반영 여부와 최종 검증 결과는 `release-v79.md`에서 확인한다.

## 메뉴 선정

- 공동 레시피 상세의 **이 버전을 메뉴 후보로 담기** 또는 메뉴판 관리의 메뉴 등록을 사용한다. 후보는 개발 버전과 가격 미정 상태로 등록할 수 있다.
- 조리 연구자는 후보를 수정할 수 있지만 판매 중인 메뉴를 변경하거나 후보로 되돌릴 수 없다.
- 출시 준비·판매 전환은 시험 조리 후 승인된 레시피 버전과 명시한 판매가가 필요하다. 무료 제공은 가격 0으로 구분한다.
- **메뉴 선정·출시·가격 관리** 권한은 재무 권한과 별개다. 사장이 직원·권한 관리에서 위임한다. 기존에 메뉴를 관리하던 재무 수정 담당자의 권한은 별도 메뉴 권한으로 이전하고 접근 이력에 기록한다. 이후 재무 권한만 새로 부여해도 메뉴 승인 권한이 생기지는 않는다.
- 판매 메뉴는 승인된 버전을 유지한다. 새로운 레시피 버전이 생기면 검토 링크를 표시하며, 레시피 상세의 버전 비교 후 메뉴에 적용한다. 과거 요청서의 작성 기준은 변하지 않는다.

## 구매담당자의 업무

1. **판매 메뉴로 빠른 구매**에서 메뉴 최대 20개, 준비 인분, 납품 희망일을 정한다.
2. 재료·구매량 계산을 누른다. 이름·규격·단위가 같은 재료만 합산한다.
3. 처음 사용하는 재료는 공통 구매 기준에서 기본 거래처·상품·환산을 확인한다. 예를 들어 상품 내용량 단위 1kg = 레시피 단위 1000g를 명시한다. 동일 단위의 환산값은 1이다. 상품이 바뀌면 다시 확인한다.
4. 선택적으로 재고 품목을 연결한다. 연결한 품목은 레시피와 같은 단위여야 하며 기존 예약을 제외한 사용 가능량만 제안한다. 여러 재료를 같은 재고 품목에 연결해도 같은 수량을 중복 배정하지 않는다.
5. 진행 중 요청, 구매처·규격·환산, 사용할 재고를 검토하고 확인한다. **업체별 초안 생성·재고 예약**을 누르면 전체 작업을 한 트랜잭션으로 저장한다.
6. 생성한 초안에서 단가·납품 조건을 확인하고 기존 구매 승인·공유 절차를 따른다. 자동 외부 발주·메시지 발송은 없다.
7. 예약된 재고는 재고·조리 예약 화면에서 실제 사용을 기록하거나 남은 예약을 해제한다. 구매요청을 취소하거나 수정해도 조리 계획의 재고 예약은 자동 해제되지 않는다.

계획을 이름(예: 월요일 점심)으로 저장하거나 최근 30개 구매 준비 계획에서 불러올 수 있다. 메뉴가 변경·중지되었으면 이전 버전으로 자동 실행하지 않고 다시 선택하도록 한다. 납품일은 새 계획의 날짜를 확인한다. 템플릿은 업소당 100개까지다.

## 재고와 중복 방지

- 요청서 작성 시 실제 재고를 차감하지 않고 준비에 사용할 수량을 예약한다. 실제 사용을 기록할 때 차감한다.
- 입고 예정량은 자동으로 차감하지 않는다. 현 단계에서 동일 재료의 진행 중 요청 개수를 보여 주므로 실제 요청 내용을 열어 중복 계획을 조정한다. 기존 수동 메뉴·레시피 구매 화면도 계속 제공한다.
- 구매 기준·상품 버전·메뉴 버전·재고·진행 중 요청이 계산 후 바뀌면 다시 계산해야 한다.
- 응답이 불확실하면 입력을 고정하고 같은 요청 재확인으로 재시도한다. 서버가 동일 요청 ID와 입력을 검증해 초안·예약을 중복 생성하지 않는다. 앱을 종료한 경우 최근 구매 계획과 구매 목록에서 저장 결과를 먼저 확인한다.
- 모든 재료를 기존 재고로 준비할 수 있으면 구매요청서 없이 재고 예약만 만들어진다.
- 납품일은 현재 날짜부터 365일 이내, 재료는 100개 이내, 구매 기준은 업소당 1000개 이내다. 현재 기본 구매처는 재료당 한 곳이며 다른 업체로 바꾸려면 구매 기준을 다시 선택한다.

## 보안·구현

새 DB 0070, 원본 레시피/메뉴/구매 이력 보존, 서버의 이용권·활성 회원·업소 권한 검사, 테이블 RLS, 직접 쓰기와 익명 RPC 차단, 고정 search_path를 사용한다. 준비 작업은 업소 단위로 직렬화한다. 공급업체나 재고를 다른 업소에서 가져올 수 없다. 새 AI 호출이나 외부 유료 API는 없다.

직원 관리 0064, 공동 거래처 0068, 입고·재고 0069와 함께 적용한다. 사전 모집 등 이번 업무 개편과 관계없는 보류 마이그레이션은 자동 적용하지 않는다.

구버전 호환: 서버는 기존 상태 값과 숫자형 가격을 유지하고 별도 후보·가격 확정 플래그를 저장한다. 새 앱은 후보와 가격 미정을 구분한다. 기존 앱에서는 후보가 출시 준비/0원으로 표시될 수 있으나 고객용 판매 메뉴에 포함되지 않고, 승인되지 않은 후보의 출시 구매는 서버에서 차단된다. 새 기능은 v79 웹 또는 새 Android 앱에서 사용한다.
