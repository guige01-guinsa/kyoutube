# 협력업체 구매 요청서

2026-09-13. v62 출시 기능. 운영 DB 0051·0052와 후속 [내 구매처 관리](shopping-store-management.md)의 DB 0053을 적용했습니다.
서명 AAB 생성·검증 상태는 [v62 출시 기록](release-v62.md)을 참고합니다.

## 사용자 흐름

장보기 도우미의 ‘협력업체에 구매 요청’에서 시작합니다. 선택한 장보기 목록이 있으면
그 목록의 재료를, ‘모든 목록 합산’이면 전체 활성 목록의 미구매 재료를 선택할 수 있습니다.

1. 협력업체명, 담당자, 연락처, 주로 구매하는 재료를 등록합니다.
2. 요청서를 만들고 업체·요청자·회신 연락처·희망 납품일/시간·납품 장소를 입력합니다.
3. 장보기에서 품목을 선택하거나 직접 추가합니다. 품목별 수량·단위·규격·브랜드·포장 설명을 수정할 수 있습니다. 모르는 수량/단위는 사용자가 확인해야 저장할 수 있습니다.
4. 단가는 입력한 구매 단위 1개당 금액입니다. 비워 두면 견적 요청으로 표시합니다. 배송비·세금 포함 총액과 납품 가능 여부를 업체에 회신 요청합니다.
5. 저장 후 미리보기에서 공유 내용을 확인합니다. ‘카카오톡 등으로 공유’는 휴대폰 공유 화면으로 텍스트를, ‘PDF 공유’는 한영 PDF 파일을 전달합니다. 받는 사람과 최종 전송은 카카오톡에서 직접 선택합니다.
6. 전달 확인 → 업체 수락 확인 → 입고 확인은 사용자의 수동 기록입니다. OS 공유 결과를 전송·읽음·업체 수락·결제로 간주하지 않습니다. 취소 기록도 업체에 자동 통보되지 않으므로 별도로 연락해야 합니다.
7. 업체 수락/입고 확인 이후 원래 장보기에서 가져온 품목은 실제 구매 수량·금액 기록으로 연결합니다. 각 목록의 ‘장보기 완료’ 때 재고에 반영합니다. 구매 금액은 기존 유료 셰프 작업실의 원가 불러오기로 활용합니다.

전달 확인 이후 요청서 내용은 고정됩니다. 수정 발주/반복 주문은 ‘새 요청서로 복제’를 사용합니다.
복제 시 업체·요청자·납품 장소·품목/규격을 보존하고 날짜·시간·요청사항·단가·이전 장보기 연결은 초기화합니다.
이전 요청서의 품목은 반복 주문을 위한 기본 품목으로 활용할 수 있습니다.
이전 업체를 삭제했다면 다른 업체를 자동 지정하지 않고 직접 선택하도록 안내합니다.

복제하거나 직접 추가한 품목은 기존 장보기 항목에 자동 연결하지 않습니다. 장보기 도우미에서 현재 목록을 확인해 구매를 기록합니다.
서로 다른 업체로 보내려면 각각 요청서를 만들고 해당 업체에서 구매할 품목을 선택합니다.

## 운영·보안

- 무료/유료 로그인 회원이 사용할 수 있습니다. 셰프 원가/매출의 유료 제한은 유지합니다.
- DB 0052: `shopping_suppliers`, `supplier_purchase_requests`, `save_supplier_purchase_request` RPC.
- 사용자별 RLS, 요청서 생성/수정 RPC, 기대 revision 검사, 동일 내용 재시도, 전달 후 스냅샷 변경 금지, 단계별 상태 전환을 적용합니다.
- 업체 200개, 요청서 1,000개, 요청서당 품목 100개, 요청서 JSON 128KiB 한도입니다. 요청 수량은 양수·소수점 6자리까지이며, 실제 장보기 구매 기록은 기존 소수점 2자리 규칙을 따릅니다.
- 요청서는 최근 50개부터 불러오며 ‘요청서 더 보기’로 확장합니다. 계정을 바꾸면 조회 범위도 초기화됩니다.
- 업체 삭제 시 요청서의 업체 스냅샷은 유지됩니다. 요청서는 별도로 삭제할 수 있고 계정 삭제 시 두 테이블 모두 삭제됩니다. 이미 공유한 메시지/문서는 회수하지 않습니다.
- 사용자 입력 연락처만 저장합니다. 휴대폰 주소록 접근 권한, Kakao 로그인/키, 유료 발송 API, AI 호출, 별도 문서 서버를 사용하지 않습니다.
- PDF는 앱에 포함된 SIL OFL 나눔고딕으로 기기에서 생성합니다. 문서 생성 중 외부 서버로 구매/주소 정보를 보내지 않습니다. 공유 과정에서는 선택한 대상 앱에 문서가 전달되며 OS 공유용 임시 캐시 파일이 생성될 수 있습니다.
- 메시지나 PDF에는 앱 로그인 토큰·원본 레시피·내부 목록 ID를 넣지 않습니다. 요청자/업체/주소/요청 품목 등 미리보기의 정보가 포함되므로 공유 전에 확인합니다.
- 계정 변경 시 개인 화면과 편집 대화상자를 닫고, PDF 생성 후 실제 공유 직전에도 계정을 확인합니다.

## 검증 및 출시

- 최종 Flutter 3.44.8 정적 분석: 오류 없음. 전체 테스트 261개 통과, 기존 선택형 미리보기 테스트 4개 건너뜀(2026-09-13).
- Android 디버그 APK 생성 성공: `build/app/outputs/flutter-apk/app-debug.apk`(2026-09-13, Gradle 965.6초). 파일 공유 Provider와 앱에 포함된 한글 글꼴도 확인했습니다. 테스트용 빌드이며 운영 설정의 서명 AAB 생성이나 휴대폰 설치는 수행하지 않았습니다.
  이 APK는 후속 ‘내 구매처 관리’ 확장 전 검증 결과입니다. 해당 확장의 최신 검증은 별도 문서를 따릅니다.
- 로컬 DB의 장보기·요청서 계약 테스트 모두 통과. 검사 후 새 스키마 및 테스트 계정이 남지 않았음을 읽기 전용 조회로 재확인했습니다.
- 한영 예시 PDF 각 1페이지 및 품목 100개 PDF 10페이지를 렌더링해 확인했습니다. 100개 품목의 텍스트 누락 없음. 실제 협력업체 정보 대신 테스트 자료를 사용했습니다.
- 도메인: 문서 내용, 명시적 단위, 날짜, 복제 초기화, 원래 목록 연결.
- 위젯: 360×800·글자 배율 1.15, 한국어/영어, 공유 시 상태 보존, 사용자 확인 상태 전환, 계정 변경, 불확실한 저장 재시도.
- PDF: 한글/영어 및 품목 100개 문서 생성과 렌더링 검사.
- 로컬 SQL: `tools/test/run_supplier_request_contract.ps1`. 0035 기준 로컬 DB에서 0036~0053 및 계약 테스트를 단일 트랜잭션으로 실행하고 롤백합니다.
- 운영 적용 시 보류 중인 0047·0048을 일반 db push로 함께 적용하지 않습니다. 출시 대상 0051·0052·0053 중 명시적으로 승인받은 마이그레이션만 적용합니다.
- 실제 카카오톡 전송·파일 수신은 연결된 휴대폰에서 추가 확인이 필요합니다. 개발 테스트는 공유 호출을 대체하며 실제 업체에 메시지를 보내지 않습니다.
- 환경 진단의 기존 경고: 전역 Flutter/Dart PATH가 고정 SDK 경로와 다름, Android 라이선스 상태 미확인, Windows용 Visual Studio 구성요소 부족. 검증 명령은 모두 저장소의 Flutter 3.44.8과 JDK 17을 직접 사용했습니다.
- 출시 전 공개 개인정보처리방침과 Google Play 신고 내용을 실제 배포 범위에 맞춰 업데이트해야 합니다. 관련 저장소 문서는 초안입니다.
