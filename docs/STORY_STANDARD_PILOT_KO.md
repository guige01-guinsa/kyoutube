# 한국어 1분 표준 제작 — 서버·관리자 연결 개발본

제작 엔진, DB 예약·승인, 워커, 관리자 화면을 로컬 코드로 연결했다.
아직 운영에 배포하지 않았다. 현재 웹에서 새 모드를 실행할 수 있다는 의미가 아니며,
실제 불고기 영상·음성 생성, 유료 요청·서버 배포·업로드는 하지 않았다.
기존 세 언어 작품과 비빔밥 재편집 경로는 변경하지 않는다.

## 고정 규격

- `ko-60-v1`: 한국어만, 세로 720×1280, 24fps, 6장면×10초.
- 역할: 인사 / 음식 정보 / 재료 / 조리 / 실제 앱 시연 / 마무리.
- 장면당 낭독은 50자 이하, 실제 음성 0.5~9.5초. 0.25초 여백 후 재생한다.
- 시간을 넘기면 원고를 줄여 다시 승인한다. 발화 절단·자동 배속은 금지한다.
- 짧은 화면 설명과 낭독 원고를 분리한다. 원고에 없는 능력을 앱에 부여하지 않는다.
- 음성 모델·목소리는 기존 설정 유지. 변경은 원고 승인 해시와 캐시 키에 반영된다.
- 3분/5분은 현재 거부한다. 1분 안정화 후 별도 검증·버전으로 추가한다.

## 승인 및 실행

1. 조사·기획: 출처 2개 이상, 음식 관련 장면마다 출처 연결. 출처 목록 존재는 사실 검증이 아니다.
2. 관리자가 원고·출처·이미지 사용권과 비용 견적을 검토한다.
3. `sample`: 첫 장면만 음성 생성하여 비공개 저장. 생성 음성의 해시를 기록한다.
4. 관리자가 실제로 듣고 발음·속도·목소리를 승인한다.
5. `render`: 같은 원고/음성 설정 해시의 승인만 허용한다. 첫 음성은 동일 캐시를 재사용한다.
6. 나머지 음성·실제 앱 캡처·삽화로 조립한다. 과장된 가짜 앱 화면은 사용하지 않는다.
7. 미디어 전체 검사 후 관리자가 전편을 듣고 확인한다. 자동 검사는 자연스러움을 보증하지 않는다.
8. 비공개 업로드는 기존 검토·파일 해시·채널 확인 절차로 별도 승인한다. 자동 공개하지 않는다.

`executeStandardStage`의 IO 어댑터 계약:

- `authorize`: 서버에서 MFA 관리자, 승인 원고 해시, 단계, 금액·월 예산·만료 여부 확인.
- `claimOnce`: 서버 트랜잭션으로 작업 선점. 동일/불확실 작업의 중복 호출 금지.
- `check`: 유료 호출·저장 전마다 lease, 관리자, 중단 스위치·비용 예약 재확인.
- `reviewedSample`: 서버 저장소의 실제 청취 승인과 음성 해시. 브라우저가 보낸 true만 신뢰하지 않음.
- `prepareVisuals`: 승인된 원고에 대응하는 6장과 사용권/해시 검증. 다섯째는 개인정보 없는 실제 앱 캡처.
- `cachedSpeech`: 기존 캐시 엔진과 새 전용 비공개 저장소 사용. `saveSample`도 비공개 보관.
- `assemble` / `inspectVideo`: 아래 오프라인 조립기 및 독립 전체 미디어 검사 연결.
- `complete` / `needsReview`: 결과·시간·비용 예약을 보존. 실패·응답 유실 시 자동 재시도 금지.

`story_studio_standard_worker.mjs`가 기존 작업 큐와 실행기를 연결한다.
`20261028180000_standard_pilot_story_studio.sql`은 기존 작업과 같은 비용 예약 합계를
사용하며 관리자 MFA, 원고 버전, 중복 요청, 시험음 승인과 비공개 업로드를 검증한다.
새 모드는 기본 꺼짐이며 기존 예산을 변경하지 않는다. 새 음성 캐시는 전체 96MB,
프로젝트당 20문단, 개별 2MB 이내이며 기존 192MB 캐시와 별도다.
실제 앱 캡처가 없으면 본편 비용 예약 전에 차단한다.
실제 청구액, 이미지·음성 비용, 호스팅 비용은 별도 기록해야 한다.
월 30만원은 애플리케이션 예산 목표이며 공급자 청구의 절대 상한을 보증하지 않는다.

## 개발 검사 (키·네트워크 불필요)

```
node --test tools/marketing/story_studio_standard.test.mjs
node --test tools/marketing/story_studio_standard_worker.test.mjs
node tools/marketing/story_studio_standard_database.test.mjs
python tools/marketing/story_studio_standard_render_test.py
node tools/marketing/story_studio_standard.mjs --check-plan <private-plan.json>
python tools/marketing/story_studio_standard_render.py <private-asset-directory>
```

조립 디렉터리: `plan.json`, `panel-0.png`~`panel-5.png`,
`ko-0.wav`~`ko-5.wav`. 결과는 `ko.mp4`이며 기존 파일을 덮어쓰지 않는다.
DB 검사는 `MARKETING_PGLITE_PATH`의 로컬 PGlite를 사용하며 운영 DB에 접속하지 않는다.
조립기는 `quality.json`에 전체 디코딩 검사 결과를 기록하고 워커가 해시·길이를 확인한다.
테스트 음성은 합성 사인파다. 실제 목소리·완성 작품으로 안내하지 않는다.
사용자의 불고기 원고·삽화·음성은 공개 저장소에 넣지 않는다.

## 관리자 화면과 운영 전 남은 작업

관리자 새 경로는 `/marketing/standard`이다. 기존 한국어 시리즈를 선택해 음식 기획을
저장하고 원고 작성 → 수정·출처 확인 → 짧은 시험 음성 → 청취 확인 → 60초 제작 →
전편 확인 → 비공개 업로드 순서로 진행한다. 이 경로는 배포 후 이용할 수 있다.
작업은 기존 10분 간격 예약 실행을 공유하므로 큐 대기 시간이 더해질 수 있다.
아직 실제 제작 시간을 측정하지 않았고 완료 시간을 보장하지 않는다.
시험 음성·본편 결과에는 실행 시간(`production_ms`)과 문단별 음성 길이를 저장한다.
이 값에는 큐 대기와 사람의 검토 시간이 포함되지 않으므로 총 소요 시간과 구분한다.

1. `assets/story_demos/standard-guide-v1.json`은 이미 공개 승인된 실제
   `bibimbap-draft.jpg` 공통 안내 캡처를 변경 없이 참조한다. 2026-10-29 육안 검토:
   특정 음식명·검색 결과·개인정보 없이 AI 초안 버튼과 원본 비교 안내만 보인다.
   해당 안내만 설명하고 불고기 검색·초안 생성이 실제로 수행됐다고 주장하지 않는다.
   캡처 해시 검사가 실패하면 제작을 차단한다. 앱 화면이 바뀌면 다시 확인한다.
2. 전체 Flutter 검사 후 변경 커밋과 범위를 검토한다. 공개 저장소의 기반에는 최신
   기존 제작소 화면이 없으므로, 이 공개 기반 전체 앱을 그대로 운영 웹에 배포하지 않는다.
   기존 웹 기반에 새 화면을 이식한 별도 작업본으로 웹 배포 검사를 수행한다.
3. 승인된 코드만 공개 반영하고 큐가 비었을 때 새 migration을 적용한다.
   공개 저장소에 비공개 웹 작업 이력·원고·미디어·키를 밀어 넣지 않는다.
4. 워커 연결, 실제 캡처, 단가와 예산을 확인한 뒤 새 모드를 명시적으로 활성화한다.
   현재의 금액·횟수 한도를 자동으로 늘리지 않는다.
5. 새 유료 제작의 견적·범위를 확인한 후 불고기 시험 음성과 본편을 만들고 품질을 검토한다.
6. 웹은 `WEB_RELEASE_SAFETY_KO.md`의 승인 커밋과 두 배포 도구를 사용한다.
연속 3편을 수동 코드 수정 없이 완료하기 전에는 5분 모드를 켜지 않는다.

공식 음성 참고: https://developers.openai.com/api/docs/guides/text-to-speech
2026-10-28 확인. 기존 모델을 자동 교체하지 않았으며, 모델 종료 일정은 운영 전 재확인한다.
