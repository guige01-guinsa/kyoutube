# Recipe Scout v65 — 2026-09-15

사용자 승인에 따라 운영 DB **0058** 적용과 **1.0.1+65 production 서명 AAB** 생성·검증을 완료했다. 휴대폰 업데이트는 사용자가 직접 진행한다.

## 앱 변경

- 레시피에서 수정한 재료가 오래된 장보기 초안에 가려지던 문제를 수정했다. 조리 원문이 바뀌면 준비 목록을 갱신하고, 변경되지 않은 재료의 선택 및 직접 입력한 구매량은 유지한다.
- **조리 수량·단위는 레시피에서, 구매 수량·단위는 장보기에서 별도로 관리한다.** 조리량을 자동 구매량으로 사용하지 않으며, 구매량을 몰라도 목록을 먼저 만들 수 있다.
- 준비 목록의 편집 버튼에서 구매 재료명·수량·단위를 입력한다. 무게·부피·개수·포장의 34종 구매 단위를 제공한다. 조리 계량 단위는 새 구매 입력에서 제외하며 기존 기록은 읽을 수 있다.
- kg↔g, L↔mL, dozen↔개는 표준 환산한다. 포장 기준이 없으면 환산 기준 또는 최종 구매량을 직접 입력한다. 예: 2팩 × 300g = 600g = 0.6kg. 입력 기준은 해당 편집에 사용되며 전역 규칙으로 저장되지는 않는다.
- 구매 수량을 소수점 6자리까지 보존한다. 125g→0.125kg가 0.13kg으로 반올림되는 문제를 방지했다. 금액 정밀도는 유지한다.
- 조리 완료는 구매 이력이나 재고를 차감하지 않는다. 새 준비 목록은 전체 선택으로 시작하며 사용자가 실제 보유 재료를 제외한다.
- 목록 생성 오류 안내와 한글·영어 튜토리얼을 새 구매 흐름에 맞췄다.

상세 설계·원인·회귀 항목은 [장보기 수정 기록](shopping-create-fix-v65.md)에 있다.

## 운영 DB

- **0058_fix_shopping_create_units.sql만** 트랜잭션으로 적용하고 정확한 원문을 마이그레이션 이력에 등록했다. 사전 모집용 0057은 미적용 상태다.
- `kitchen_shopping_items.quantity`: numeric(12,2) → numeric(18,6).
- `create_kitchen_shopping_list(text,jsonb,uuid)`: 기존 서버의 37종 단위와 미확정 구매량을 수용한다. 이전 앱의 작은술·큰술 등이 전체 목록 생성을 실패시키던 오류를 해결했다.
- `record_shopping_purchase(uuid,jsonb)`: 수량 및 항목별 구매량 검증 정밀도 2→6. 금액·중복 방지·소유자 검증은 유지한다.
- 기존 함수 정의를 보관했다. 실제 함수 본문 해시와 승인된 SQL의 일치, 열 정밀도, 함수 권한·소유자·search_path·RLS 정책 유지, 익명/회원 식별 없는 조회에서 행 미노출을 검증했다.
- 운영 고객 데이터의 삭제나 테스트 계정·구매 기록 생성 없이 적용했다. Edge Function 재배포는 필요하지 않았다.
- 되돌릴 때에도 구매 수량 열을 소수점 2자리로 축소하지 않는다. 새로 저장된 정확한 구매량이 손실될 수 있기 때문이다.

## 업데이트 후 확인

Google Play Console의 테스트 트랙에 AAB를 업로드해 기존 앱을 업데이트한다. 이번 작업에서는 Play 업로드·공개 출시·휴대폰 설치를 수행하지 않았다.

1. 해당 비빔밥의 장보기 준비에서 수정한 조리 원문 밥 120g·달걀 1개가 표시되는지 확인한다.
2. 구매량 미입력 상태로 목록을 만들고, 다른 목록에서는 달걀 구매 10개처럼 별도 수량을 입력한다.
3. 125g→0.125kg, 2팩→600g 등 구매 환산과 선택 제외·재진입을 확인한다.
