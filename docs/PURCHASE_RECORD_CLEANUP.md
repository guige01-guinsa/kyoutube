# 구매 기록 정리와 보관함

## 사용자 흐름

장보기 또는 업소 구매 업무의 우측 상단 메뉴 → **기록 정리** → 대상·기간·검색 조건 → 기록 선택 → 대상 미리보기 → 보관.
같은 메뉴의 **보관함**에서 선택하여 복원한다. 한 번에 현재 페이지의 최대 50건만 처리하며, 초기 선택은 비어 있다. 페이지·조건이 바뀌면 선택을 해제한다.

- 개인 공간: 구매요청, 상품별 구매 기록, 저장 상품, 저장 구매처.
- 업소 공간: 업소의 구매 기록. 조회는 `purchasing.read`, 보관·복원은 `purchasing.write` 권한이 필요하다.
- 작성 중·완료·취소 상태만 보관 가능하다. 승인 대기·승인 완료·전달·수락 등 진행 중 요청은 원래 구매 흐름에서 확인한다.
- 개인 메뉴의 **주방 정리**는 기존 보유 재료/진행 중 장보기/완료 내역/조리 기록 정리와 최근 정리 복구 화면을 연다. 이 기존 기능의 복구 한도는 최근 3건, 각각 30분이다. 새 구매 기록 보관함에는 이 시간 제한이 없다.

## 보존과 오류 처리

보관은 원본을 삭제하거나 상태를 바꾸지 않는다. 금액, 수량, 단위, 재고, 예약, 입고 마감, 원본 변경 이력을 보존한다. 원장 합계와 내보내기는 보관 기록도 포함한다. 저장 상품과 거래처의 보관은 새 구매의 추천·선택 목록에 반영한다. 기존 요청서의 거래처 정보는 유지한다.

서버가 원본 내용과 보관 버전의 토큰을 다시 확인한다. 미리보기 후 기록이 수정되거나 다른 직원이 보관 상태를 변경하면 전체 처리를 거절한다. 한 항목이라도 실패하면 일괄 작업 전체가 취소된다. 처리 응답을 확인할 수 없을 때는 재전송을 막고 새로고침하도록 안내한다. 원본이 수정되면 기존 보관 표시는 무효가 되어 목록에 다시 나타난다.

작업 중 이동과 중복 실행을 막는다. 계정 전환 시 개인 기록 화면과 확인 창을 닫고 이전 계정의 비동기 응답을 무시한다. 정리 창이 열려 있는 동안 권한이 변경되어도 서버가 권한을 다시 검사한다. 진행 중 상태는 클라이언트에도 표시 보호를 두어 오래된 보관 목록으로 숨기지 않는다.

## 서버 구성과 적용 순서

추가 마이그레이션: `supabase/migrations/0074_purchase_record_archives.sql`.

- `shopping_record_archives`: 원본 ID, 범위, 원본 토큰, 보관 상태와 버전.
- `shopping_cleanup_events`: 보관/복원 실행자와 실행 시각. 사용자는 이력을 직접 수정·삭제할 수 없다.
- 인증된 RPC: `shopping_cleanup_list`, `shopping_cleanup_index`, `shopping_cleanup_apply`.
- 원본 조회 보조 함수는 인증 사용자에게도 직접 호출 권한이 없다. 개인정보는 소유자별, 업소 자료는 실제 업소 권한별로 제한한다.
- 익명 접근 및 직접 테이블 변경을 차단한다. 공유 작업은 업소 잠금, 범위 잠금, 정렬된 원본 행 잠금을 이용한다.

2026-09-29 사용자의 배포 승인에 따라 선행 구조를 확인하고 **운영 DB에 0074를 적용한 후 웹 v90 배포와 Android AAB 생성을 완료했다.** 기존 구매·거래처·재고 관련 12개 테이블의 적용 전후 데이터 지문이 동일했다. 다른 미적용 마이그레이션은 일괄 적용하지 않았으며 DB 초기화는 사용하지 않았다.

서버 함수가 아직 없으면 새 정리 화면은 서버 준비 안내를 표시하고 기존 구매 화면은 계속 동작한다. 따라서 앱 소스만 배포해서는 보관 기능이 활성화되지 않는다.

웹과 Android는 같은 화면·보관 조회 코드를 사용한다. 보관 표시를 모르는 구버전 앱에서는 원본 기록이 계속 보일 수 있으므로, 두 환경에서 같은 표시를 원하면 Android 업데이트도 함께 배포해야 한다. 이 경우에도 원본이나 집계 값은 손실되지 않는다.

## 검증

- `tools/dev/verify.ps1`: 고정 Flutter SDK의 환경, 정적 분석, 전체 Flutter 테스트.
- `test/features/shopping/purchase_cleanup_test.dart`: 선택·미리보기·취소·복원, 권한, 계정 전환, 응답 불확실성, 이동 제한, 페이지 선택, 주방 정리 진입, 좁은 화면과 큰 글씨.
- `test/features/shopping/purchase_archive_visibility_test.dart`: 표시에서만 숨김, 원본 금액·수량 유지, 복원 후 재표시, 보관 상품 추천 제외, 진행 중 요청 보호.
- `node tools/test/business_workspaces_contract.cjs --inventory --cleanup`: PGlite 격리 DB에서 기존 재고 계약과 새 권한·보관·복원·동시 변경 토큰·원본 보존·일괄 원자성 검사. 운영 접속 없이 실행한다.

최종 실행 결과:

- 환경 검사 통과(Flutter 3.44.8, JDK 17), 정적 분석 경고·오류 없음.
- 전체 Flutter 테스트 **727건 통과**, 선택 실행하는 기존 전문가 화면 캡처 검사 **4건 제외**.
- 격리된 로컬 DB 검사 **259건 통과**, 운영 데이터 변경 **0건**.
- 한국어 390px·1440px, 영어 320px/글씨 200% 미리보기를 확인했다.
- 기존 일반 쇼핑 검색 버튼을 기대하던 테스트는 사용자가 승인한 숨김 정책 및 검색어 복사 동작에 맞게 갱신했다.
