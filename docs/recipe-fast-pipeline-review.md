# 디테일 스케치와 180초 비공개 제작 흐름

확인한 한국어 원고에서 `제작·비공개 업로드 (180초 목표)`를 선택하면, 비용 확인 창에서 제작과 기술 검사 후의 비공개 업로드까지 함께 승인한다. 원본 레시피 검토와 기존 소녀 캐릭터 음성 사용 확인이 모두 필요하다. 기존 검토용 제작과 수동 업로드는 유지한다.

## 시간 측정과 실행

목표 구간은 서버가 원고 제작 요청을 접수한 `story_jobs.created_at`부터 유튜브의 비공개 상태를 확인하고 업로드 완료를 저장한 시점까지다. GitHub 대기·실행 환경 준비·음성 생성·그림과 영상 인코딩·저장소 전송·유튜브 업로드 확인 시간을 모두 포함한다. 그 전에 진행하는 자료 조사, 원고 편집과 사용자 검토는 포함하지 않는다. 유튜브의 후속 해상도 변환 완료 시간은 별도다.

영상 제작과 비공개 업로드가 같은 실행 환경에서 이어진다. 즉시 실행 요청에는 승인된 작업 ID를 전달하고, DB 임대가 그 작업만 가져오도록 제한한다. 제작 완료 시 서버가 만든 업로드 작업 한 건만 뒤따르며 일반 대기열을 반복 소비하지 않는다. 한 번의 흐름은 최대 두 작업이고 재시도하지 않는다. GitHub의 병렬 실행 제한은 유지하며 대기 요청이 다른 요청 때문에 취소되지 않도록 대기열을 보존한다.

최종 시간과 목표 달성 여부는 DB 서버가 계산한다. 영상 조립만 끝난 상태에서 180초 목표를 달성했다고 표시하지 않는다. 외부 지연으로 초과하면 실제 초과 시간과 결과를 보존한다. 외부 실행 대기나 유튜브 응답 시간 때문에 모든 상황에서 180초 완료를 보장하지 않는다. 운영 승인 후 실제 비공개 시험 업로드로 전체 시간을 측정해야 한다.

## 그림 품질과 안전 기준

`recipe-sketch-v2`는 두 배 해상도로 선을 그린 뒤 축소한다. 김치의 잎맥, 두부의 작은 구멍, 양파의 결, 나무 도마와 냄비의 명암, 곡선 김과 기포를 보완한다. 재료를 써는 장면을 재료를 넣는 장면으로 오인하지 않도록 구분한다. 원문의 수량·단위·조리 순서는 바꾸지 않는다. 유료 이미지 생성은 추가하지 않는다. 기존 소녀 캐릭터 음성 설정과 음성 캐시 키도 보존한다.

자동 업로드에는 서버가 연결한 제작 작업 ID, 같은 파일 해시, 한국어 레시피 프로필, 정확한 원고와 모든 장면의 인코딩 후 그림 검사 결과가 필요하다. 수동 확인을 했다는 허위 기록을 만들지 않는다. 비공개만 허용하고, 영상 길이가 180초 이상이면 자동 업로드를 보류해 사용자에게 계속할지 선택을 받는다. 제작 예산·관리자/MFA·전체 일시정지·중복 방지·불확실한 업로드의 재실행 금지는 유지한다.

## 반영 순서

새 DB 구성은 `fast_recipe_enabled=false`로 시작한다. 유휴 대기열을 확인하고 승인된 DB 구성과 제작 서버를 적용한 뒤 즉시 실행 함수를 적용한다. 기존 운영 웹의 보존된 작업 트리에 UI 변경만 반영하고 승인된 전체 커밋으로 웹 빌드·배포 안전 도구를 사용한다. 각 구성의 일치를 확인한 뒤 관리자 설정의 빠른 제작 기능을 활성화한다. 기존 작품·비밀키·예산 한도는 변경하지 않는다.

운영 검증에서는 원고가 확인된 새 한국어 작품 한 건만 생성해 요청 접수부터 비공개 업로드 확인까지 측정한다. 캐시를 재사용한 검사와 새 음성을 생성한 실제 측정을 구분한다. 제작이 실패하면 추가 유료 호출을 자동으로 반복하지 않는다.
